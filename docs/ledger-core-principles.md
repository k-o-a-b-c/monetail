# 家計簿共通前提と確定済み仕様

[← 家計簿共通設計の入口](ledger-foundation-core.md)

## 確定済みの前提

- SQLiteは1ファイル。認証アカウントは全体、家計簿・人物・業務マスタ・取引は家計簿ごとに管理する。同じアカウントの複数参加を認める。例外として[税区分・税率履歴](ledger-core-schema.md#shared-tax-history)は全家計簿で共有する。
- 全登録利用者が家計簿を作成できる。家計簿の参加招待と、全体管理者によるアカウント登録招待は別の操作。
- 家計簿の権限は閲覧者・編集者・管理者。招待を受けて参加した人は閲覧者。全体のAdminロールを家計簿の権限へ読み替えない。
- アカウントと人物は別管理。家計簿管理者が任意に対応を設定する。人物だけの登録、人物との対応なしでの登録・ログインを認め、名前一致で自動対応しない。
- 編集者は自分の支払方法を編集でき、管理者は他人のものも編集できる。**レシートでは**管理者は全支払方法を利用して全件の登録・編集・削除が可能、編集者は自分の対応人物が所有する支払方法を使用するレシートだけ登録・編集・削除可能（登録者が他人でも可）、閲覧者は閲覧のみ。振替は両側の編集権限を確認する。他の業務操作へこの権限を自動拡張しない。
- 通常操作では最後の有効な家計簿管理者を保護する。紛失・復元等の緊急復旧中はログイン可能な管理者が一時的に0人でもよい。

## 確定した仕様（DEC-046・048）

| 項目 | 仕様 | 状態 |
| --- | --- | --- |
| 家計簿作成 | 入力は名前だけ。作成者を家計簿管理者にし、人物・支払方法・科目は自動作成しない | API・Client・WinUI画面実装済み |
| 任意の人物対応 | 同じ家計簿では1アカウント0〜1人物、1人物0〜1アカウント。家計簿ごとに独立 | API実装・管理画面は未実装 |

家計簿名は前後空白を除いて1〜100文字。同名を認め、名前で統合しない。上限は.NETのstring.Lengthで数える。作成にパスキーの直近再確認は要求しない。人物名は[人物管理](ledger-persons.md)、参加者一覧等の未確定事項は[参加者管理](ledger-participants.md)・[今後の実装](ledger-core-transition.md#後続で確定すること)を参照する。

親のアカウントだけが家計簿管理者として参加し、人物は子供だけを登録する構成も認める。親自身の人物登録・紐づけや、子供のアカウント作成は不要。家計簿を操作するアカウントと記録対象の人物を分け、人物対応の有無を管理権限の条件にしない。
