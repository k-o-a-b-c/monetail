# 09 レガシー版 操作ガイド（コードから再構成）

更新: 2026-10-16 / **実機の画面確認は未実施**。本書の操作名・動作はソース上のイベント処理とフォームから読み取ったもの。画像やキー操作の全環境での動作を保証しない。

## 1. 画面全体の構成

起動フォームは `ViewForm`。起動時に `My.Settings.ConnectionString` でSQLiteに接続し、当月の一覧を初期表示する。年月を切り替え、支払者と支払い方法の絞り込みを使える。

- **一覧タブ**: レシート、振替、残高の月別一覧を表示。選択した行を「変更」またはダブルクリックで編集画面に渡す。
- **分類集計タブ**: 1月〜12月と年間合計を費目分類別に集計。支払者／明細対象者を絞り込み、セルのダブルクリックで内訳へ。
- **残高集計タブ**: 支払方法別の月次残高・評価額・予測額。グラフ、USD換算への切替がある。
- **収支集計タブ**: 支払方法別の月次収入／支出／差額を表示。集計セルから内訳へ。

**注意:** 一覧タブでは月切替、それ以外の年次集計タブでは年切替を行う。タブによって月入力欄の有効状態も変わる。

### 画面上の視覚的な補助

- レシート一覧で、対象者が未設定の明細を一つでも含むレシート行を `MistyRose` 色にする。
- 残高登録では「登録残高」と「自動計算残高」が異なる口座行を `MistyRose` 色にする。
- 残高集計では、自動計算による予測値を `MistyRose` 色にしてツールチップで説明する。
- 支払メモでは、確認日が本日でない口座行を `MistyRose` 色にする。

色はエラー確定の意味ではない。表示条件は該当ソースを参照すること。

## 2. レシートの新規登録

画面: `RegisterForm`。

1. 一覧タブの新規ボタンで入力画面を開く。日時、店名、店舗名（場所）、税込／税抜、支払い方法、レシートメモを設定。
2. **分類グループ**を選び「追加」。税率と分類のメモを設定可能。同じ分類を選択した既存グループを統合するUI処理がある。
3. 作成したグループを選び、商品名、単価（`Fee`）、数量、値引額、値引率、課税対象、対象者（複数）、商品メモを入力して明細を追加。
4. グループ・明細を増やし、合計金額の表示を確認。
5. 「登録」を実行。店名・税区分・支払い方法が設定され、明細が1件以上ある場合に登録ボタンが有効化される。時刻が00:00:00なら確認ダイアログが出る。

**入力支援（コード確認済み）**

- 店名入力の確定後、過去の店舗名に対応する店舗（場所）の候補を取得。
- 税区分・支払い方法・分類は、条件に応じて過去の同店の入力や店舗マスタから初期候補を決める。
- 商品名候補は、同じ店と分類の過去の登録内容から取得。
- 単価欄の入力確定時、`+` と `-` で区切られた整数文字列を順に加減算し、数値に置き換える。例 `100+50-20` → `130`。小数・掛け算などはこの処理の対象外。

**注意:** 税端数方式は現状まだ店舗別には保存できない（今後改修）。**オーケーは専用の3/103計算を実装せず、今までどおり既存の明細「割引額」に手入力**する。現行コードでは割引額を単価から引いてから数量を掛けるため、**まとめ入力で割引合計を使うなら数量1**に注意。実レシートとの照合が必要。[08 運用仕様](08-requested-enhancements.md)。

## 3. レシートの変更・流用・削除

- 「変更」または一覧のダブルクリックで既存レシートを開く。入力したグループ・商品を修正し、「更新」。
- 「流用登録」ボタンでは元レシートの `Seq` を0にして新規として保存する。元レシートはDB上変更しないことをテストで確認する必要がある。
- 「削除」ボタンは確認ダイアログの後、DBから削除する。
- 変更時に日付が変わると追加の確認ダイアログが出る。

**更新・削除の処理**: 対象者割当→明細→グループの順で子を削除し、削除操作では最後にレシート親を削除します。途中で失敗した場合はDBの変更全体を戻します。操作手順や接続時の外部キー設定は変わりません。[05 課題](05-issues.md)。

## 4. 振替登録

画面: `RegisterTransferForm`。

1. 新規振替画面で日時、名称、金額、移動元・移動先の支払い方法、メモを入力。
2. **移動元と移動先が同じ**なら登録を拒否する。
3. 登録・更新・流用登録・削除を実行できる。編集時の日付変更・時刻00:00:00には確認がある。
4. 振替は残高の自動計算では移動元をマイナス、移動先をプラスにする。費目別の購入レシートとは区別される。

## 5. 残高の登録

画面: `RegisterBalanceForm`。

1. 日付と備考を設定。
2. 支払い方法ごとに自動計算残高（参照用）が表示される。
3. 「反映」列の操作で自動計算値を登録残高欄にコピーできる。手入力することもできる。
4. 任意で評価額と口座ごとのメモを入力。
5. **評価額だけで残高が空**の行は登録できない。登録残高が1件もなければ保存不可。
6. 既存と同一日付の残高がある場合、日付入力確定時のチェックで登録ボタンを無効化する。
7. 既存残高は変更／削除可能。残高と予測額の不一致は行の色で表示する。

## 6. 支払い方法の確認メモ

画面: `RegisterPaymentMemoForm`。

- 支払い方法別の予測残高・確認日・メモを一覧で管理。
- 「反映」で確認日を**今日の日付**にする。
- 終了時に登録するかを確認する（Yes / No / Cancel）。
- 「最前面」に固定する選択がある。
- 一括保存のDB処理には明示的なトランザクションがない。途中失敗時の挙動をテストで確認する。

## 7. 集計の読み方

| 表示 | 計算・絞り込みの位置付け |
| --- | --- |
| 分類集計 | `Receipt.GetGroupStatisticsList` で計算。対象者集合の部分一致／完全一致と按分選択がある |
| 収支集計 | `Receipt.Incomes`（負額の収入）と `Receipt.Expenses`（正額の支出）を月単位で集計 |
| 残高集計 | 各月の最新残高と、必要に応じた`GetAutoBalance` の予測残高 |
| USD換算 | その年のUSD/JPYレートを各月に対応させ、JPY÷レートで計算 |

合計・分類・商品個別の金額は**税の切り捨て単位の差**で一致しない可能性がある。計算仕様・確認例は [03](03-calculations.md) と [12](12-calculation-contract.md) を参照。
