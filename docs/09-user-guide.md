# 09 レガシー版 操作ガイド（コードから再構成）

更新: 2026-10-19 / 操作名・動作はソース上のイベント処理とフォームから再構成。Windowsの一時DBを使う自動テストで税設定・流用・NULL読込等の画面操作を確認済み。**実運用DBを使う手動の画面確認は未実施**で、画像やキー操作の全環境での動作を保証しない。

## 1. 画面全体の構成

起動フォームは `ViewForm`。exe横の`HouseholdAccountsBeta.exe.config`の`ConnectionString`で既存SQLiteを指定する。不在・不正DB・移行不足では「DB設定エラー」を表示して終了するため、表示された設定ファイル・DBパス・必要な移行を確認してから再起動する。設定画面は追加していない。[19 設定手順](19-database-startup-settings.md)参照。成功時は当月の一覧を表示し、年月移動と支払者・支払い方法の絞り込みを使える。

- **一覧タブ**: レシート、振替、残高の月別一覧を表示。選択した行を「変更」またはダブルクリックで編集画面に渡す。
- **分類集計タブ**: 1月〜12月と年間合計を費目分類別に集計。支払者／明細対象者を絞り込み、セルのダブルクリックで内訳へ。
- **残高集計タブ**: 支払方法別の月次残高・評価額・予測額。グラフ、USD換算への切替がある。
- **収支集計タブ**: 支払方法別の月次収入／支出／差額を表示。集計セルから内訳へ。

**注意:** 一覧タブでは月切替、それ以外の年次集計タブでは年切替を行う。タブによって月入力欄の有効状態も変わる。

レシート・振替・残高の更新・削除は、他の保存や削除で内容が変わっていると警告して中止する。入力は画面に残り、通常の確認操作は増えない。閉じた後は一覧を読み直すため、一覧から開き直して最新内容を確認する。[更新版移行と保存契約](18-stale-edit-protection.md)を参照。

### 画面上の視覚的な補助

- レシート一覧で、対象者が未設定の明細を一つでも含むレシート行を `MistyRose` 色にする。
- 残高登録では「登録残高」と「自動計算残高」が異なる口座行を `MistyRose` 色にする。
- 残高集計では、自動計算による予測値を `MistyRose` 色にしてツールチップで説明する。
- 支払メモでは、確認日が本日でない口座行を `MistyRose` 色にする。

色はエラー確定の意味ではない。表示条件は該当ソースを参照すること。

## 2. レシートの新規登録

画面: `RegisterForm`。

1. 一覧タブの新規ボタンで入力画面を開く。日時、店名、店舗名（場所）、内税／外税、税端数（切り捨て／四捨五入）、支払い方法、レシートメモを設定。
2. **分類グループ**を選び「追加」。税率と分類のメモを設定可能。同じ分類を選択した既存グループを統合するUI処理がある。
3. 作成したグループを選び、商品名、単価（`Fee`）、数量、値引額、値引率、課税対象、対象者（複数）、商品メモを入力して明細を追加。
4. グループ・明細を増やし、合計金額の表示を確認。
5. 「登録」を実行。店名・税区分・支払い方法が設定され、明細が1件以上ある場合に登録ボタンが有効化される。時刻が00:00:00なら確認ダイアログが出る。

**入力支援（コード確認済み）**

- 店名入力の確定後、過去の店舗名に対応する店舗（場所）の候補を取得。
- 税区分・支払い方法・分類は、条件に応じて過去の同店の入力や店舗マスタから初期候補を決める。
- 新規レシートの税端数は、候補から店を選択するか、店名を入力して別の欄へ移動すると、同じ店で現在のWindows利用者が使った直近レシートの方式を初期選択する。日付・時刻が同じ場合はレシート番号（`seq`）が大きいものを使い、履歴なしは切り捨て。店舗マスタ未登録・店名自由入力でも設定でき、店舗マスタの税端数値は使用しない。
- 税端数を手動で選んだ後は、店名を変更しても選択を維持する。現在選択中の方式を明示的にクリックした場合も手動選択になる。内税／外税と税端数は別々のラジオボタングループなので、片方を選んでももう片方は解除されない。
- 商品名候補は、同じ店と分類の過去の登録内容から取得。
- 単価・値引額の両欄で整数の`+`・`-`・`*`を使える。掛け算を先に計算し、例`100+20*3`は`160`となる。欄を離れると結果へ置き換わり、空欄・不正な式・途中の整数範囲超過は0になる。メッセージボックスは表示しない。小数・除算・括弧は使えない。[24 入力例と範囲](24-integer-money-expressions.md)。

**税端数:** 方式は店舗設定として一括適用するのではなく、レシートごとに保存する。外税は同じ税率の課税明細をグループをまたいで合算してから端数処理する。10%の19円明細2件なら、切り捨て41円／四捨五入42円。内税では方式を変えても合計は変わらない。税端数対応前の既存レシートは切り捨ての計算を維持する。[15 詳細設計](15-shop-tax-rounding-design.md)。

**金額の範囲超過:** 単価・値引額・数量や税設定によって金額が扱える範囲を超えると、明細追加・更新、レシート登録・流用を警告メッセージで中止する。入力と元の明細は保持されるので修正して再操作する。税区分などの切替で範囲外になった場合は合計欄に「範囲超過」と表示し、登録時に警告する。[25 詳細](25-receipt-amount-overflow.md)。

**オーケーの割引:** 専用の3/103計算を実装せず、今までどおり既存の明細「割引額」に手入力する。現行コードでは割引額を単価から引いてから数量を掛けるため、**まとめ入力で割引合計を使うなら数量1**に注意。実レシートとの照合が必要。[08 運用仕様](08-requested-enhancements.md)。

**数量・値引率:** 明細の追加・更新には数量1以上の整数、値引率0〜100%を入力する。値引率は小数可、空欄・空白のみは0%。欄を離れると、不正な数量は1、不正な値引率は0、100%超の数値は100へ補正される。メッセージボックスは表示しない。補正は画面の値だけに行い、明細の追加・更新時に反映する。2.5%などの小数率は保存・再読込後も保持する。単価は収入・返金用の負額も使える。過去の範囲外値はそのまま読込・計算できるが、その明細を更新する際は同じ自動補正を行う。[23 詳細](23-detail-input-validation.md)。

## 3. レシートの変更・流用・削除

- 「変更」または一覧のダブルクリックで既存レシートを開く。入力したグループ・商品を修正し、「更新」。
- 「流用」ボタンでは従来どおり確認後すぐに新規保存して画面を閉じる。追加で「登録」を押す必要はなく、画面上の内税／外税・税端数を引き継ぐ。元レシートの `Seq` を0にして保存する実装で、元レシートのDB上の内容が変わらないことは自動テスト済み。確認で「いいえ」を選ぶと追加保存せず画面が開いたままになる。
- 「削除」ボタンは確認ダイアログの後、DBから削除する。
- 変更時に日付が変わると追加の確認ダイアログが出る。
- 保存済みレシートの税端数は店名を変えても上書きしない。内税／外税・税端数の変更は画面の合計に即時反映するが、必要な登録確認がすべて済むまでは元の `Receipt` の税設定を変更しない。登録確認を断るか、保存せず閉じて同じレシートを開き直すと、元の両設定と合計になる。登録した場合は変更後の設定を保持する。
- 所在地とレシート・分類グループ・商品メモは、DBの値がNULLでも空欄で表示する。読込や取消ではDBのNULLを変更しない。後で明示的に保存した場合は空欄が空文字として保存される。店名や品名などの必須項目の扱いは変更しない。

**更新・削除の処理**: 対象者割当→明細→グループの順で子を削除し、削除操作では最後にレシート親を削除します。途中で失敗した場合は、その操作のトランザクション内のDB変更をすべて戻します。外部キーON/OFF両方で自動テスト済みです。操作手順や接続時の外部キー設定は変わりません。[05 課題](05-issues.md)。

## 4. 振替登録

画面: `RegisterTransferForm`。

1. 新規振替画面で日時、名称、金額、移動元・移動先の支払い方法、メモを入力。
2. **移動元と移動先が同じ**なら登録を拒否する。
3. 登録・更新・流用登録・削除を実行できる。編集時の日付変更・時刻00:00:00には確認がある。
4. 振替は残高の自動計算では移動元をマイナス、移動先をプラスにする。費目別の購入レシートとは区別される。

振替メモのSQL NULLは読込時に空文字として扱い、保存値は読込だけで更新しない（LEG-028）。

**振替の入力チェック:** 名称空欄・移動元／先の未選択・不正な金額では、登録と流用の両方が押せなくなる。入力を修正すると押せる状態に戻り、追加の通知や自動補正は行わない。金額は従来どおり0円・負額を含む整数で、計算式は使えない。同一口座の警告と、確認後すぐに保存して閉じる流用は維持する。[28 詳細](28-transfer-input-validation.md)。

## 5. 残高の登録

登録する残高は、指定した日の終了時点の金額です。予測残高はその翌日から対象日末までの取引を反映します。保存日時に時刻が残っていても日付として扱い、小数秒を含む対象日の最後の取引まで集計します。[21 推算期間](21-end-of-day-balance.md)参照。

画面: `RegisterBalanceForm`。

1. 日付と備考を設定。
2. 支払い方法ごとに自動計算残高（参照用）が表示される。
3. 「反映」列の操作で自動計算値を登録残高欄にコピーできる。手入力することもできる。
4. 任意で評価額と口座ごとのメモを入力。
5. **評価額だけで残高が空**の行は登録できない。登録残高が1件もなければ保存不可。
6. 既存と同一日付の残高がある場合、日付入力確定時のチェックで登録ボタンを無効化する。
7. 既存残高は変更／削除可能。残高と予測額の不一致は行の色で表示する。

備考と口座ごとのメモもSQL NULLだけを空文字として読み込み、登録残高・評価額や保存済みNULLを変更しない（LEG-028）。

残高削除は支払方法別の子→残高親の順で行い、親削除で失敗した場合も先行する子削除を既存トランザクションで戻す。操作手順は従来どおりで、FK ON/OFFのDB処理を自動検証済み（LEG-027）。手動の画面確認や実DBの復旧確認とは区別する。

**残高登録の入力エラー:** 評価額だけの入力や残高が1件もない場合は登録前にエラー表示する。不正な整数が残っている場合もエラーで中止する。編集値は残るので修正して再登録でき、保存せず閉じた場合は元の日付・タグ・明細を保持する。同じ残高を開き直しても途中の編集状態にはならない。[29 詳細](29-balance-input-state.md)。

## 6. 支払い方法の確認メモ

画面: `RegisterPaymentMemoForm`。

- 支払い方法別の予測残高・確認日・メモを一覧で管理。
- 「反映」で確認日を**今日の日付**にする。
- 終了時に登録するかを確認する（Yes / No / Cancel）。
- 「最前面」に固定する選択がある。
- 保存は全行をまとめて確定する。途中で失敗した場合は、その一括保存の追加・更新をすべて元に戻す。入力方法と終了時の確認操作は従来どおり。

## 7. 集計の読み方

| 表示 | 計算・絞り込みの位置付け |
| --- | --- |
| 分類集計 | `Receipt.GetGroupStatisticsList` で計算。対象者集合の部分一致／完全一致と按分選択がある |
| 収支集計 | `Receipt.Incomes`（負額の収入）と `Receipt.Expenses`（正額の支出）を月単位で集計 |
| 残高集計 | 各月の最新残高と、必要に応じた`GetAutoBalance` の予測残高 |
| USD換算 | その年のUSD/JPYレートを各月に対応させ、JPY÷レートで計算 |

合計・分類・商品個別の金額は**税端数を処理する単位の差**で一致しない可能性がある。レシート全体の税率別合算による会計合計が正本で、分類・人別は参考額。計算仕様・確認例は [03](03-calculations.md) と [12](12-calculation-contract.md) を参照。

**集計表の範囲超過:** 分類集計・収支集計で月額や年計が扱える範囲を超えると、表全体を「集計不可／範囲超過」に置き換える。年・支払者・対象者や収入／支出の条件を変え、範囲内になれば通常表示へ戻る。エラー行から詳細は開かない。保存済みデータは変更されない。[26 詳細](26-statistics-amount-overflow.md)。

**残高の範囲超過:** 登録・支払メモの推算欄が範囲外なら「範囲超過」と表示する。「反映」は入力済み残高を保持するので、日付を変えるか有効な残高を手入力する。残高集計では表を「集計不可／範囲超過」にし、グラフを消す。年・支払者・評価額／USDの条件を変えて範囲内になれば通常表示へ戻る。0円・データなしとは区別する。[27 詳細](27-balance-amount-overflow.md)。
