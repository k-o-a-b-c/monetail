## 共通HTTP境界・認可

参加者追加は[家計簿招待](ledger-invitations.md)の受領で行い、任意のアカウントID指定による直接追加APIは作らない。人物対応の操作は[参加者API](ledger-person-api-contract.md)を正本とする。

- 対象家計簿を指定して操作するAPIは、対象家計簿の現在の参加・roleを要求ごとにDBで確認する。Cookieの全体Adminやクライアントのroleを信用しない。
- 未認証・セッション失効・利用停止は401。指定した家計簿の未参加と不存在は同じ404、参加済みで役割不足は403、古いrevision・対応の重複・要求IDの競合は409。人物・参加者・招待の操作にも適用する。
- 全体のアカウント検索・一覧・存在照会を家計簿管理者へ追加しない。人物名・表示名からの照合も行わない。
- 書込時はDBの最新の参加・権限・対象所属をトランザクション内で再確認する。最後の有効な管理者の同時降格・除外は、同じ書込ロック内で確認し、片方しか成立させない。
- 全体のアカウント停止と家計簿管理者保護の関係、緊急時の家計簿管理者復旧は別途具体化する。既存の全失効コマンドへ、今回新しい家計簿参照を加えない。
- 業務APIは共通HTTP境界に従う。家計簿に依存しない共通税区分・税率履歴の認証・認可は[共通税区分・税率履歴API](specs/api/features/tax-rates.md)に従う。ログイン、固定HTTPS・ホスト検証・no-store、POSTのOrigin・CSRF・64KiB上限、認証／保存障害時503を適用する。GETは追加の本人再確認を要求しない。認証APIの既存のIP単位の回数制限は維持する。

### アカウント単位の回数制限（DEC-049）

認証済みの業務APIは原則として同じアカウントで、作成・更新・削除・順序保存等の書込を合わせて固定1分20回、参照・家計簿を開く操作を合わせて固定1分120回の別枠とする方針を確認済み（DEC-069。DEC-068の全操作を共有120回とする方針から変更）。機能ごとに書込枠や参照枠を追加せず、新しい別枠は必要な理由と対象を示して確認してから追加する。

| 対象 | 現行実装 |
| --- | --- |
| 家計簿・人物・科目・支払方法・参加者・招待の作成・更新・削除・順序保存・参加確定 | 同一アカウントで共有20回／分 |
| 家計簿の参照・開く、人物・科目・支払方法・参加者・招待の一覧／編集情報、共通税率履歴の全件取得、招待preview | 同一アカウントで共有120回／分 |

認証後の検証済みアカウントIDで数え、端末・セッション・IPや対象家計簿が違っても同じ枠の要求は合算する。別アカウントの枠と、書込・参照の2枠は独立。作成して開く操作や更新後一覧の取得等のAPI内部処理は別のHTTP要求として二重計上せず、書込要求は書込枠だけを使う。既存の指定家計簿・最後の家計簿を開く要求は、最終選択の更新を含めても従来どおり参照枠とする。HTTPメソッドだけで書込・参照を判定しない。制限判定を通る要求は入力不備等も数え、超過は待機させず429とする。Cookie検証で未認証・失効と判断した要求はアカウント枠を使わず401等の認証結果を返す。認証APIは[セッション保護](auth-session-security.md)の既存のIP単位の制限を維持する。DBにカウンターや列を追加しない。
