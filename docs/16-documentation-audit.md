## 実装と検証の基準

| 対象 | 照合した現行動作 |
| --- | --- |
| 税端数（[PR #1](https://github.com/k-o-a-b-c/monetail-legacy/pull/1)） | 税率ごとに合算後、レシートに保存したfloor/half_upで計算。floorは既存Double式を維持、half_upの税額はDecimalとAwayFromZero（負の中間値もゼロから遠い側） |
| 初期選択と画面 | 同じ店名・現在の利用者の直近レシート（日付降順・同日時はseq降順）を使う。店舗マスタの値は使わず、未登録店も利用可能。端数ラジオは内税／外税と独立 |
| 編集と流用 | 内税／外税・端数方式は画面だけで保持し、GetTotalへ選択値を渡す。確認後にReceiptへ転記。レシート全体のディープコピーは未導入で、明細等は従来の共有オブジェクト編集。流用は従来どおり確認後に新規保存して閉じる |
| 外部キー（[PR #2](https://github.com/k-o-a-b-c/monetail-legacy/pull/2)） | 更新は対象者割当→明細→グループを削除して子を再INSERT。削除操作は同じ子削除後に親を削除。処理失敗時は、その操作のトランザクション内のDB変更をすべて巻き戻す。接続のFK設定・DDLは変更しない |
| NULL読込（[PR #3](https://github.com/k-o-a-b-c/monetail-legacy/pull/3)） | 所在地とレシート・グループ・明細のタグの4列、6読込箇所だけNULLをモデル上の空文字へ変換。一覧・残高・子再読込・画面取消で保存済みNULLと金額を維持。明示保存時は既存処理で空文字を保存 |
| 維持・保留 | オーケーは既存discount_feeへの手入力を維持。マスタ画面の作成は見送り。ポイントは一部実装で採用範囲未決定。小数割引率の読込と支払メモ一括保存は未改修 |
| 構造 | 元DDLは16表・90列・17FK（複合FKは2件）。移行SQLは店舗とレシートに計2列を追加し、一時DBは92列。元DDLファイルは元のまま保持 |
| 自動検証 | 計算20件（JSON11＋VB9）・移行5件・Windows実SQLite／画面15件（従来8＋FK4＋NULL3）の計40件と、既存ソリューションのNuGet復元・Windowsビルドが[基準mainのCI](https://github.com/k-o-a-b-c/monetail-legacy/actions/runs/39120545702)で成功 |
