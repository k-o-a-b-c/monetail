# 24 単価・値引額の整数式入力

更新: 2026-10-20。利用者の指定に基づき、単価・値引額の両欄で整数の加算・減算・乗算を使えるようにする。

| 入力例 | 計算結果 |
| --- | ---: |
| `100+50-20` | 130 |
| `100+20*3` | 160 |
| `2*3+4*5` | 26 |
| `-10*2+5` | −15 |
| `2*-3` | −6 |
| `1--2` | 3 |

## 入力規則

- 数字は半角の`0`〜`9`、演算子は半角の`+`・`-`・`*`。乗算を先に計算し、加減算は左から処理する。
- 各整数の先頭には単項の`+`または`-`を1つ付けられる。負の単価・負の値引額も維持する。
- 数字と演算子の間の空白・タブ・改行は許容する。数の途中に空白を入れた`1 2`は不正とする。
- 小数、桁区切り、除算、括弧などは対象外。空欄・不正な式は0へ補正する。旧処理が途中まで計算していた`100+`や符号だけの入力も、今回は不正な式として0にする。
- 整数リテラル、途中の積・合計、結果はすべてInt32（−2,147,483,648〜2,147,483,647）の範囲。途中で範囲を超えた式は全体を0にする。例えば`2147483647+1-1`も0。最小値の負数は正しく扱う。

## 画面と保存

`IntegerExpression.EvaluateOrZero`を単価・値引額で共用する。両欄の`Validated`イベントで整数へ置き換え、メッセージボックスは表示しない。出力は桁区切りなし・半角の整数とする。

欄を離れるだけでは明細・会計合計・DBを変更しない。明細の追加／更新時にも同じ処理を呼ぶため、欄のイベントを経由しない操作でも同じ結果を反映する。DBには式でなく評価結果の整数を保存する。取消時は元レシートとDBを維持する。

数量・値引率の自動補正は[23 仕様](23-detail-input-validation.md)を継続する。レシートの計算式、税率ごとの合算、端数方式、単価値引を数量倍する処理、オーケーの手入力値引、保存SQL・DB構造は変更しない。

## 検証と残る範囲

共通の固定入力表で優先順位・符号・空白・型の境界・不正式・途中の桁あふれを比較する。式の評価はen-US／de-DEでも同じ結果となる。Windowsでは両欄を離れる実操作、明細追加／更新、取消、両端数方式の保存・再読込とINTEGER保存を、製品SQLiteのFK ON/OFFで確認する。件数・最新結果は[tests/README](../tests/README.md)を参照する。

この制限は入力式の評価に適用する。評価後の単価・値引額・数量から明細金額やレシート合計を求める際のオーバーフローは、別の改修で扱う。実データでの確認・手動E2Eは未実施。
