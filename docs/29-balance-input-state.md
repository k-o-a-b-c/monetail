# 29 残高登録の入力エラー時の元データ保持

更新: 2026-10-20。利用者承認に基づき、残高登録の入力エラーで元のBalanceが途中状態になる問題を修正する。

## 問題と変更

編集画面は親の一覧が持つBalanceをそのまま受け取る。従来は登録時に日付・タグを転記し、元のGroupsを空にしてから行を処理していた。そのため「評価額だけ入力」「残高が1件もない」などで中止すると、DBは未変更でも一覧内のオブジェクトは途中状態になり、通常のキャンセル後に同じ残高を開くとその状態が残る。

現在は画面から一時的な`pendingGroups`を作り、全行が有効であることを確認する。残高未入力で評価額だけがある行は従来のエラーにし、残高・評価額がない行は従来どおり省略する。残高が1件もなければ従来のエラーで中止する。

残高・評価額は`Integer.TryParse`で確認する。欄のValidatedを経由せず不正な文字列やInt32の範囲外が残っていても、変換例外で止めず、該当する項目を整数で入力するようエラー表示する。入力を0や空欄に補正しない。既存のCellValidatedによる入力の確定方法は変更しない。

入力検証後、既存の更新確認・日付変更確認を行う。それらを通った場合だけ日付・タグ・候補リストをBalanceへ転記し、既存の保存処理を呼ぶ。入力エラーでは登録確認を先に出さず、エラーだけを表示する。正常な新規・更新の確認回数は増やさない。同日残高の重複確認は従来どおり最初に行う。

## 保持と互換性

入力エラーや確認取消では、入力済みの編集値を残し、元のBalanceの参照・日付・タグ・Seq／更新版・Groupsのリストと各明細の参照・値を保持する。通常のキャンセルでは親が再読込しなくても、同じBalanceを再び開けば元の値が表示される。新規画面の未保存オブジェクトも、入力エラーで変更しない。

有効な入力へ直せば同じ画面から保存できる。0円・負額・Int32の範囲、任意評価額・タグ、空行の省略と正常な保存・閉じる動作を維持する。モデル・DataAccess・SQL・DB構造・推算・採番・更新版照合は変更せず、移行は不要。

この変更は入力検証・確認中のモデル変更を防ぐもの。検証と確認の完了後に行う保存処理・競合時の再読込契約は既存のままとする。[18 保存契約](18-stale-edit-protection.md)、[27 推算表示](27-balance-amount-overflow.md)参照。

## 検証

Windows上で製品の登録画面・実SQLiteのFK ON/OFFを使い、次を確認する。

- 新規・編集で全行空、評価額のみ、途中行の不正整数／範囲外を拒否し、入力・元モデル各値・参照・Seq／更新版・全保存値・型・スキーマを保持する。
- 編集を保存せず閉じ、ヘッダーや明細を再読込した新しいオブジェクトではなく、同じBalanceを渡して再表示しても元の日付・タグ・金額・任意評価額が残る。
- 表示とエラー処理で書込イベント0回、接続のFK／user_versionの保持を確認する。
- 修正後の新規・更新で0円・負額・型の境界・任意評価額・タグを保存・再読込し、他の保存値と更新版を保持する。
- 有効な候補を作った後の更新確認・日付変更確認を取り消しても、入力・元モデルとリスト／明細参照が変わらない。
