# 28 振替の登録・流用の入力チェック

更新: 2026-10-20。利用者承認に基づき、登録では止めていた不正入力が「流用」や処理の直接呼出を通る問題を修正する。

## 共通の入力条件

`RegisterTransferForm.TryGetTransferInput`で、名称が空文字ではないこと、移動元・移動先が支払方法として選択されていること、金額をInt32へ変換できることを確認する。同じ判定を登録・流用のボタン状態と、`RegisterTransfer`の先頭で使う。

空欄・空白だけの金額、不正文字、小数、計算式、Int32の範囲外は両ボタンを無効にする。処理を直接呼んでも、確認ダイアログ・Seq変更・モデルへの転記・DB保存より前に中止する。入力、元Transferの各値と支払方法の参照、Seq・更新版・全保存値を保持し、追加のメッセージボックスや0補正は行わない。修正するとボタンが再度有効になる。

金額は従来どおり`Integer.TryParse`の範囲・書式を使い、0円・負額・最小値−2,147,483,648・最大値2,147,483,647を許容する。前後の空白や符号も従来の整数入力として扱う。名称の空白だけを禁止する新しい条件は追加しない。単価・値引額の[24 整数式](24-integer-money-expressions.md)は振替金額には適用しない。

## 確認と保存の互換性

移動元・移動先が同じ場合は、従来どおり両ボタンを押せる状態で「移動元と移動先が同一です。」の警告を表示し、確認や保存へ進まない。時刻未設定、更新、日付変更、流用の確認は維持する。いずれの確認を取り消しても元のTransferやDBは変更しない。

正常な新規登録には追加の確認を増やさない。流用は従来どおり確認後にSeqを新規用へ切り替えて保存し、画面を閉じる。追加の登録操作は不要。元の保存済み振替は変更せず、確認した入力を新しい振替へ保存する。金額は事前の検証で取得した整数を使い、確認後の`Integer.Parse`をなくす。

モデル・DataAccess・保存SQL・DB構造・採番・更新版照合は変更せず、移行は不要。DB競合など、入力検証後の保存エラーに対する既存契約は維持する。

## 検証

Windows上で製品の振替登録画面と実SQLiteを使い、FK ON/OFFで次を確認する。

- 新規・編集で名称空欄、移動元／先の未選択、不正な金額の両ボタン無効化。ボタンを強制的に有効化して処理を直接呼んだ場合も、ダイアログ0回・モデルとDBの変更0回で拒否する。
- 入力・モデル各値・参照・Seq／更新版・全テーブルの保存値／型・スキーマの保持と、修正後の正常保存。
- 新規・更新・即時流用で0円・負額・型の両端・符号／空白付き整数を保存・再読込し、INTEGER保存と流用元を含む無関係な全保存値の保持を確認する。
- 流用／更新／時刻未設定／日付変更の確認取消と、同一口座の両ボタンの警告が入力と元データを保持すること。

既存のダイアログ応答ヘルパーに、公開処理を直接呼ぶ入口と、想定外の「エラー」を閉じて失敗として報告する処理を追加する。通常のボタン操作の経路は維持する。件数とCI結果は[tests/README](../tests/README.md)に集約する。利用者環境の手動確認は含まない。
