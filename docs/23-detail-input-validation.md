# 23 明細の数量・値引率の入力検証

> 本書はこの改修時点の履歴。税率・課税フラグ・Doubleの旧記述は[42 明細税率への切替](42-detail-tax-application.md)と[12 現行計算](12-calculation-contract.md)に置き換わった。税端数のレシート保存、入力補正、即時流用の操作は維持する。新版の検証状態は[tests/README](../tests/README.md)。

利用者の指定に基づき、入力欄を離れたときと明細の追加・更新時に次の範囲へ自動補正する。通知ダイアログは表示しない。

| 項目 | 入力条件 |
| --- | --- |
| 数量 | 1〜2,147,483,647の整数。空欄・数値以外・小数・0以下・整数範囲外は1へ補正 |
| 値引率 | 0〜100%の有限な数値。小数可。空欄・空白のみは0%。負数・数値以外・NaN／無限大は0、100%超の有限値は100へ補正 |
| 単価・値引額 | 後続改修で両欄に整数の加減算・乗算を追加。不正式・途中のInt32範囲超過は0。負数を維持（[24 仕様](24-integer-money-expressions.md)） |

数量・値引率の数値変換は従来と同じ現在のカルチャーを用いる。数量の上限は型の上限であり、どの単価との組合せでも金額が収まることを保証するものではない。

## 画面の動作

数量・値引率の`Validated`イベントで表示を補正する。欄を離れるだけではレシートの明細・合計やDBを変更しない。正常な数値も現在のカルチャーで表示し直し、値引率の空欄・空白のみは0になる。

`RegisterForm.AddDetailButton_Click`でも同じ補正処理を呼んでから明細へ反映する。入力欄のイベントを経由しない場合も補正され、追加の確認や修正操作は必要ない。単価・値引額も後続の[24 整数式](24-integer-money-expressions.md)で同じタイミングに評価する。

## 既存データとの互換性

制限は画面から明細を追加・更新するときに適用する。保存済みの数量0以下・100%超の値引率を自動修正しない。既存レシートの読込・計算・表示・取消を維持する。その明細の入力欄を離れれば表示が補正され、明細を「更新」すると補正値を反映する。欄の補正だけで取消した場合は元の明細を保持する。

レシート全体の保存時の再検査やDataAccess・DBの範囲制約は追加しない。したがって既存の明細を変更せず、レシートのヘッダーを保存・流用する経路は従来のまま。モデル・計算式・保存SQL・DB移行・税端数処理・オーケーの割引機能も変更しない。

## 回帰テスト

製品の登録画面とSQLiteのFK ON/OFFで次を確認する。実行構成・件数・CI結果は[tests/README](../tests/README.md)を参照する。

- 実際に欄を離れる操作で自動補正し、他の入力・明細の選択・値と参照・会計合計・保存済み全行を保持する。欄のイベントを経由しない追加／更新でも補正値を反映する。ダイアログで操作を止めない。
- 数量1・複数・型の上限、空欄／空白・0%・100%・小数率と負の単価を追加／更新でき、両端数方式で保存・再読込できる。数量上限は単価・値引額0で検証する。
- 保存済みの数量0／−2・値引率125%／150%を読み込み、現行計算値と画面表示を維持して取消できる。

単価・値引額の式入力・不正式・途中の桁あふれは[24 仕様](24-integer-money-expressions.md)で対応した。式を評価した後の金額は[25 範囲確認](25-receipt-amount-overflow.md)で明細反映・登録前に確認する。任意の外部書込みの制約、複数レシートの集計全体、実データの検査は別の課題とする。
