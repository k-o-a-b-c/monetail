# 23 明細の数量・値引率の入力検証

利用者の承認に基づき、明細の追加・更新時に次の条件を確認する。

| 項目 | 入力条件 |
| --- | --- |
| 数量 | 1〜2,147,483,647の整数。空欄・数値以外・小数・0以下・整数範囲外を拒否 |
| 値引率 | 0〜100%の有限な数値。小数可。空欄・空白のみは0%。負数・100%超・数値以外・NaN／無限大を拒否 |
| 単価・値引額 | 今回は検証条件を変更しない。負の単価による収入・返金、オーケーの手入力値引を維持 |

数値変換は従来と同じ現在のカルチャーを用いる。数量の上限は型の上限であり、どの単価との組合せでも金額が収まることを保証するものではない。

## 画面の動作

`RegisterForm.AddDetailButton_Click`は、数量・値引率をローカル変数へ読み、両方の検証後に明細へ反映する。不正な場合は「入力エラー」を表示し、対象欄へフォーカスを戻して文字列を選択する。

エラー時は明細を追加・更新せず、入力内容・明細の選択・追加／更新ボタンの状態を維持する。数量と値引率がともに不正なら数量から案内する。正しい入力の追加・更新・登録の操作回数は変わらない。

## 既存データとの互換性

制限は画面から明細を追加・更新するときに適用する。保存済みの数量0以下・100%超の値引率を自動修正しない。既存レシートの読込・計算・表示・取消を維持する。その明細を「更新」する場合は新しい入力条件に合わせる必要がある。

レシート全体の保存時の再検査やDataAccess・DBの範囲制約は追加しない。したがって既存の明細を変更せず、レシートのヘッダーを保存・流用する経路は従来のまま。モデル・計算式・保存SQL・DB移行・税端数処理・オーケーの割引機能も変更しない。

## 回帰テスト

製品の登録画面とSQLiteのFK ON/OFFで次を確認する。実行構成・件数・CI結果は[tests/README](../tests/README.md)を参照する。

- 不正な数量・値引率を追加／更新で拒否し、入力・選択・明細の値と参照・会計合計・保存済み全行を保持する。エラーを閉じると対象欄へ戻る。
- 数量1・複数・型の上限、空欄／空白・0%・100%・小数率と負の単価を追加／更新でき、両端数方式で保存・再読込できる。数量上限は単価・値引額0で検証する。
- 保存済みの数量0／−2・値引率125%／150%を読み込み、現行計算値と画面表示を維持して取消できる。

単価・値引額の不正文字列、計算結果の整数オーバーフロー、任意の外部書込みの制約、実データの検査は別の課題とする。
