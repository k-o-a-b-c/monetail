# 家計簿API・業務契約

**家計簿APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：参加中の家計簿の一覧・個別参照、作成、指定／最後の家計簿を開く、家計簿名の変更、アカウント別並び順の保存、家計簿の削除。
- Clientの操作者情報の再取得：[画面共通処理](../../../ledger-person-conflicts.md)。
- 関連契約：[家計簿共通前提](../../../ledger-core-principles.md)、[家計簿DB](../../../ledger-core-schema.md)、[参加者API](members.md)、[招待API](invitations.md)、[人物API](persons.md)、[科目API](categories.md)、[支払方法API](payment-methods.md)。
- 共通契約：[認証API](../../../auth-api-contract.md)、[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)、[共通再送](../../../ledger-operation-retries.md)。

## 2. エンドポイントと権限

| メソッド・パス | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /ledgers` | 自分が参加する家計簿一覧を取得 | 有効な認証アカウント | 200 |
| `GET /ledgers/{ledgerId}` | 対象家計簿と本人の参加情報を取得 | 対象家計簿の参加者 | 200 |
| `POST /ledgers` | 家計簿を作成 | 有効な登録アカウント | 初回201、同一の成功要求の再送200 |
| `POST /ledgers/{ledgerId}/open` | 指定家計簿を開き、最終選択を保存 | 対象家計簿の参加者 | 200 |
| `POST /ledgers/open-last` | 最後の家計簿を開く | 有効な認証アカウント | 200 |
| `PATCH /ledgers/{ledgerId}` | 家計簿名を変更 | 対象家計簿のAdmin | 200 |
| `PUT /ledgers/order` | 自分の家計簿一覧の順序を保存 | 有効な認証アカウント | 200 |
| `DELETE /ledgers/{ledgerId}` | 家計簿を削除 | 対象家計簿のAdmin | 200 |

- APIは各要求で認証を検証し、対象家計簿を指定する操作では現在の参加と操作権限も検証する。全体管理者の権限は家計簿Adminの権限を代替しない。別アカウントのIDを入力から受け取らない。確定前の再検証と最終選択の扱いは第7節に従う。

## 3. 家計簿の値・業務制約

| 項目 | 契約 |
| --- | --- |
| `ledgerId` | APIが生成するUUID v4。家計簿名・順序から独立 |
| `name` | .NET `string.Trim()` で前後の空白を除去し、1～100 UTF-16コード単位（.NET `string.Length`）として保存する。上限超過を切り詰めない。同名を認め、名前で統合しない |
| `role` | ログイン中のアカウントの対象家計簿内の役割。[参加者API第3節](members.md#3-参加者の値業務制約)の役割のいずれか |
| `myPersonId` | ログイン中の参加者に対応する同一家計簿の人物ID。未設定なら`null` |
| 作成 | 作成者がAdminとして参加する。人物・科目・支払方法・招待は自動作成しない。直近のパスキー本人確認は要求しない |
| 名前変更 | 業務記録の有無にかかわらず変更できる |
| 並び順 | アカウント単位の任意の順序。端末間で共有し、新規作成・招待参加は末尾に追加する。家計簿の削除・参加解除では対象家計簿を一覧から除き、残った家計簿の相対順を維持する |
| 削除 | レシート・残高（評価額のみの登録を含む）・振替・支払メモが1件でも残る家計簿は削除不可。業務記録が0件の場合は物理削除する。直近のパスキー本人確認は要求しない |

人物とアカウントの対応は[参加者API](members.md)に従う。人物対応の有無を管理権限の条件にしない。

## 4. リクエスト

パスの `ledgerId` はUUID（N・D・B・P・X形式。URL上で適切にエンコードする）。UUID値として照合し、UUIDとして解釈できないパスはルーティングの404とする。全桁ゼロのUUIDもパスではUUIDとして扱い、第6節の認可・存在確認に従う。

GETおよび2つの開くPOSTには要求本文を必要としない。開くPOSTの対象はパスまたは認証中のアカウントの最終選択から決まる。本文が送られても対象の決定には使用せず、共通HTTP境界は適用する。

作成POST・PATCH・並び順PUT・DELETEはJSONオブジェクトを送る。Content-Typeは `application/json` または `+json` サフィックスを持つJSONメディアタイプを受け付ける。

本文のUUID文字列は.NET `Guid.TryParse` で解釈できる形式（N・D・B・P・X）を受け付け、同じUUID値として照合する。全桁ゼロのUUIDは本文では不正とする。UUIDのバージョンによる入力制限は設けない。

| JSON項目 | 型 | 作成POST | PATCH | DELETE | 並び順PUT |
| --- | --- | --- | --- | --- | --- |
| `requestId` | UUID文字列 | 必須 | — | — | — |
| `name` | 文字列 | 必須 | 任意 | — | — |
| `revision` | UUID文字列 | — | 必須 | 必須 | 必須 |
| `ledgerIds` | UUID文字列の配列 | — | — | — | 必須 |

- 「任意」はキーの省略を許す。「—」は送信不可。キー名は大文字・小文字を区別する。`null`は認めない。入力不備のエラーと検証の優先順位は第6節に従う。
- PATCHの省略項目は変更しない。
- 並び順PUTの `ledgerIds` は現在参加している全家計簿のIDを保存する順に各1回指定する。未参加・未知ID、重複・欠落を認めない。0件の場合は空配列。

## 5. 成功応答・識別と並び順

成功応答は操作に応じて次のJSONオブジェクトを返す。各JSONオブジェクトは本節の表に列挙した項目のみで構成し、すべて必須キーとする。`null`は表で明記した項目だけに許す。読み取りの整合性・再送時の応答は第7節に従う。

| 操作 | 応答形式 |
| --- | --- |
| 一覧GET・作成POST・PATCH・並び順PUT・DELETE | 家計簿一覧JSONオブジェクト |
| 個別GET・指定して開くPOST | 家計簿オブジェクト |
| 最後の家計簿を開くPOST | 最終選択JSONオブジェクト |

家計簿一覧の保存順は[DBの表示順管理](../../../ledger-core-schema.md#master-order-storage)に従う。

### 家計簿一覧JSONオブジェクト

| トップレベル項目 | 型 | 内容 |
| --- | --- | --- |
| `ledgers` | オブジェクト配列 | 現在参加中の全家計簿を本人の保存順で返す。各要素は家計簿オブジェクト。0件なら空配列 |
| `orderRevision` | UUID文字列 | 本人の家計簿一覧の構成・順序の更新版。作成・参加履歴がないアカウントにも有効な初期順序版を持たせ、0件でも返す |

### 家計簿オブジェクト

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `ledgerId` | UUID文字列 | 家計簿ID |
| `name` | 文字列 | 保存済みの家計簿名 |
| `role` | 文字列 | 本人の現在の役割 |
| `revision` | UUID文字列 | 家計簿自身の更新版 |
| `myPersonId` | UUID文字列または`null` | 本人の対応人物ID。未設定・新規作成直後は`null` |

### 最終選択JSONオブジェクト

| トップレベル項目 | 型 | 内容 |
| --- | --- | --- |
| `ledger` | 家計簿オブジェクトまたは`null` | 最後に開いた家計簿。履歴なし・現在未参加なら`null` |

UUIDの応答形式は小文字のN形式（ハイフンなし32桁）。更新版はAPIが生成するUUID v4とし、一致のみで照合する。

## 6. 競合・失敗応答

### エラー本文

家計簿APIの業務エラーは以下の4項目のみで構成するJSONオブジェクトを返す。ただし、保存障害の503 `store_unavailable` は `code`・`message` の2項目とする。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けのエラーの説明。具体的な文言は実装側で管理し、クライアントの処理分岐には使用しない |
| `field` | 文字列または`null` | 対象のJSON項目名。個別項目を特定しない場合は`null` |
| `latest` | オブジェクトまたは`null` | 更新版競合時の最新情報。形式は後述。それ以外は`null` |

受付前の認証・認証ストア障害・Origin／CSRF・本文上限・回数制限等の拒否、およびルーティング段階のエラーは第1節の共通HTTP契約・HTTP境界に従う。業務エラー本文を一律には要求しない。GETと2つの開くPOSTは共有参照枠、作成POST・PATCH・DELETE・並び順PUTは共有書込枠を使用する。

### HTTP状態・エラーコード

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 400 | `invalid_input` | Content-Typeの欠落・JSON非対応、JSON形式・オブジェクト形式の不備、未知・重複キー | `null` |
| 400 | `invalid_input` | 個別項目の型・値・必須キーの欠落、空UUIDなどの不備 | 該当項目名 |
| 400 | `invalid_input` | 並び順の配列・要素・全家計簿ID集合の不備 | `ledgerIds` |
| 400 | `invalid_input` | 新規家計簿を末尾に追加する際、[DBの表示順管理](../../../ledger-core-schema.md#master-order-storage)で定める順位値の上限を超える | `null` |
| 401 | `authentication_changed` | 業務処理中の認証再検証で失効・停止等を検出 | `null` |
| 403 | `forbidden` | 名前変更・削除に必要な家計簿Admin権限がない | `null` |
| 404 | `not_found` | 指定家計簿の不存在・未参加、作成再送時に現在の参加がない | `null` |
| 409 | `request_conflict` | 成功記録のある要求IDの再利用で第7節の同一性条件を満たさない | `null` |
| 409 | `revision_conflict` | 更新版の不一致 | `null` |
| 409 | `ledger_referenced` | 業務記録が残る家計簿の削除 | `null` |
| 503 | `store_unavailable` | 業務処理の保存先障害等 | （キーなし） |

参照制約による削除拒否と保存先障害を区別し、家計簿の不存在と未参加を区別する情報、内部例外・DBの詳細を応答に公開しない。

### 検証の優先順位

受付・JSONオブジェクト／許可キーの検証を通過した要求では、現在の認証と、対象家計簿を指定する操作では現在の参加・操作権限を業務データの検証より先に確認する。以下は複数の不備が重なったときの業務エラーの優先順位であり、内部処理の構成を指定するものではない。

| 操作 | 優先順位（先に該当したエラーを返す） |
| --- | --- |
| 作成POST | 名前・要求IDの入力検証 → 再送照合（第7節） → 同一成功要求の場合は現在の参加確認、新規要求の場合は表示順上限の検証 |
| PATCH | 対象家計簿の存在・参加・Admin権限 → 更新版の妥当性・一致 → 名前の入力検証 |
| 並び順PUT | 更新版の妥当性・一致 → `ledgerIds` の検証 |
| DELETE | 対象家計簿の存在・参加・Admin権限 → 更新版の妥当性・一致 → 参照による削除制限 |

### 更新版競合

- PATCH・DELETEの `revision` は対象家計簿の `revision`、並び順PUTの `revision` は本人の `orderRevision` と原子的に照合する。
- 家計簿単位の `revision` は名前の実値変更時だけ更新する。役割・本人対応の変更では更新しない。
- 入力の正規化後に実値が変わらないPATCH（`revision` だけを指定した場合を含む）は、権限・版・業務制約の検証を通れば無変更成功（200）とし、行版を維持する。
- `orderRevision` は参加家計簿の追加・除外・順序の変更時に更新する。追加・除外では旧順序版を条件とせず、現在の順序に対して操作する。並び替えは家計簿自身の更新版・他アカウントの順序・最終選択を変更しない。
- 並び順PUTで家計簿ID順が変わらない場合は、0件の空配列や1件の場合も含めて無変更成功（200）とし、保存順と `orderRevision` を維持する。無変更時も更新版・全家計簿ID集合を検証し、古い `revision` は409を返す。
- 409 `revision_conflict` の `latest` は行版競合（PATCH・DELETE）なら対象家計簿の最新情報（第5節の家計簿オブジェクト）、並び順PUTの版競合なら最新の一覧と順序版（第5節の家計簿一覧JSONオブジェクト）を返す。

409の `latest` に情報を返す前にも現在の認証を検証し、対象家計簿の行版競合では現在の参加・Admin権限も検証する。認証失効なら401、未参加なら404、権限不足なら403を優先する。現在の権限で認められない情報は返さない。

## 7. 整合性・作成の再送

### 原子性と認可

- 一覧・個別GETでは取得前と結果確定前に現在の認証を検証し、個別GETでは両時点で対象家計簿への現在の参加と必要な権限も検証する。取得に失敗したときは取得済みのデータを返さない。
- 成功応答の家計簿一覧と順序版は同じトランザクションの整合した状態を返す。書込時は変更後の状態を返す。
- 作成POST・PATCH・並び順PUT・DELETEおよび最終選択を保存する2つの開くPOSTでは、業務制約・必要な更新版の照合と当該操作の全変更を一つのトランザクションで確定する。成功の確定直前にも現在の認証・当該操作に必要な参加と権限を検証する。確定前に処理が失敗した場合は当該操作の変更をすべて戻す。確定後の通信断・応答喪失はロールバックの根拠とならず、別の確定済み操作は取り消さない。DELETEでは関連データ削除前に同一書込トランザクション内で参加・Admin権限を確認し、自身の削除処理による参加者行の消滅を権限喪失と扱わない。
- 家計簿作成・招待参加・参加解除による構成変更と順序版の更新も当該操作と原子的に確定する。

### 最終選択

- 最終選択はアカウント単位で端末間共有する。指定して開く・最後の家計簿を開く操作で有効な家計簿を開いたときに保存し、複数端末では最後に確定した選択を保持する。作成・招待参加と開く操作は独立させ、一覧・個別GET、作成・再送、招待参加、名前変更、並び順保存、通常の参加解除では最終選択を変更しない。家計簿自体の削除による最終選択の除去は後述する。
- 指定して開く・最後の家計簿を開く操作はそれぞれ1回の要求で完了する。開く処理で参加を失った場合、指定は404、最後は200と `{"ledger":null}` を返す。履歴なし・現在未参加の場合も最後は同じ応答とし、最終選択を変更しない。開くPOSTの再送も通常の要求として扱う。指定して開く操作は指定ID、最後の家計簿を開く操作は要求時点の最終選択を対象とする。

### 名前変更

- 家計簿ID、全アカウントの並び順・順序版、参加者・人物対応、最終選択、マスタ・業務記録は変更しない。

### 削除

- 業務記録の参照を確認し、参照があれば拒否する。並行する業務記録の登録・更新と家計簿削除が競合しても、参照制約に反する状態で両方が成功しない。削除可否の事前確認APIは設けない。家計簿自体の削除は、参加者の降格・除外における最後の有効なAdminの保護の対象外とする。
- 削除対象家計簿の人物・科目・支払方法、参加者・招待を削除する。関連する全アカウントの一覧から対象家計簿を除き、参加構成が変わるアカウントの順序版を更新する。対象家計簿を指す最終選択を除去する（過去の参加者分も含む）。他の家計簿を指す最終選択は維持する。
- 認証アカウント、共通税率履歴、要求成功記録、他家計簿の業務データは維持する。RESTRICTによる参照整合性を維持し、業務記録の連鎖削除を行わない。
- 削除した家計簿IDは再利用しない。

### 作成の再送

- POST /ledgersでは、サーバー発行の家計簿IDとは別にクライアントが発行した `requestId` で同一作成要求を識別する。[共通再送](../../../ledger-operation-retries.md)に従い、家計簿作成は `ledger.create` として扱う。
- 同一性は要求ID・操作者・操作種類・正規化後の名前で判定する。同じUUIDの表記差や名前の前後空白の差は同一視する。成功記録のある要求IDで異なる操作者・操作・正規化入力を送れば409 `request_conflict` とし、元の家計簿情報を返さない。成功記録が存在しない要求IDは再送照合上の新規要求として扱う。
- 新規要求では家計簿・作成者のAdmin参加・成功要求記録・一覧への追加と順序版を原子的に確定する。確定前に作成者のAdmin参加を確認する。
- 同一成功要求の再送では現在の参加を確認し、改名・並び替え・役割変更後でも参加中なら現在の家計簿一覧と順序版を200で返す。家計簿や参加を再作成せず、家計簿自身の更新版・最終選択・順序・順序版・成功記録を変更しない。現在未参加（家計簿削除済みを含む）なら404とする。
- 保存結果が不明な作成POSTは同じ `requestId` と同じ名前で再送する。要求成功記録は共通再送契約に従って無期限保持する。

### 更新・並び順保存・削除の再送

- PATCH・並び順PUT・DELETEの再送には第6節の更新版照合を適用する。専用の成功再送記録を作成せず、`requestId`を要求しない。削除済みの家計簿へのDELETE再送は404 `not_found` とする。
