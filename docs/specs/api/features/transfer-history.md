# 振替履歴候補・自動補完API・業務契約

**振替名候補検索・支払方法自動補完APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：保存済み振替からの振替名候補検索と支払方法自動補完の2操作。全パスは `/ledgers/{ledgerId}` の下。
- 対象外：振替の保存・削除、マスタ管理、候補表示・補完値の画面適用。
- 関連契約：[振替API](transfers.md)、[家計簿API](ledgers.md)、[人物API](persons.md)、[支払方法API](payment-methods.md)、[振替DB](../../../ledger-transfer-db.md)、[振替画面](../../../ledger-transfer-ui.md)。
- 共通契約：[認証API](../../../auth-api-contract.md)、[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)。

## 2. エンドポイントと権限

| メソッド・パス（家計簿相対） | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /transfers/suggestions` | 振替名候補検索 | Admin・Editor・Viewer | 200 |
| `GET /transfers/autofill` | 支払方法自動補完 | Admin・Editor | 200 |

各要求で現在の認証・対象家計簿への参加を検証する。全体管理者でも未参加の家計簿へアクセスできない。自動補完では第5節の本人所有・書込権限を適用する。Viewerは403。

## 3. 履歴候補・自動補完の値・業務制約

- 同一家計簿の保存済み振替のみを対象とし、未保存入力・他家計簿を含めない。
- 部分一致検索は検索語と振替名の双方について英数字の全角／半角と英字の大文字／小文字だけを同一視する。かな・記号・互換文字の変換やTrimは行わず、保存値と応答の元文字列は変更しない。
- 自動補完の振替名照合と候補の重複除去は元文字列の完全一致（BINARY）とする。検索上同値でも別表記は別候補とする。

## 4. リクエスト

GETには要求本文を必要としない。UUIDのパス・クエリ形式は[振替API第4節](transfers.md#4-リクエスト)に従う。許可したクエリのみ各1値を受け付ける。クエリ名は大文字・小文字を区別する。`q`・`name` に独自の文字数上限は設けず、共通HTTP境界に従う。

### 4.1 振替名候補検索

| クエリ | 必須 | 値 |
| --- | --- | --- |
| `q` | 任意 | 振替名の部分一致検索語。省略・空文字は絞り込みなし |

### 4.2 支払方法自動補完

| クエリ | 必須 | 値 |
| --- | --- | --- |
| `name` | 必須 | 確定振替名（空文字不可） |
| `fromPaymentMethodId` | 任意 | 手動選択された振替元のUUID |

本人対応人物は現在の参加情報からAPIが特定する。本人対応人物がある場合、指定元の支払方法が同一家計簿に存在しないなら400、Editorに所有者権限がないなら403とする。本人対応人物なしの場合は入力形式の検証後、第5節の両項目nullを返す。

## 5. 成功応答・並び順

HTTP 200は下表の項目のみで構成するJSONオブジェクト。全項目を必須キーとし、`null`は明記した項目だけに許す。UUID応答は小文字のN形式。

### 5.1 振替名候補検索

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `suggestions` | 文字列配列 | 元の振替名、0〜100件 |
| `hasMore` | 真偽値 | 条件一致・重複除去後の候補が100件を超える場合のみ`true` |

全対象履歴に検索条件を適用し、元文字列で重複除去した後、候補に該当する振替の最終更新UTC日時の最大値降順、同日時は元文字列のBINARY昇順で最大100件を返す。0件は `{"suggestions":[],"hasMore":false}`。

### 5.2 支払方法自動補完

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `fromPaymentMethodId` | UUID文字列または`null` | 振替元 |
| `toPaymentMethodId` | UUID文字列または`null` | 振替先 |

同名の完全一致履歴のうち、現在の権限で利用可能で、振替元・先の少なくとも一方が本人対応人物の所有する支払方法である履歴を対象とする。Adminは片側または両側が本人所有、Editorは両側が本人所有の履歴に限る。指定元がある場合は振替元がそのIDと一致する履歴だけを対象とする。

対象の最終更新UTC日時降順、同日時は振替IDのBINARY降順の最新1件から両IDを返す。別々の履歴を組み合わせない。取引日・有効期間による絞り込みは行わない。本人対応人物なし、または該当履歴なしの場合は両項目を`null`とし、指定元だけを応答に写さない。取得した支払方法が入力中の取引日に利用できない場合の有効期間判定はクライアント側で行い、古い履歴へのフォールバックは行わない。画面の手動値保護・補完適用は[振替画面](../../../ledger-transfer-ui.md)に従う。

## 6. 失敗応答

### エラー本文

振替履歴APIの業務エラーは以下の4項目のみで構成するJSONオブジェクトを返す。ただし、保存障害の503 `store_unavailable` は `code`・`message` の2項目とする。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けの説明。具体的な文言は実装側で管理し、処理分岐には使用しない |
| `field` | 文字列または`null` | 対象のクエリ名。特定しない場合は`null` |
| `latest` | `null` | 更新版競合は対象外 |

受付前の認証・認証ストア障害・回数制限等の拒否、およびルーティング段階のエラーは共通HTTP境界に従う。業務エラー本文を一律には要求しない。2操作とも共有参照枠を使用する。

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 400 | `invalid_input` | 必須項目欠落、空の振替名、不正UUID、未知・重複クエリ、同一家計簿に存在しない指定元ID | 該当クエリ名 |
| 403 | `forbidden` | 自動補完の操作権限または指定元の所有者権限不足 | `null` |
| 404 | `not_found` | 家計簿不存在・未参加 | `null` |
| 503 | `store_unavailable` | 保存先障害等 | （キーなし） |

内部例外・DBの詳細を公開しない。

### 検証の優先順位

[共通の検証原則](../../../ledger-core-api.md#共通の検証原則)に従う。両操作で受付時の認証を含む共通HTTP境界を適用してから、下表の業務処理へ進む。同一段階の個別項目の順序は規定しない。

| 操作 | 検証・処理の流れ |
| --- | --- |
| 候補GET | 家計簿参加 → 許可クエリ・重複の検証 → 全対象履歴の候補検索・重複除去・並び替え・件数制限 → 応答 |
| 自動補完GET | 家計簿参加・書込ロール → 許可クエリ・重複・必須項目・振替名／UUIDの検証 → 本人対応なしなら両項目null、本人対応ありかつ指定元があれば実在と所有者権限を検証 → 本人所有・権限・指定元条件で最新同名履歴を取得 → 応答 |

## 7. 整合性・認可

- 参照専用であり、振替や更新日時を変更しない。検索・結合は対象家計簿に限定する。
- 取得前に参加を確認し、非参加は404とする。取得障害時は部分データを成功応答として返さない。自動補完は取得時に確認した参加・ロール・本人対応人物に基づく。補完値は取得時点の候補であり、保存時には最新の権限・有効性を検証する。
