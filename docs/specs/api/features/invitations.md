# 家計簿招待・参加受諾API・業務契約

**家計簿招待・参加受諾APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：家計簿招待の一覧・発行・取消、招待のプレビュー・参加受諾。
- アカウント登録招待は[認証API](../../../auth-api-contract.md)の独立した契約に従う。
- 関連契約：[家計簿API](ledgers.md)、[参加者API](members.md)、[招待DB](../../../ledger-core-schema.md#ledger-invitations-storage)、[招待画面](../../../ledger-invitations.md)。
- 共通契約：[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)、[共通再送](../../../ledger-operation-retries.md)。

## 2. エンドポイントと権限

| メソッド・パス | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /ledgers/{ledgerId}/invitations` | 有効招待一覧 | Admin | 200 |
| `POST /ledgers/{ledgerId}/invitations` | 新規発行・同一成功要求の再送 | Admin | 新規201・再送200 |
| `DELETE /ledgers/{ledgerId}/invitations/{invitationId}` | 取消 | Admin | 200 |
| `POST /ledger-invitations/preview` | 招待状態・参加先の確認 | 認証済みアカウント | 200 |
| `POST /ledger-invitations/accept` | 参加受諾 | 認証済みアカウント | 200 |

管理3操作は要求ごとに対象家計簿への現在の参加とAdmin権限を検証する。全体Adminは家計簿Adminを代替しない。preview・acceptは家計簿未参加でも利用できる。本人は検証済みの認証アカウントIDで判定する。

## 3. 招待の値・業務制約

| 項目 | 契約 |
| --- | --- |
| 招待ID | APIが生成するUUID |
| 招待先 | 発行時にアカウントを固定せず、リンクを受け取った登録・ログイン済みアカウントが参加できる |
| 有効期限 | 発行から7日間。現在のUTC日時が期限未満で、未使用・未取消の招待を有効とする |
| 招待トークン | APIが暗号学的に安全な32バイト（256ビット）の乱数を生成し、パディングなしのBase64URLで符号化する。43文字のASCII文字列（`A-Z`・`a-z`・`0-9`・`-`・`_`）とし、家計簿をまたいで全招待で一意とする。[招待DB](../../../ledger-core-schema.md#ledger-invitations-storage)で一意性を保証する |
| リンク | 固定HTTPSオリジンの `/ledger-invitation#token=...`。有効な同一リンクは再取得・再コピー可能 |
| 発行 | 他の有効招待を失効させず、新しい招待を追加する |
| 取消 | 対象招待を失効させる。使用済み・取消済みへの取消は参加や状態を戻さず成功する。期限切れの未使用・未取消招待も取消可能 |
| プレビュー | 読取専用。有効な招待に対して参加済みか未参加かを返す |
| 参加受諾 | 1リンクで新たに参加できるのは1アカウント。未参加者の参加が成功した時だけ消費する。有効な招待を既存参加者が受諾しても参加・役割・人物対応・招待は変えない |
| 新規参加・再参加 | Viewer・人物未設定、新しい参加者更新版を発行する。除外前の役割・人物対応は復元しない。[参加者API](members.md)に従う |

新しい招待へ切り替える場合は取消と発行を用いる。招待による参加はアカウント登録・家計簿を開く操作から独立する。トークンやリンク全体を通常ログへ記録しない。

## 4. リクエスト

パスの `ledgerId`・`invitationId` はUUID（N・D・B・P・X形式。URL上で適切にエンコードする）。UUID値として照合し、UUIDとして解釈できないパスはルーティングの404とする。全桁ゼロのUUIDもパスではUUIDとして扱い、第6節の認可・存在確認に従う。

GET・DELETEには要求本文を必要としない。3つのPOSTはJSONオブジェクトを送る。Content-Typeは `application/json` または `+json` サフィックスを持つJSONメディアタイプを受け付ける。

本文のUUID文字列は.NET `Guid.TryParse` で解釈できる形式（N・D・B・P・X）を受け付け、同じUUID値として照合する。全桁ゼロのUUIDは本文では不正とする。UUIDのバージョンによる入力制限は設けない。

| JSON項目 | 型 | 発行 | preview | accept |
| --- | --- | --- | --- | --- |
| `requestId` | UUID文字列 | 必須 | — | — |
| `token` | 文字列 | — | 必須 | 必須 |

- 「—」は送信不可。キー名は大文字・小文字を区別する。`null`は認めない。入力不備のエラーと検証の優先順位は第6節に従う。
- preview・acceptはいずれも招待URLのフラグメントから取得した `token` をそのまま本文で送信し、大文字・小文字を区別して完全一致で照合する。前後空白の除去や大文字・小文字の変換は行わない。第3節の形式は発行するトークンの契約であり、文字列として受け付けた値に対応する招待が存在しない場合は404 `invitation_invalid` とする。ブラウザーでの取得・一時保存・削除は[招待画面](../../../ledger-invitations.md#ブラウザーへの招待情報の受け渡し)に従う。

## 5. 成功応答・識別と並び順

各JSONオブジェクトは以下の表に列挙した項目のみで構成し、すべて必須キーとする。`null`は参照先の家計簿オブジェクトで明記した項目だけに許す。読み取りの整合性・再送時の応答は第7節に従う。

### 管理3操作の共通応答

GET・発行POST・DELETEの成功応答は共通の招待一覧JSONオブジェクトを返す。

| トップレベル項目 | 型 | 内容 |
| --- | --- | --- |
| `invitations` | オブジェクト配列 | 対象家計簿の現在の有効招待の全件。0件は空配列 |

| `invitations[]` の項目 | 型 | 内容 |
| --- | --- | --- |
| `invitationId` | UUID文字列 | 招待ID |
| `url` | 文字列 | コピー用の招待URL |
| `createdAtUtc` | UTC日時文字列 | 発行日時 |
| `expiresAtUtc` | UTC日時文字列 | 有効期限 |

発行日時昇順、同日時なら招待ID昇順とする。画面上の並び順は[招待画面](../../../ledger-invitations.md)に従う。発行・取消時は変更後の一覧を返し、再送時も現在の一覧を返す。

### preview・既存参加者のaccept

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `status` | 文字列 | previewは未参加なら `valid`、参加済みなら `already_member`。既存参加者のacceptは `already_member` |
| `ledgerId` | UUID文字列 | 招待先家計簿ID |
| `ledgerName` | 文字列 | 招待先家計簿名 |
| `expiresAtUtc` | UTC日時文字列 | 有効期限 |

### 新規参加のaccept

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `status` | 文字列 | `joined` |
| `ledger` | オブジェクト | 参加先の[家計簿オブジェクト](ledgers.md#家計簿オブジェクト)。新規参加時の `role` はViewer、`myPersonId` は `null` |

UUIDの応答形式は小文字のN形式（ハイフンなし32桁）。日時はISO 8601のUTC表記とする。

## 6. 競合・失敗応答

### エラー本文

招待・参加受諾APIの業務エラーは以下の4項目のみで構成するJSONオブジェクトを返す。ただし、保存障害の503 `store_unavailable` は `code`・`message` の2項目とする。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けのエラーの説明。具体的な文言は実装側で管理し、クライアントの処理分岐には使用しない |
| `field` | 文字列または`null` | 対象のJSON項目名。個別項目を特定しない場合は`null` |
| `latest` | `null` | 共通エラー項目。常に`null` |

受付前の認証・認証ストア障害・Origin／CSRF・本文上限・回数制限等の拒否、およびルーティング段階のエラーは第1節の共通HTTP契約・HTTP境界に従う。業務エラー本文を一律には要求しない。GET・previewは共有参照枠、発行・取消・acceptは共有書込枠を使用する。

### HTTP状態・エラーコード

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 400 | `invalid_input` | Content-Typeの欠落・JSON非対応、JSON形式・オブジェクト形式の不備、未知・重複キー | `null` |
| 400 | `invalid_input` | 個別項目の型・値・必須キーの欠落、空UUIDなどの不備 | 該当項目名 |
| 400 | `invalid_input` | 新規参加の末尾追加で[DBの表示順管理](../../../ledger-core-schema.md#master-order-storage)の順位値上限を超える | `null` |
| 401 | `authentication_changed` | 業務処理中の認証再検証で失効・停止等を検出 | `null` |
| 403 | `forbidden` | 管理操作に必要な家計簿Admin権限がない | `null` |
| 404 | `not_found` | 管理対象家計簿の不存在・未参加、対象招待の不存在（他家計簿のIDを含む）、発行再送の結果不在 | `null` |
| 404 | `invitation_invalid` | preview・acceptでトークンが見つからない | `null` |
| 409 | `request_conflict` | 成功記録のある要求IDの再利用で第7節の同一性条件を満たさない | `null` |
| 409 | `invitation_used` | preview・accept・発行再送の招待が使用済み | `null` |
| 409 | `invitation_revoked` | preview・accept・発行再送の招待が取消済み | `null` |
| 409 | `invitation_expired` | preview・accept・発行再送の招待が期限切れ | `null` |
| 503 | `store_unavailable` | 業務処理の保存先障害等 | （キーなし） |

管理対象の不存在と未参加を区別する情報、内部例外・DBの詳細・失効招待の秘密値をエラー応答に公開しない。

### 検証の優先順位

受付・JSONオブジェクト／許可キーの検証を通過した要求では、管理操作は現在の認証・家計簿参加・Admin権限を個別の業務データ検証より先に確認する。preview・acceptは本文のトークンの型を検証した後、招待の照合前に現在の認証を検証する。以下は複数の不備が重なったときの業務エラーの優先順位であり、内部処理の構成を指定するものではない。

| 操作 | 優先順位（先に該当したエラーを返す） |
| --- | --- |
| GET | 現在の認証・家計簿参加・Admin権限 |
| 発行POST | 要求IDの入力検証 → 再送照合（第7節） → 同一成功要求の場合は結果の存在 → 使用済み → 取消済み → 期限切れ |
| DELETE | 対象家計簿内の招待の存在 |
| preview | トークンの型 → 現在の認証 → トークンの存在 → 使用済み → 取消済み → 期限切れ → 現在の参加確認 |
| accept | トークンの型 → 現在の認証 → トークンの存在 → 使用済み → 取消済み → 期限切れ → 現在の参加確認 → 未参加の場合のみ表示順上限の検証 |

## 7. 整合性・再送

### 原子性と認可

- 管理操作は取得・変更の前と結果確定前に現在の認証・参加・Admin権限を検証する。preview・acceptも業務処理の前と確定前に現在の認証を検証する。
- 成功応答は同じトランザクションの整合した状態を返す。取得障害・認証や必要な権限の喪失時は取得済みの情報を返さない。発行・取消・新規参加の書込は当該操作に伴う変更を一つのトランザクションで確定する。確定前に失敗した場合は当該操作の全変更を戻し、別の確定済み操作まで取り消さない。確定後の通信断・応答喪失はロールバックの根拠にならず、クライアントから保存結果を断定できない。
- 新規参加では参加者追加、招待消費、本人の家計簿一覧への末尾追加と順序版の更新を一つのトランザクションで確定する。[家計簿API](ledgers.md)に従い、最終選択・家計簿自身の更新版を維持する。既存参加者の受諾では新規採番や順序版更新を行わない。
- 参加確定時にも招待の期限・使用・取消状態を検証する。同一リンクで複数アカウントが同時に参加する場合は先に確定した1人だけが新規参加し、後の要求は使用済みとなる。取消と参加は同じ書込境界で状態を照合し、取消が先なら参加不可、参加が先なら成立した参加を維持する。

- 発行・取消は招待と発行の成功記録を対象とし、家計簿の属性・更新版、参加者・人物・科目・支払方法、各マスタの更新版・順序版、家計簿一覧の順序・順序版・最終選択、既存業務記録、共通税率履歴、他家計簿を変更しない。新規参加による変更は前述の参加者追加・招待消費・本人の家計簿一覧と順序版に限る。

### 発行の再送

- 発行POSTでは、APIが発行する招待IDとは別にクライアントが発行した `requestId` で同一発行要求を識別する。[共通再送](../../../ledger-operation-retries.md)に従い、招待発行は `ledger-invitation.create` として扱う。
- 同一性は操作者・操作種類・対象家計簿で判定する。同じUUIDの表記差は同一視する。現在の認証・家計簿参加・Admin権限を先に検証し、再送記録を照合する。
- 同一成功要求の再送では発行結果の有効性を確認し、同じリンクを含む現在の有効招待一覧を200で返す。招待・期限・成功記録を変更しない。成功記録のある要求IDで異なる操作者・操作・家計簿を指定すれば409 `request_conflict`。結果が不在・使用済み・取消済み・期限切れの場合は第6節のエラーを返す。
- 保存結果が不明な発行POSTは同じ要求ID・同じ内容で再送する。成功記録が存在しない要求IDは再送照合上の新規要求として扱う。成功した招待と共通再送記録の原子的な確定・成功記録の無期限保持は共通再送に従う。

### 取消・参加受諾の再送

- 取消・acceptはその時点の招待状態で判定する。使用済み・取消済みの招待に対する取消再送は無変更成功（200）とし、現在の一覧を返す。対象招待が不在なら404 `not_found` とする。使用済みリンクに対するacceptは409 `invitation_used` とする。
- 参加受諾の結果不明時は、同一アカウントの現在の参加状況を[家計簿APIの個別GET](ledgers.md)で確認できる。404は元の受諾の失敗を確定するものではない。具体的な再確認・再試行の操作は[招待画面](../../../ledger-invitations.md#家計簿の参加確認結果未実装)に従う。
