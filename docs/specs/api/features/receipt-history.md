# レシート履歴候補・基本情報自動補完API・業務契約

**レシート履歴候補検索・基本情報自動補完APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：保存済みレシートからの店名・所在地・品名候補の検索、および店名確定時のレシート基本情報の取得。
- 関連契約：[レシートAPI](receipts.md)、[人物](persons.md)、[科目](categories.md)、[支払方法](payment-methods.md)、[家計簿](ledgers.md)、[レシートDB](../../../ledger-receipt-schema.md)、[候補入力・自動補完画面](../../../ledger-receipt-suggestions.md)。
- 共通契約：[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)。

## 2. エンドポイントと権限

| メソッド・パス | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /ledgers/{ledgerId}/receipt-suggestions` | 履歴候補検索 | Admin・Editor・Viewer | 200 |
| `GET /ledgers/{ledgerId}/receipt-autofill` | 基本情報自動補完 | Admin・Editor・Viewer | 200 |

各要求で現在の認証と対象家計簿への参加を検証する。候補と所在地・税設定は参加者全員が参照可能。補完する支払方法だけは第5節の本人・権限制約を適用する。

## 3. 値・業務制約

- 同一家計簿の保存済みレシートのみを検索する。画面の未保存入力・他家計簿は含めない。
- 部分一致検索は検索語と候補文字列の双方にUnicode NFKC、かな種統一、言語非依存の英字大小文字非区別を適用する。濁点・空白を除去せず、元の文字列・保存値は変更しない。
- 検索範囲の店名は元文字列の完全一致（BINARY）。候補の重複除去も元文字列の完全一致で行う。表記差が検索上同値でも別候補とする。
- NULL、空文字、空白だけの文字列は候補検索の対象外。その他の候補の前後空白は保持する。自動補完は候補検索とは別に最新履歴の値を取得するため、所在地が未入力でも古い非空値へ置換しない。

## 4. リクエスト

パスとクエリのUUIDは[レシートAPI第4節](receipts.md#4-リクエスト)に従う。許可したクエリのみ各1値を受け付ける。

### 4.1 履歴候補検索

| kind | 必須クエリ | 任意クエリ | 検索範囲 |
| --- | --- | --- | --- |
| shopName | kind | q | 家計簿内の全レシートの店名 |
| shopLocation | kind・shopName | q | 同じ店名のレシートの所在地 |
| itemName | kind・shopName・categoryId | q | 同じ店名・科目の明細の品名 |

`shopName` は元文字列の空文字不可・最大100 UTF-16コード単位。 `categoryId` はUUID。 `q` は最大100 UTF-16コード単位（正規化前）で、省略・空文字は絞り込みなし。1文字から検索できる。候補は検索語による部分一致で絞り込む。

### 4.2 基本情報自動補完

| クエリ | 必須 | 値 |
| --- | --- | --- |
| shopName | 必須 | 確定店名の元文字列（空文字不可、最大100 UTF-16コード単位） |
| transactionDate | 必須 | 実在するローカル取引日（YYYY-MM-DD） |

対象人物は現在の参加情報からAPIが本人対応人物を導出する。

## 5. 成功応答・識別と並び順

すべての応答キーは必須。

### 5.1 履歴候補検索

| キー | JSON型 | 意味 |
| --- | --- | --- |
| suggestions | 文字列配列 | 元の文字列、0〜100件 |
| hasMore | 真偽値 | 条件一致・重複除去後の候補が100件を超える場合のみtrue |

全対象履歴に検索条件と空候補の除外を適用し、元文字列で重複除去した後、候補に該当するレシートの最終更新UTC日時の最大値降順、同日時は元文字列のBINARY昇順で最大100件を返す。品名も明細ではなく親レシートの更新日時を使用する。金額やメモの変更でも候補順位は上がり得る。0件は `{"suggestions":[],"hasMore":false}`。

### 5.2 基本情報自動補完

| キー | JSON型 | NULL |
| --- | --- | --- |
| shopLocation | 文字列 | 可 |
| paymentMethodId | 小文字N形式UUID文字列 | 可 |
| taxInclusionMode | 整数0（税込）・1（税抜） | 可 |
| taxRoundingMode | floor・half_upの文字列 | 可 |

店名の完全一致履歴から、次の2集合それぞれで最終更新UTC日時降順、同日時はレシートIDのBINARY降順の最新1件を選ぶ。

- 所在地・税込／税抜・税端数方式：同一家計簿の全人物の同名店レシート。3項目は同じレシートから取得する。最新の所在地がNULLまたは空文字なら空欄とする値を返し、それより古い所在地を探さない。
- 支払方法：本人対応人物が所有する支払方法を利用した同名店レシートのうち、取引日に支払方法・所有人物双方の有効期間内（両端含む）であり、現在のロールがAdminまたはEditorのもの。本人対応なし・Viewer・利用可能な履歴なしならNULL。Adminも他人物の支払方法へフォールバックしない。

いずれも該当履歴なしならその集合の全項目をNULLとする。別表記・部分一致の店名へフォールバックしない。画面での適用・手動値保護は[候補入力・自動補完画面](../../../ledger-receipt-suggestions.md)に従う。

## 6. 競合・失敗応答

業務エラーは[レシートAPI第6節](receipts.md#6-競合失敗応答)の4項目（latestはNULL）。保存先障害の503はcode・messageの2項目。受付前の認証・回数制限・ルーティング等は共通HTTP境界に従う。2操作とも共有参照枠を使用する。

| HTTP | code | 条件 | field |
| --- | --- | --- | --- |
| 400 | invalid_input | kind不正、必須項目欠落、空の店名、長さ超過、不正UUID・日付、未知・重複クエリ | 該当クエリ名 |
| 404 | not_found | 家計簿不存在・未参加 | NULL |
| 503 | store_unavailable | 保存先障害等 | キーなし |

## 7. 整合性・再送

- 参照専用であり、レシートや更新日時を変更しない。検索・結合は対象家計簿に限定する。
- 取得前と応答確定前に認証・参加を検証し、認証失効時は401、非参加時は404として補完値・候補を返さない。
- 自動補完では開始時から本人対応人物（未対応との切替を含む）またはロールが変化した場合、取得済み支払方法IDを破棄してNULLを返す。新しい人物・ロールで再検索せず、所在地・税設定の取得結果は維持する。
