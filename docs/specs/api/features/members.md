# 参加者API・業務契約

**参加者APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：家計簿の参加者一覧取得・役割と人物対応の更新・除外。全パスは `/ledgers/{ledgerId}` の下。
- 対象外：認証アカウント自体、人物マスタの操作、招待による参加、家計簿自体の操作。
- 関連契約：[家計簿API](ledgers.md)、[人物API](persons.md)、[参加者管理](../../../ledger-participants.md)、[人物・参加者DB](../../../ledger-person-db.md)、[招待](../../../ledger-invitations.md)。
- 共通契約：[認証API](../../../auth-api-contract.md)、[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)、[共通再送](../../../ledger-operation-retries.md)。

## 2. エンドポイントと権限

| メソッド・パス（家計簿相対） | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /members` | 参加者一覧を取得 | Admin | 200 |
| `PATCH /members/{accountId}` | 役割・人物対応を更新 | Admin | 200 |
| `DELETE /members/{accountId}` | 参加者を除外 | Admin | 200 |

- APIは各要求で認証・対象家計簿への現在の参加・Admin権限を検証する。全体管理者の権限は家計簿Adminの権限を代替しない。
- 本人は認証済みアカウントIDで判定する。本人の役割の実値変更・除外は禁止し、本人の人物対応の編集は許可する。確定前の再検証は第7節に従う。

## 3. 参加者の値・業務制約

- 役割は `Admin`・`Editor`・`Viewer`。人物対応は任意で、同一家計簿の1アカウントにつき最大1人物、1人物につき最大1アカウント。他の参加者に対応済みの人物を奪わない。有効期間外の人物も対応候補とする。
- 人物対応の変更は旧対応の解除と新対応の設定を原子的に行う。アカウント表示名と人物名は同期せず、人物の業務記録・支払方法の所有者を移さない。人物対応の変更は本人判定・本人所有分の操作権限に反映される。
- 参加者の除外は参加者行と人物対応を取り除き、アカウント・人物・過去の業務記録を保持する。本人の退会操作は設けず、他のAdminによる除外に統一する。最後の有効なAdminを保護する。
- 参加者の追加は招待で行う。再参加時はViewer・人物未設定とし、以前の役割・人物対応は復活させない。

## 4. リクエスト

パスの `ledgerId`・`accountId` はUUID（N・D・B・P・X形式。URL上で適切にエンコードする）。UUID値として照合し、UUIDとして解釈できないパスはルーティングの404とする。全桁ゼロもパスではUUIDとして扱い、第6節の認可・存在確認に従う。

GETには要求本文を必要としない。PATCH・DELETEはJSONオブジェクトを送る。Content-Typeは `application/json` または `+json` サフィックスを持つJSONメディアタイプを受け付ける。本文のUUID文字列は.NET `Guid.TryParse` で解釈できる形式を受け付け、同じUUID値として照合する。全桁ゼロのUUIDは本文では不正とし、UUIDのバージョンによる入力制限は設けない。

| JSON項目 | 型 | PATCH | DELETE |
| --- | --- | --- | --- |
| `revision` | UUID文字列 | 必須 | 必須 |
| `role` | 文字列 | 任意 | — |
| `personId` | UUID文字列または`null` | 任意 | — |

「任意」はキーの省略を許す。「—」は送信不可。キー名は大文字・小文字を区別する。省略した項目は変更しない。`personId: null` は対応解除を表す。役割の `null` は認めない。

## 5. 成功応答・識別と並び順

全3操作の成功応答は同じ一覧JSONオブジェクトを返す。以下の表に列挙した項目のみを必須キーとして返し、`null` は表で明記した項目だけに許す。

| トップレベル項目 | 型 | 内容 |
| --- | --- | --- |
| `members` | オブジェクト配列 | 対象家計簿の全参加者 |

| `members[]` の項目 | 型 | 内容 |
| --- | --- | --- |
| `accountId` | UUID文字列 | 参加者の認証アカウントID |
| `displayName` | 文字列または`null` | アカウント表示名 |
| `role` | 文字列 | 家計簿内の役割 |
| `personId` | UUID文字列または`null` | 対応する人物ID。未対応なら`null` |
| `personName` | 文字列または`null` | 対応する人物の現在名。未対応なら`null` |
| `joinedAtUtc` | UTC日時文字列 | 現在の参加の開始日時（ISO 8601） |
| `revision` | UUID文字列 | 参加者単位の更新版 |

UUIDの応答形式は小文字のN形式（ハイフンなし32桁）。更新版はAPIが生成するUUID v4とし、一致で照合する。

配列順は次のとおり。

1. 操作者本人。
2. 本人以外の人物対応済み参加者を[人物マスタの共通順](persons.md#5-成功応答識別と並び順)で並べる（順位値が同じ場合は人物ID昇順）。
3. 本人以外の人物未対応参加者を参加日時昇順、同日時ならアカウントID昇順で並べる。

クライアントは認証済みアカウントIDで本人を識別し、操作者の権限・本人対応は[家計簿API](ledgers.md)で管理する。人物の選択候補は人物APIの全人物と参加者一覧を人物IDで照合して求める。画面操作は[参加者管理](../../../ledger-participants.md)に従う。

## 6. 競合・失敗応答

### エラー本文

業務エラーは以下の4項目のみで構成するJSONオブジェクトを返す。ただし、保存先障害の503 `store_unavailable` は `code`・`message` の2項目とする。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けの説明。クライアントの処理分岐には使用しない |
| `field` | 文字列または`null` | 対象のJSON項目名。特定しない場合は`null` |
| `latest` | オブジェクトまたは`null` | 更新版競合時の最新情報。それ以外は`null` |

受付前の認証・認証ストア障害・Origin／CSRF・本文上限・回数制限等の拒否、ルーティング段階のエラーは共通HTTP境界に従う。業務エラー本文を一律には要求しない。GETは共有参照枠、PATCH・DELETEは共有書込枠を使用する。

### HTTP状態・エラーコード

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 400 | `invalid_input` | Content-Type・JSON形式・オブジェクト形式の不備、未知・重複キー | `null` |
| 400 | `invalid_input` | 個別項目の型・値・必須キーの欠落、空UUID等 | 該当項目名 |
| 401 | `authentication_changed` | 業務処理中の認証再検証で失効・停止等を検出 | `null` |
| 403 | `forbidden` | Admin権限がない | `null` |
| 403 | `self_role_change` | 本人の役割の実値変更 | `null` |
| 403 | `self_exclusion` | 本人の除外 | `null` |
| 404 | `not_found` | 家計簿不在・未参加、権限確認後の対象参加者または指定人物不在（他家計簿の人物を含む） | `null` |
| 409 | `person_already_assigned` | 別の参加者に対応済みの人物を指定 | `personId` |
| 409 | `revision_conflict` | 更新版の不一致 | `null` |
| 503 | `store_unavailable` | 業務処理の保存先障害等 | （キーなし） |

### 検証の優先順位

受付・JSONオブジェクト／許可キーの検証を通過した要求では、現在の認証・参加・Admin権限を先に確認する。複数の不備が重なる場合は次の順で判定する。

| 操作 | 優先順位 |
| --- | --- |
| PATCH | 対象参加者の存在 → 更新版の妥当性・一致 → 役割の入力検証 → 本人の役割変更禁止 → 人物IDの入力検証 → 同一家計簿の人物の存在 → 対応の重複 |
| DELETE | 本人の除外禁止 → 対象参加者の存在 → 更新版の妥当性・一致 |

### 更新版競合

- PATCH・DELETEは対象参加者の更新版を原子的に照合する。役割・人物対応の実値が変わった場合に参加者の更新版を更新する。実値が変わらないPATCH（`revision`のみを指定した場合を含む）は、権限・版・業務制約の検証を通れば200とし、版を維持する。
- 409 `revision_conflict` の `latest` は最新の対象参加者1件（第5節の `members[]` と同じオブジェクト）。
- 競合情報を返す前にも現在の認証・参加・Admin権限を検証し、認証失効・未参加・権限不足を検出した場合は401・404・403を優先する。現在の権限で認められない情報は返さない。

## 7. 整合性・再送

- PATCH・DELETEは権限・版・業務制約の検証と変更を一つのトランザクションで確定する。確定前に失敗した場合は当該操作の変更をすべて戻す。確定後の通信断・応答喪失はロールバックの根拠にならず、クライアントから保存結果を断定できない。
- 成功応答は同じトランザクション内の整合した参加者一覧を返す。書込時は変更後の一覧とする。成功確定直前にも認証・参加・Admin権限を再検証し、必要な権限を失った場合は成功とせず、変更をすべて戻す。
- 競合する人物割り当ては先に確定した対応を維持する。同時除外・降格でも現在の操作者の権限を検証し、最後の有効なAdminの保護を維持する。
- 除外時は対象アカウントの家計簿一覧からの除外・順序版の更新を同じ書込トランザクションで確定する。残りの家計簿の相対順と最終選択の扱いは[家計簿API](ledgers.md)に従う。役割・人物対応の変更だけでは家計簿一覧の順序版を変更しない。
- 人物マスタの行版・順序版、家計簿編集版、既存業務記録、他家計簿の参加者を変更しない。
- 書込の再送には第6節の更新版照合を適用する。作成要求IDを用いる処理は対象外。
