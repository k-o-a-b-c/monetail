# 共通税区分・税率履歴API・業務契約

**共通税区分・税率履歴APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：全家計簿共通の日付別税率履歴の取得。
- 対象外：税率履歴の登録・更新・削除（運営者の同期CLIで管理し、HTTP書込APIは設けない）、科目の編集、レシートの入力・保存・計算、Clientキャッシュ。
- 関連契約：[税区分・税率履歴DBと同期CLI](../../../ledger-core-schema.md#shared-tax-history)、[科目API](categories.md)、[レシートAPI](receipts.md)。
- 共通契約：[認証API](../../../auth-api-contract.md)、[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[共通HTTP境界・回数制限](../../../ledger-core-api.md)。

## 2. エンドポイントと権限

| メソッド・パス | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /tax-rates` | 全家計簿共通の税率履歴を全件取得 | 有効な認証アカウント | 200 |

- APIは各要求で現在の認証を検証する。家計簿の作成・参加・選択および役割によらず取得できる。
- GETは共有参照枠を使用する。認証・回数制限等は第1節の共通契約に従う。

## 3. 税区分・税率履歴の値・業務制約

| 税区分コード | 名称 |
| --- | --- |
| `Standard` | 標準 |
| `ReducedFood` | 食品軽減 |
| `ReducedNewspaper` | 新聞軽減 |
| `Exempt` | 非課税 |

- 税区分コードは完全一致。税区分は科目の初期税率を決めるための分類であり、税込／税抜設定とは別の概念。食品軽減と新聞軽減は同じ税率でも別区分として扱う。
- 税率履歴の適用開始日と適用終了日は両端を含む。終了日が `null` の場合は終了なし。実在する日付とし、開始日は終了日以前とする。同じ税区分の適用期間は重複せず、期間の隙間を許容する。
- 税率は百分率のDecimal（8は8%）。全税区分で `null` を許容し、`Exempt` は `null` 必須。税率 `null` はその期間の税なしを示し、課税0%および対応する履歴行が存在しない場合とは区別する。

## 4. リクエスト

- パスパラメーター・リクエスト本文・定義されたクエリパラメーターはない。取引日・税区分・期間による絞り込みやページングは行わない。

## 5. 成功応答・並び順

HTTP 200の成功応答はJSONオブジェクトを返す。各JSONオブジェクトは以下の表に列挙した項目のみで構成し、すべて必須キーとする。`null`は表で明記した項目だけに許す。

| トップレベル項目 | 型 | 内容 |
| --- | --- | --- |
| `rates` | オブジェクト配列 | 全税区分・全期間の税率履歴。0件の場合は空配列 |

| `rates[]` の項目 | 型 | 内容 |
| --- | --- | --- |
| `taxCategoryCode` | 文字列 | 第3節の税区分コード |
| `validFrom` | 日付文字列 | 適用開始日（YYYY-MM-DD） |
| `validTo` | 日付文字列または`null` | 適用終了日（YYYY-MM-DD）。終了なしは`null` |
| `rate` | Decimal文字列または`null` | 百分率のDecimalをInvariantCultureで表した文字列、または`null`。Decimalとして同値の表記を許容する（例：課税0%の`"0"`と`"0.0"`、8%の`"8"`と`"8.00"`）。`null`とは区別する |

- 過去・現在・将来の登録済み履歴を全件返す。同じ数値の税率も区分・期間を保持し、重複排除しない。
- 配列の並び順は保証しない。

## 6. 失敗応答

### エラー本文

共通税区分・税率履歴APIの業務エラーは以下の4項目のみで構成するJSONオブジェクトを返す。ただし、保存障害の503 `store_unavailable` は `code`・`message` の2項目とする。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けのエラーの説明。具体的な文言は実装側で管理し、クライアントの処理分岐には使用しない |
| `field` | 文字列または`null` | 対象のクエリ名。個別項目を特定しない場合は`null` |
| `latest` | `null` | 更新版競合は対象外 |

受付前の認証・認証ストア障害・回数制限等の拒否、およびルーティング段階のエラーは第1節の共通HTTP契約・HTTP境界に従う。業務エラー本文を一律には要求しない。

### HTTP状態・エラーコード

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 400 | `invalid_input` | 未知クエリ | 該当クエリ名 |
| 503 | `store_unavailable` | 業務処理の保存先障害等 | （キーなし） |

内部例外・DBの詳細を応答に公開しない。

### 検証の優先順位

[共通の検証原則](../../../ledger-core-api.md#共通の検証原則)に従う。全操作で受付時の認証を含む共通HTTP境界を適用し、第4節でJSON本文を定義した操作ではJSONメディアタイプ・構文・トップレベルのオブジェクト／許可キーを検証してから、下表の業務処理に進む。

矢印はエラーの優先順位を示す。同一段階の項目は列挙順を要求しない。業務処理は受付時に認証済みのアカウントを使用する。内部処理やクラス構成は指定しない。

| 操作 | 検証・処理の流れ |
| --- | --- |
| GET | 未知クエリの検証 → 全税区分・全期間の履歴取得 → 応答 |

家計簿の存在・参加・役割、再送照合、更新版照合は適用しない。

## 7. 整合性・認可

- 受付時の認証を通過した要求で全履歴を取得する。取得障害時は履歴を返さない。固定HTTPS・ホスト検証・no-storeなど共通HTTP境界を適用する。
- 履歴は全家計簿で共有し、アカウントによって履歴の集合を変えない。取得操作は税率履歴・家計簿・保存済み取引を変更しない。
- 税率履歴の取得結果は保存可否の保証ではない。レシート保存時の最新税率履歴による検証と保存済み実税率の扱いは[レシートAPI](receipts.md)に従う。
