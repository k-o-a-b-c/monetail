# 共通税区分・税率履歴API・業務契約

**共通税区分・税率履歴APIの外部契約の正本。**

## 1. 対象・関連契約

- 対象：全家計簿共通の日付別税率履歴の取得。パスは `/ledgers/{ledgerId}` の下。
- 対象外：税率履歴の登録・更新・削除（運営者の同期CLIで管理し、HTTP書込APIは設けない）、科目の編集、レシートの入力・保存・計算、Clientキャッシュ。
- 関連契約：[税区分・税率履歴DBと同期CLI](../../../ledger-core-schema.md#shared-tax-history)、[科目API](categories.md)、[レシートAPI](../../../ledger-receipt-api.md)。
- 共通契約：[認証API](../../../auth-api-contract.md)、[セッション保護](../../../auth-session-security.md)、[Windows認証](../../../auth-windows-oauth.md)、[家計簿API・回数制限](../../../ledger-core-api.md)。

## 2. エンドポイントと権限

| メソッド・パス（家計簿相対） | 動作 | 権限 | HTTP成功コード |
| --- | --- | --- | --- |
| `GET /tax-rates` | 全家計簿共通の税率履歴を全件取得 | 現在の家計簿参加者（Admin・Editor・Viewer） | 200 |

- APIは各要求で認証・対象家計簿への現在の参加を検証する。全体管理者であっても対象家計簿に参加していなければ閲覧できない。取得結果の確定前の再検証は第7節に従う。
- GETは共有参照枠を使用する。認証・回数制限等は第1節の共通契約に従う。

## 3. 税区分・税率履歴の値・業務制約

| 税区分コード | 名称 |
| --- | --- |
| `Standard` | 標準 |
| `ReducedFood` | 食品軽減 |
| `ReducedNewspaper` | 新聞軽減 |
| `Exempt` | 非課税 |

- 税区分コードは完全一致。税区分は科目の初期税率を決めるための分類であり、税込／税抜設定とは別の概念。食品軽減と新聞軽減は同じ税率でも別区分として扱う。
- 税率履歴の適用開始日と適用終了日は両端を含む。終了日が `null` の場合は終了なし。実在する日付とし、開始日は終了日以前とする。同じ税区分の適用期間は重複せず、期間の隙間を許容する。
- 税率は百分率のDecimal（8は8%）。全税区分で `null` を許容し、`Exempt` は `null` 必須。税率 `null` はその期間の税なしを示し、課税0%および対応する履歴行が存在しない場合とは区別する。

## 4. リクエスト

- パスの `ledgerId` に家計簿IDを指定する。
- リクエスト本文・定義されたクエリパラメーターはない。取引日・税区分・期間による絞り込みやページングは行わない。

## 5. 成功応答・並び順

HTTP 200のJSONオブジェクトは以下の1項目で構成する。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `rates` | オブジェクト配列 | 全税区分・全期間の税率履歴。0件の場合は空配列 |

`rates[]` の各要素は以下の4項目で構成する。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `taxCategoryCode` | 文字列 | 第3節の税区分コード |
| `validFrom` | 文字列 | 適用開始日（YYYY-MM-DD） |
| `validTo` | 文字列または`null` | 適用終了日（YYYY-MM-DD）。終了なしは`null` |
| `rate` | 文字列または`null` | 百分率のDecimalをInvariantCultureで表した文字列、または`null`。Decimalとして同値の表記を許容する（例：課税0%の`"0"`と`"0.0"`、8%の`"8"`と`"8.00"`）。`null`とは区別する |

- 過去・現在・将来の登録済み履歴を全件返す。同じ数値の税率も区分・期間を保持し、重複排除しない。
- 配列の並び順は保証しない。履歴が0件でも `{"rates":[]}` を返す。

## 6. 失敗応答

受付前の認証・認証ストア障害・回数制限等の拒否、およびルーティング段階のエラーは第1節の共通HTTP契約・HTTP境界に従う。業務エラー本文を一律には要求しない。

業務処理中の401・404は以下の4項目のみで構成するJSONオブジェクトを返す。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| `code` | 文字列 | エラーコード |
| `message` | 文字列 | 利用者向けのエラーの説明。具体的な文言は処理分岐に使用しない |
| `field` | `null` | 個別項目を特定しない |
| `latest` | `null` | 更新版競合は対象外 |

保存先障害の503は `code`・`message` の2項目とする。

| HTTP | `code` | 条件 | `field` |
| --- | --- | --- | --- |
| 401 | `authentication_changed` | 業務処理中の認証再検証で失効・停止等を検出 | `null` |
| 404 | `not_found` | 家計簿不在・未参加 | `null` |
| 429 | — | 共有参照枠の超過 | — |
| 503 | `store_unavailable` | 業務処理の保存先障害等 | （キーなし） |

不在と未参加を区別せず、内部例外・DBの詳細を応答に公開しない。Clientの参加・権限情報の再確認は[家計簿API](../../../ledger-core-api.md)に従う。

## 7. 整合性・認可

- 全履歴の取得前と取得結果の確定前に現在の認証・家計簿参加を検証する。認証失効なら401、未参加なら404とし、取得済みの履歴を返さない。取得障害時も履歴を返さない。
- 履歴は全家計簿で共有し、対象家計簿によって履歴の集合を変えない。取得操作は税率履歴・家計簿・保存済み取引を変更しない。
- 税率履歴の取得結果は保存可否の保証ではない。レシート保存時の最新税率履歴による検証と保存済み実税率の扱いは[レシートAPI](../../../ledger-receipt-api.md)に従う。
