# 人物管理 — WinUI 3 機能仕様（移行レビュー草案）

> **未切替・レビュー用。** この文書は既存の確定事項を機能単位に再編した草案。現時点の正本は[人物管理](../../../../ledger-persons.md)であり、この草案との相違は正本を優先する。**新しい操作・仕様を決定する文書ではない。** 承認後に[移行手順](../../README.md)に従って正本を切り替える。

## 1. 範囲と参照

- 対象：管理・設定内の **M01 人物一覧、M02 追加・編集・削除確認、M03 共通並び順設定**。同一Window内で操作する。
- 対象外：参加者と人物の対応付け（[参加者管理](../../../../ledger-participants.md)）、招待、支払方法等の人物選択画面、API・DBの実装内容、旧版からの未承認変更。
- 関連する契約：人物の名前・有効期間・参照削除制限は[人物管理](../../../../ledger-persons.md)、HTTP/JSON/更新版/再送は[人物・参加者API](../../../../ledger-person-api-contract.md)、403/404時の権限・競合と一覧順は[人物競合・後続](../../../../ledger-person-conflicts.md)および[共通再送](../../../../ledger-operation-retries.md)を正本とする。ここでは**Windows画面での扱いのみ**を定める。
- 共通：外観とナビゲーションは[UI_DESIGN](../../../../../UI_DESIGN.md)、日付入力・Enter・IMEは[入力コントロール設計](../../../../59-input-controls-design.md)、表示方式/実装状態は[画面台帳](../../../../screen-inventory.md)を参照する。

以下の「確定済み」は既存正本で利用者確認済みとされる事項の整理であり、**現在のXAML・Clientの実装完了を意味しない**。

## 2. 画面構成・表示（確定済み）

| 画面 | 配置・情報 | 操作・遷移 |
| --- | --- | --- |
| M01 人物一覧 | 家計簿を開いた状態で「管理・設定」の左メニューを残し、右側に家計簿名、人物名、有効開始日、有効終了日を表示。本人の人物名には「本人」を添える。人物IDは画面表示しない。 | 一覧で1人を選択して編集/削除、管理者は追加/並び順変更。ホームへの移動は共通ナビゲーションに従う。 |
| M02 追加・編集 | 一覧の背後を残した標準 ContentDialog。人物名・有効開始日・有効終了日の3欄。人物とアカウントの対応を選ぶ欄は設けない。 | ［登録］または［保存］、［キャンセル］。ダイアログを閉じると一覧へ戻る。 |
| M02 削除確認 | 選択人物の名前を含む、同一Window内の ContentDialog。既定操作は［キャンセル］。 | 明示的に［削除］して実行。参照が残る人物は削除不可。 |
| M03 並び順設定 | 管理者専用の同一Window内の専用領域。全人物を保存対象の家計簿共通順で表示。 | 選択して［上へ］［下へ］、［保存］で確定、［キャンセル］で変更を破棄して一覧へ戻る。 |

### 一覧の初期表示・絞り込みと並び順

- 初期表示は**Windowsの本日の日付に有効な人物のみ**。開始・終了日は両端を含む。［有効期間外も表示］をオンにすると取得済みの全人物を表示する。切替は**画面内の絞り込みだけ**で、追加GETや人物の変更はしない。
- 人物一覧には上記チェックだけを設け、検索や別の絞り込みを追加しない。期間の空欄は制限なしであることを説明する。
- 通常の一覧・人物選択欄は、絞り込んだ**表示対象の中で**本人に対応する人物を先頭、そのほかを家計簿共通順とする。本人が期間外で非表示なら無理に追加しない。本人への対応がなければ先頭移動はしない。
- M03は**全人物を共通順そのまま**表示する。本人先頭の表示用並べ替えを適用しない。新規人物は共通順末尾へ追加される（[人物の並び順契約](../../../../ledger-person-conflicts.md)）。
- 一覧は単一選択。未選択・権限なしでは対象操作ボタンを無効化する。表示対象0件は「表示対象の人物はありません。」と示し、管理者は［追加］から登録できる。

## 3. 操作権限（確定済み）

| 操作 | 管理者 | 管理者以外の本人（Viewerを含む） | その他の参加者 |
| --- | --- | --- | --- |
| 一覧の閲覧 | 可 | 可 | 可 |
| 追加 | 可 | 不可 | 不可 |
| 名前の編集 | 全人物 | 自分に対応した人物のみ | 不可 |
| 有効期間の編集 | 可 | 不可（表示のみ） | 不可 |
| 削除 | 可（確認・参照制限あり） | 不可 | 不可 |
| 並び順の変更 | 可 | 不可 | 不可 |

- 「本人」は**現在ログイン中のアカウントと、家計簿内で対応付けられた人物ID**から判定する。人物名の一致では判定しない。閲覧には家計簿への参加が必要。
- 権限は表示時だけでなく保存時にも現在の参加・役割・人物対応を確認する。403/404の失敗応答で返る本人の現在の権限を使い、閉じた後の操作可否を更新する。権限の確認だけの追加GETを行わない（[権限喪失契約](../../../../ledger-person-conflicts.md)）。

## 4. 追加・編集の入力と保存（確定済み）

- **新規追加**：人物名・有効開始日・有効終了日をすべて空欄で開始する。**編集**：選択人物の保存済み3項目を表示する。管理者以外の本人の編集では期間を変更不可とし、名前だけを保存する。
- 人物名は前後の空白を除いた1～100 UTF-16コード単位（.NET string.Length）、同一家計簿内では前後空白除去後の**完全一致**で重複不可。大小文字・全角半角・Unicode正規化は同一視せず、超過を勝手に切り詰めない。具体的な業務検証・適用範囲は[人物正本](../../../../ledger-persons.md)と[API契約](../../../../ledger-person-api-contract.md)。
- 開始日・終了日の片側空欄はその側の制限なし。両方空欄なら全期間。開始日が終了日より後は保存不可。既存の取引を新期間の外へ追い出す変更も保存不可。
- 日付欄は共通の**空欄可**入力。欄離脱・保存直前に形式を補完し、不正な日付は空欄へ補正する。キャンセル時は補完しない。表示形式、補完、IME、Enter/Shift+Enter/Ctrl+Enterは[共通入力仕様](../../../../59-input-controls-design.md)を適用する。
- ［登録］［保存］を押すとクライアント側で検証可能な入力不備を送信前に止め、該当欄の近くへエラーを出してその欄へフォーカスを戻す。入力や空欄を維持し、エラー領域は通常は確保しない。検証はAPI側でも実施する。
- 名前と有効期間の保存は**1操作**。権限にない項目を黙って部分保存しない。成功時は同じAPI応答に含まれる更新後人物一覧へ反映し、ダイアログを閉じる。成功確認のための追加GETはしない。
- ［キャンセル］/Escは保存せず閉じる。保存中は再度の登録・保存や取消を受け付けない。ContentDialog表示中は背後の管理メニューや画面遷移を操作できない。キャンセル後に編集を自動再開せず、自動保存・保存確認は追加しない。
- 通常のEnterは次の入力欄・ボタンへ進み、最後の欄でのEnter移動は**保存しない**。保存ボタン上のEnterまたはCtrl+Enterが実行操作（権限・検証条件を迂回しない）。IME変換確定を優先し、標準Tab操作も維持する。

### 入力エラーと復旧

| 種類 | 画面動作 |
| --- | --- |
| 名前空欄・上限超過、重複 | 入力を残し、名前欄付近に理由を表示して修正可能にする。 |
| 開始日が終了日より後、既存記録が期間外 | 入力を残し、期間欄付近など画面内に理由を表示して修正可能にする。 |
| 通信・保存失敗 | 入力を保持して原因を表示し、利用者の再試行を可能にする。作成要求ID・更新版・再送の扱いはAPI/Client正本に従う。 |
| 403/404 権限喪失・対象不在 | 入力を保持したまま保存不可と説明。閲覧権限のないデータを取得しない。閉じた後の有効操作は失敗応答の現在権限を使う。 |
| 作成結果の人物が後で削除された要求の再送 | 人物を再作成せず「作成した人物は削除されています」と画面内に示す。 |

画面内の具体的エラー文例は[既存人物正本](../../../../ledger-persons.md)にあるが、文例のすべてを固定文言として確定したものとは扱わない。

## 5. 削除（確定済み）

- 管理者が単一選択した人物について、**名前を含む確認**を出す。既定ボタンはキャンセル。Ctrl+Enterの保存ショートカットから削除は実行しない。
- 人物の参照がある場合は削除しない（支払方法所有者、取引明細、参加者対応等）。関連参照の自動解除はしない。削除可否を事前判定するための一覧全履歴走査も行わない。
- 成功時は応答の最新一覧を反映し確認を閉じる。参照・通信・権限エラーでは確認内で理由を示す。失敗を「削除できた」と扱わず、追加GETや対象の勝手な削除をしない。操作中は重複実行を防ぐ。
- 更新版競合時は最新3項目と更新版を確認内に表示し、本人が［最新内容に切り替える］を選んだときだけ確認対象を更新する。**削除の再実行はさらに明示操作が必要**。認証失効後の削除を自動再送しない。

## 6. 編集・削除と並び順の競合（確定済み）

### 人物編集・削除の409更新版競合

1. 現在の権限で返せる最新の人物名・開始日・終了日**全3項目**を読み取り専用で、元の操作領域内に表示する。相違項目だけの抜粋や差分強調はせず、競合表示用に追加GETはしない。
2. 編集中の未保存入力と古い更新版を保持する。競合を受けただけで自動上書きしない。切替前の古い版での保存を通さない。
3. ［最新内容に切り替える］でのみ入力／削除対象と保存用更新版を最新に差し替える。**未保存入力が置き換わることを説明**し、以後の保存・削除も更新版を再照合する。再競合なら同じ表示に戻す。
4. 競合表示は必要時だけ出してレイアウトを広げる。通常時には表示領域を予約しない。権限喪失の場合は上記の権限エラーを優先する。

### M03 共通並び順の保存

- 管理者が全人物の共通順を選択・上下移動で編集する。［上へ］［下へ］自体では通信しない。［保存］で**全人物IDの順序と全体更新版**を一括保存する。［キャンセル］で破棄して一覧へ戻る。
- 共通順の競合（409）だけは人物編集と異なり、「ほかの操作で変更されています。最新の並び順を読み込みます。」と示し、**未保存の並べ替えを破棄して最新一覧・全体更新版にその場で置き換える**。確認や別GETは行わず、人物増減も反映する。
- 権限喪失時は保存不可と説明し、403/404の権限情報に従う。変更を無断保存しない。

## 7. 認証失効からの再開（確定済み）

- **追加・編集の保存中401**：ダイアログを閉じ、未保存の名前・日付入力、元の人物更新版、作成要求ID等をメモリーに一時保持してログイン画面へ移る。同一API接続先・同一アカウントで再ログインした場合だけ、元の家計簿と最新の参加・権限・本人対応を確認して同じ編集を再開する。復元したことを表示し、**自動で保存しない**。
- 別アカウントや接続先変更では下書きを引き継がず通常の遷移へ進む。元の家計簿に参加できないときは最新人物一覧を追加取得せず、既存の入力を残して保存不可と説明する。再ログイン後に編集権限が失われた場合や対象人物が削除されていた場合も、入力を保持して保存不可と説明する。
- **並び順の保存中401**：未保存の**人物ID順**と元の**全体更新版**を保持。同じアカウント・接続先で再ログイン後、取得済み最新の表示名を使って復元するが、人物の増減があってもID順を黙って補正しない。権限を失っている場合も内容を残して保存不可と説明し、**自動保存しない**。競合が起きれば第6節の最新順へ置換する動作に従う。
- **削除中401**：ログインへ戻り、削除は自動再送しない。追加・編集の下書き復元と混同しない。

この文書による**コード変更は行わない**。機能の実装／後続レビュー時には少なくとも以下を照合する。

| 観点 | 確認すべき結果 |
| --- | --- |
| 一覧 | 期間内のみ／全表示、本人先頭／本人なし、全期間の共通順、空状態、権限ごとのボタン |
