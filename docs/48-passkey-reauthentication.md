# 48 パスキーによる本人再確認

**同じアカウント・既存セッションの本人再確認と、重要操作に使う直近5分の認可ポリシーを実装。** [43 認証設計](43-passkey-authentication-design.md)と[47 ログイン・セッション](47-passkey-login-sessions.md)を引き継ぐ。全失効／復旧コマンドは[49](49-authentication-revocation-recovery.md)で実装し、Web管理画面・パスキー追加／削除は後続。

## 操作とHTTP契約

`/auth/login`でログイン中の本人と固定ログイン期限・直近の本人確認日時を表示し、「本人確認をやり直す」から端末のパスキーを操作する。アカウントや人物コードは入力しない。取消・失敗では確認済みにせず、再操作できる。セッション自体が失効していればログイン操作へ戻す。

| 経路 | 条件と結果 |
| --- | --- |
| `POST /auth/reauthentication/options` | 有効なセッションとCSRFが必要。現在の本人のパスキーだけを候補にした標準認証オプションを返す |
| `POST /auth/reauthentication/verify` | 本文は`{"credential":{…}}`。同じ本人・セッションの署名検証に成功した場合だけ200。再確認失敗は共通メッセージの403 |
| `GET /auth/me` | 従来の本人情報・`expiresAtUtc`に、サーバーUTCの`verifiedAtUtc`を追加 |

未認証・セッション期限切れ・取消・利用停止は401、人物対応の不備は403、認証ストア障害は503。302転送はしない。既存のHTTPS・Origin・CSRF・本文上限・キャッシュ禁止を共用し、登録・ログイン・本人再確認の開始／検証を合わせてIPごと1分20回に制限する。

## 同じ本人・セッションへの固定

- `ReauthenticationChallenges`は、標準Identityの検証状態・認証ID・開始時のセッション識別子ハッシュ・人物コード・有効期限をメモリへ保持する。登録・通常ログインとは別の領域とCookieを使い、5分・1回限り、最大1024件。同じブラウザーの再開始で古い状態を置換し、再起動では未完了分を破棄する。
- 一時Cookieは`__Host-Monetail.Reauthentication`。Secure・HttpOnly・SameSite=Lax・Path=/・Domainなし。アカウント・セッションはクライアント入力から選ばず、検証済みのログイン状態を使う。同じ人物の別セッションへチャレンジを持ち込んでも拒否する。
- `MakeRequestOptionsAsync`へ現在の本人を渡し、その本人の鍵に限定する。検証も標準`PerformAssertionAsync`で行い、Origin・RP ID・チャレンジ・署名・UV・所有者・署名カウンターを確認する。別人の有効なパスキーを使っても本人を切り替えない。
- 署名検証前にSQLiteの書込トランザクションを取り、本人の利用可否・人物対応・鍵状態を確認する。同じトランザクションで標準の鍵状態を更新し、元のセッションが未取消かつ期限内である場合だけ`VerifiedAtUtc`を更新する。検証中に期限へ達した場合、保存失敗や競合では全体を戻す。

## 直近5分の判定と固定期限

重要操作の受付には`RequireAuthorization(RecentPasskeyRequirement.PolicyName)`を付ける。毎要求で確認したDBのセッションに対し、サーバー時刻で次を判定する。

- 失効しておらず、固定ログイン期限より前である。
- `VerifiedAtUtc`が未来ではなく、本人確認から5分未満である。5分ちょうどから403となり、通常ログインが有効なら本人再確認を行える。
- ログイン直後も、ログイン時のパスキー本人確認を使える。通常の画面操作や重要操作の利用では確認日時を更新しない。

このポリシーは重要操作用の部品であり、管理者権限を付与しない。将来の管理APIではAdminロールも別途要求する。今回の検証用の保護経路はテストホストだけに置き、本番にダミーの管理操作は公開しない。

本人再確認で新しいセッションやログインCookieを発行しない。`CreatedAtUtc`・`ExpiresAtUtc`・識別子と元のCookieを維持し、13日経過後の午前2時という固定期限を延長しない。他ブラウザーのセッションの確認日時も更新しない。セッション表の既存列を使うため、EF移行や業務DB変更はない。

## 検証と後続

実IdentityのEC署名と隔離SQLiteで、本人・ブラウザー・セッション・用途の固定、署名の不正、確認から5分の境界、認証途中の失効・人物変更・鍵削除、同時消費・署名カウンター競合、DB障害時の取消と再試行、Cookieと期限の維持、再起動と既存業務値・保存済みtotalの保持を検証する。件数と実行結果は[tests/README.md](../tests/README.md)へ集約する。

全失効／復旧コマンドは[49](49-authentication-revocation-recovery.md)で実装した。Web管理画面、人物・一般アカウント発行、パスキー追加／削除、業務APIは後続。Windows版・旧SQL・本番設定・実データは変更していない。
