# レシート一覧・集計の階層一括読込（LEG-026）

更新: 2026-10-21。`GetReceipts`の月次・年次読込を対象とする。


2026-10-23のレシート税額確定仕様では、分類の詳細画面も`GroupCode=-1`で全明細を取得し、税額配分後に表示分類を絞る。以下の`GroupCode`指定による部分読込API自体の契約は維持するが、その部分モデルをレシート全体の税計算には使わない。

## 変更と互換性

親→グループ→明細→対象者の個別SELECTを、4表のLEFT JOINによる1 SELECTへ変更する。マスタが未読なら従来どおり別途読み、同じDataAccess内のマスタオブジェクトを各モデルへ割り当てる。1つの読込カーソルで階層を取得し、主キーと並び順で繰り返される親・子を一度だけ生成する。親やグループが切り替わったら子の生成状態をリセットする。

- 日時は従来どおり月初／年初から最終日の23:59:59まで。月末・年末の最終秒内の小数部分を含める変更はしない。
- 支払方法は親を絞る。分類はグループのJOIN条件へ置き、該当分類がない親も空のGroupsで残す。
- 親は日時降順・Seq降順、グループと明細はSeq昇順、対象者はコード昇順。子が空の親・グループ、対象者なしの明細も残す。
- 子の所属はレシート／グループ／明細の複合キーで結合する。0のSeqも有効な番号として扱う。複数対象者で同じ明細を重複生成しない。
- ヘッダー・子の値、NULLの空文字化、小数割引率、税設定、更新版、マスタ参照、計算は維持する。読込では保存済みの値・型・更新版・スキーマを変更しない。

対象は一覧・分類別詳細・年次集計などの`GetReceipts`利用経路。PR #28では`GetPaymentReceipts`（残高推算など）と編集時の`LoadReceiptChildData`は既存の階層読込を維持した。その後[36](36-batch-payment-receipt-reads.md)で支払方法別も一括化し、SELECT列・JOINと組立を共通化する。子再読込は従来方式を維持する。保存SQL・DDL・接続設定・画面操作は変更しない。

## 検証と性能比較

Windowsの実SQLiteでFK ON/OFFを検証する。空の階層、同日複数親、同じ子番号の別親、Seq=0、複数対象者、8%／10%と非課税・負額・小数割引、NULL／引用符付きタグ、版と税設定を使い、固定期待値と改修前の支払方法別参照読込の両方で比較する。月次・年次・年月オーバーロード、支払方法／分類単独・併用・該当なし、境界日時、毎回の新規モデルと子再読込、マスタ参照一致も確認する。実SELECTの観測で階層1回を確認し、全保存値・型・版・スキーマ・PRAGMAと書込0回を比較する。

性能は[34 計測方法](34-receipt-read-performance.md)と同じ4ケースで再測定し、[PR #27の基準値](https://github.com/k-o-a-b-c/monetail-legacy/pull/27)と比較する。CSVの親／子SELECT数はSQLのFROMで分類するため、結合した1 SELECTは親に1、子に0と記録される。子の取得件数が0という意味ではない。

実測値・実行コミット・CIは[一括読込PR](https://github.com/k-o-a-b-c/monetail-legacy/pulls?q=is%3Apr+head%3Aperf%2Fbatch-receipt-reads)に記録し、テスト件数・実行方法・最新結果は[tests/README.md](../tests/README.md)へ集約する。共有CIの合成データ・キャッシュ保持後の時間であり、実データ／利用者端末やWeb版の性能は別途確認する。
