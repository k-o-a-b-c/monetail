# 人物管理の競合・権限喪失と後続確認

[← 人物API・DBの入口](ledger-person-api.md)

## 同時編集・失敗・再送（画面・後続業務）

- 人物の更新版・共通順・既存記録と有効期間の衝突・権限・HTTPコード・再送の**API契約は[人物API](specs/api/features/persons.md)が正本**。参加者の役割・人物対応のAPI契約は[参加者API](specs/api/features/members.md)が正本。ここでは画面の競合表示・権限喪失と後続確認のみを扱う。
- 人物・参加者の行編集・削除の競合時は、古い更新版のまま上書きせず、最新情報を画面内で確認して明示的に切り替える（DEC-065）。人物の共通順の競合は例外として通知後に未保存の順序を破棄し、最新一覧と順序版へ自動的に置き換える（DEC-092）。
- 保存の原子性・期間検証は人物APIと参加者APIの契約に従う。各業務の実装範囲は[API実装台帳](specs/api/README.md)を参照する。
- 通信失敗時も、入力を保持し、自動的に重複作成や更新の上書きをしない。要求IDの再送条件と削除済み結果のエラーは[人物API](specs/api/features/persons.md)・[共通再送管理](ledger-operation-retries.md)を参照する。

## 管理画面・後続業務で確認する残りの項目

1. 実装状況は[API実装台帳](specs/api/README.md)・[画面台帳](screen-inventory.md)を参照する。WinUI 3のアカウント管理・パスキー管理の具体的な入口・配置は後続で実装・確認する。
2. 再送契約は[共通再送管理](ledger-operation-retries.md)・[人物API](specs/api/features/persons.md)に従う。認証アカウント作成用表の統合はこの採用に含めず、了承前に範囲を追加しない。
3. 参加者の権限・役割／人物対応の一括保存、除外・再参加、同名時のID非表示、権限喪失時の入力保持は既定方針を維持する。WinUI 3の一覧・編集／除外ダイアログと競合表示は[参加者管理](ledger-participants.md)、招待発行・一覧・取消の画面は[招待](ledger-invitations.md)を正本とする（DEC-116）。

## 権限喪失・削除済み結果への再送

- 別の管理者による降格・除外等で必要な権限を失っていれば、登録・更新を拒否し、入力を残したまま画面内へ理由を表示する（DEC-081）。保存操作を自動再試行したり、編集中の入力を破棄して自動遷移したりしない。
- 家計簿を開いたときは応答の `role`・`myPersonId` をClient共通状態へ反映する。参加者の役割・本人対応の変更を保存した後、人物・科目・支払方法・参加者APIの403/404検知後、および画面再入場など最新の権限が必要なときは[家計簿個別GET](specs/api/features/ledgers.md#2-エンドポイントと権限)で再取得する。200なら現在値に置き換え、404なら対象家計簿の権限・本人対応を破棄する。定期ポーリングは要求しない。Clientのキャッシュはサーバーの認可根拠にしない。取得方式の実装状況は[API実装台帳](specs/api/README.md)を参照する。
- 画面を閉じた後、現在の権限では許可されない画面へ再入場させない。降格では管理画面等、除外では対象の家計簿へのアクセスを制限する。降格後も許可されている閲覧等まで一律に禁止しない。画面制御だけでなく各APIでも現在の参加・権限を検証する。
- 家計簿の操作者情報の再取得は業務データの追加取得とは区別する。
- 人物・科目APIの `created_result_deleted` を受けた場合は、削除済みであることを画面内に表示する（DEC-081）。

## 編集・削除対象不在時の処理

人物・科目・参加者のPATCH・DELETEで404を受けた場合は、対象不在と家計簿不在・未参加を区別するため、まず[家計簿API](specs/api/features/ledgers.md)で現在の参加・操作者情報を再確認する。現在も対象操作に必要な権限があれば、該当する一覧GETで一覧（順序版があるAPIでは順序版も）を再取得して反映し、対象IDが存在しない場合は選択を解除して、編集・削除対象が既に存在しないことを画面内に表示する。入力を保持し、存在しない対象への保存・削除を停止する。権限喪失・家計簿不在・再取得失敗の場合は既定のエラー処理に従い、権限のない業務データを取得しない。自動保存・自動再送・別IDへの対象変更は行わない。

業務APIの回数制限は[家計簿APIの共通契約](ledger-core-api.md)を参照する。
