# 人物管理の競合・権限喪失と後続確認

[← 人物API・DBの入口](ledger-person-api.md)

## 同時編集・失敗・再送（画面・後続業務）

- 人物の更新版・共通順・既存レシートと有効期間の衝突・権限・HTTPコード・再送の**API契約は[人物API](specs/api/features/persons.md)が正本**。参加者の役割・人物対応のAPI契約は[参加者API](ledger-person-api-contract.md)が正本。ここでは画面の競合表示・権限喪失と後続確認のみを扱う。
- 競合時は古い更新版のまま上書きせず、最新情報を画面内で確認して明示的に切り替える（DEC-065）。人物の共通順は、別管理者による変更や人物追加・削除後に古い配列を黙って上書きしない。
- 人物編集では名前・期間のどこかが失敗した場合はその保存全体を戻す。参加者編集での対応の付け替えも、失敗時は元の対応を維持する。別の画面で既に保存した変更まで巻き戻す契約にはしない。期間の検証は各業務データの登録・更新側でも、書込トランザクション内で行う。レシートは接続済みであり、他業務の実装範囲はそれぞれのAPI正本で確認する。
- 通信失敗時も、入力を保持し、自動的に重複作成や更新の上書きをしない。要求IDの再送条件と削除済み結果のエラーは[人物API](specs/api/features/persons.md)・[共通再送管理](ledger-operation-retries.md)を参照する。


## 管理画面・後続業務で確認する残りの項目

1. 人物のAPIは[人物API](specs/api/features/persons.md)、参加者のAPIは[参加者API](ledger-person-api-contract.md)の要求・応答形式で実装済み。人物・参加者・家計簿招待のWinUI 3管理画面を接続済み。WinUI 3のアカウント管理・パスキー管理の具体的な入口・配置は後続で実装・確認する。
2. 共通の再送管理：共通化・基本6列・要求IDの主キー・内容照合・対象への削除制限FKなし・自動削除せず保持は確認済みなので再確認しない。人物削除後の古い再送では再作成せず「作成した人物は削除されています」と画面内に表示する方針も確認済み。応答項目は上記の実装形式を使う。既存の認証アカウント作成用表の統合はこの採用に含めず、了承前に範囲を追加しない。
3. 参加者の権限・役割／人物対応の一括保存、除外・再参加、同名時のID非表示、権限喪失時の入力保持は既定方針を維持する。WinUI 3の一覧・編集／除外ダイアログと競合表示は[参加者管理](ledger-participants.md)、招待発行・一覧・取消の画面は[招待](ledger-invitations.md)を正本とする（DEC-116）。

## 一覧の並び方（API・WinUI 3実装済み）

- 新規人物は[人物API](specs/api/features/persons.md)の共通順の末尾へ追加する（DEC-085）。
- 参加者一覧は「本人を先頭、次に本人以外の人物対応ありを人物の共通順、最後に人物未設定を参加日時の古い順（同順位は内部ID順）」でAPIから返し、WinUI 3もその順序を使う（DEC-116）。参加者専用の並べ替え保存機能は追加しない。

## 権限喪失・削除済み結果への再送（権限情報の取得方式変更は未実装）

- 別の管理者による降格・除外等で必要な権限を失っていれば、登録・更新を拒否し、入力を残したまま画面内へ理由を表示する（DEC-081）。保存操作を自動再試行したり、編集中の入力を破棄して自動遷移したりしない。
- **変更後の方針（未実装）**：人物・科目・支払方法APIの成功応答と403/404業務エラーから、操作者の`currentRole`・`myPersonId`・`permissions`を除く。Clientは必要なときに[家計簿API](ledger-core-api.md)の`GET /ledgers/{id}`で現在の`role`・`myPersonId`を再取得する。200なら共通状態を更新し、404なら参加状態を破棄する。参加中で対象人物だけが不在なら、家計簿GETは200として現在の権限を返す。現在権限では閲覧できない他参加者・最新データは返さない。共通認証・CSRF・回数制限等の拒否形式は従来の契約を維持する。
- 現行実装は403/404の`permissions`から画面権限を即時更新する（DEC-106）。上記の家計簿APIへの一本化は、その応答処理・Clientの共通状態更新・回帰テストを変更するまで実装済みとは扱わない。
- 画面を閉じた後、現在の権限では許可されない画面へ再入場させない。降格では管理画面等、除外では対象の家計簿へのアクセスを制限する。降格後も許可されている閲覧等まで一律に禁止しない。画面制御だけでなく各APIでも現在の参加・権限を検証する。
- 同じ人物を同時編集した更新版の競合はDEC-065の最新情報表示を維持する。権限喪失時も閲覧できない業務データを表示しない。家計簿の操作者情報の再取得は業務データの追加取得とは区別する。HTTP応答の詳細は[人物API](specs/api/features/persons.md)。
- 作成済み人物が削除された後の再送は再作成せず、「作成した人物は削除されています」と画面内に示す（DEC-081）。HTTP項目は[人物API](specs/api/features/persons.md)。

人物・参加者を含む認証済み業務APIは、作成・更新・削除・順序保存等の書込を共有20回／分、参照・家計簿を開く操作を共有120回／分へ分ける方針を確認済み（DEC-069）。この2枠を原則とし、別枠が必要な操作を追加する場合は、理由と対象を示して確認する。
