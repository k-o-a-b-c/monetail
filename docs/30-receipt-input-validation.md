# レシートの登録・流用の入力チェック

## 背景

従来は`UpdateState`で登録ボタンだけを制御し、流用ボタンと`RegisterReceipt`の入口では必須条件を確認していなかった。店名空欄・税区分未選択・支払方法未選択・明細なしでも流用から進め、確認後にSeqやヘッダーを変更してから失敗したり、不完全な内容を保存したりする経路があった。金額範囲のチェックは既に別途実装済み（[25](25-receipt-amount-overflow.md)）。

## 仕様

- `HasRequiredReceiptInput`で店名が空文字でないこと、内税／外税の選択、有効な支払方法の選択、いずれかのグループに明細があることを共通確認する。
- 条件を満たさない間は登録・流用の両ボタンを無効にし、修正すると再び有効にする。店名の変更もその場で状態へ反映する。
- 保存処理の直接呼出でも同じ条件を確認し、不備があればダイアログ・流用のSeq変更・ヘッダー転記・DB保存より前に中止する。追加の通知や自動補正は行わない。
- 店名自由入力・店舗マスタ未登録を許容し、空白だけの名前を新たに禁止する変更は行わない。空グループがあっても別グループに明細があれば保存できる。
- 金額範囲の警告、時刻未設定・更新・日付変更・流用の既存確認を維持する。流用は確認後すぐに新規保存して閉じ、登録の押し直しを要求しない。
- 選択中の内税／外税・端数方式は既存どおり確認後に転記する。税率別合算、既存金額、オーケーの手入力割引、保存SQL・スキーマは変更しない。

今回防ぐのは不完全な入力で保存処理へ進んだ際の追加変更。グループ・明細の追加／編集／削除は従来どおりその操作時点でReceiptの明細へ反映するため、フォーム全体を取り消すトランザクションやReceiptのディープコピーを導入するものではない。有効な入力の確認後の保存失敗・競合時の扱いも[18 保存契約](18-stale-edit-protection.md)のままとする。

## 検証

製品のRegisterFormと実SQLiteをWindows上・FK ON/OFFで使用する。

- 新規／編集で店名空欄・税区分未選択・支払方法未選択・全明細削除・全グループ削除を確認する。両ボタンの無効化と、無効化を迂回した登録／流用の直接呼出が確認前に止まることを比較する。
- 拒否直前の入力・元モデル各値・グループ／明細／支払方法の参照・Seq／更新版・全保存値と型・スキーマを保持し、書込0回を確認する。入力を修正した同じ画面から保存・再読込できることも確認する。
- 新規／更新／即時流用と内税／外税・両端数方式の組合せで、未登録店名・空白店名、任意の所在地／タグ、支払方法、日時、明細、固定期待合計を保存・再読込する。新規／流用では既存レシートを含む他行を保持する。
- 有効な入力でも更新・流用・時刻未設定・日付変更の確認を取り消した場合、入力と元モデル／参照を保持し、DBを書き込まない。

金額範囲と明細の正規化は既存回帰も継続する。件数・CI結果は[tests/README](../tests/README.md)に集約する。親一覧全体のE2Eや利用者環境での手動操作は対象に含めない。
