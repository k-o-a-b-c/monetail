# 同じ分類で異なる税率を登録する

同じレシートの交際費に8%と10%を登録できるようにする（LEG-041）。既存のReceiptGroup・保存構造を使い、DB移行は行わない。

## 画面の動作

グループの重複・統合先は、分類コードと税率コードの組合せで判定する。分類が同じでも税率コードが違えば別グループとして追加できる。同じ組合せの新規追加は無効にする。

グループ一覧では、レシート日付と各グループの分類から初期選択される税率を標準とし、それと異なる税率だけを分類名に添える。2019年10月1日以降の通常分類なら10%は「交際費」、8%は「交際費（8%）」となる。軽減対象やそれ以前の日付では8%を標準とする。同率の別コードも標準として表示を省略し、初期値がマスタに存在しない場合は全グループの税率を表示する。手動の税率選択で標準の定義は変えない。日付変更時は行の名称だけを更新して選択と未反映の入力を保持し、Receipt自体は変更しない。追加するときは従来どおり一覧の空白をクリックして選択を解除し、分類と税率を選んで「追加」する。追加・更新・統合後は、対象オブジェクトの行を選択する。分類だけで行を探して別税率の行を選ぶことを防ぐ。

| 編集内容 | 動作 |
| --- | --- |
| 分類・税率を変更し、同じ組合せの他グループがない | 選択中グループを更新 |
| 分類・税率を変更し、同じ組合せの他グループがある | 「統合」。明細を移し、統合先の税率・メモを保持 |
| 分類・税率を変更せずメモだけ更新 | 選択中グループだけを更新。既存の重複グループを自動統合しない |

税率未選択では追加・更新を止める。例外として、分類変更時に統合先が1グループだけなら、従来どおりその税率を使って統合できる。候補が複数ある場合は税率を明示選択するまで止め、任意のグループへ統合しない。ボタン処理の直接呼出でも同じ条件で検証する。

## 保存・計算の互換性

- `t_receipt_groups`の主キーは`(receipt_seq, seq)`。同じ分類の別税率を既存のSQLで保存・再読込できる。
- 会計合計は引き続き税率値ごとに全分類を合算してから、各レシートの切り捨て／四捨五入を適用する。同率の別コードも計算時には同率として合算する。
- 分類別の参考集計は、各グループの計算値を分類コードごとに合算する。参考額と会計合計の端数差を含む[計算契約](12-calculation-contract.md)は変更しない。
- 保存済みグループの税率や計算結果を、表示・初期選択で変更しない。既存の同分類・同税率の重複も読込だけでは統合しない。
- グループ・明細は従来どおりメモリ上のReceiptを編集し、登録時にDBへ保存する。フォーム全体を取消可能にする変更ではない。流用は確認後の即時新規保存を維持する。

税率の初期選択は[38の条件](38-tax-default-selection.md)を維持する。期間ごとの自動選択（LEG-013）は未実装。内税／外税・端数処理・オーケーの手入力値引・マスタ画面を見送る方針は変更しない。

## 検証

製品フォーム・実SQLiteで、FK ON/OFFの追加・更新・統合、重複追加と税率欠損の抑止、明細参照と統合先メモの保持、正しい行の再選択を確認する。既存の同分類・同税率の重複も保持する。初回表示・日付境界・軽減対象・同率の別コード・標準税率の欠損での表示と、日付変更中の選択・未反映入力・モデル・DBの保持も確認する。

内税／外税と両端数方式で、交際費8%の19円1件と10%の19円2件を新規保存・再読込・更新・即時流用する。内税57円、外税切り捨て61円／四捨五入63円、明細・対象者・分類別の月額／年額を固定値で確認する。メモリ編集・表示ではDB全値／型／版／スキーマ／PRAGMAと書込0回を確認する。
