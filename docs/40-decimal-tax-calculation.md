# 消費税と税率別合算のDecimal化

税率乗算にDoubleを使うと、外税10%の−100円が−110.000…円となり、切り捨てで−111円になる。利用者承認に基づき、この1円誤差を修正する。過去／新規で計算方式を分岐しない。

## 変更範囲

- `Calculation.TaxRateSubtotal`の課税額・非課税額と戻り値をDecimalとし、税率乗算は`1D + rate / 100D`で行う。floorは負の方向への切り捨て、half_upは税額のAwayFromZeroを維持する。戻り値をDoubleへ戻さない。
- `Receipt.CalculateTotal`の税率別辞書・課税／非課税の合算・税率別結果の合計をDecimalとする。値引後の金額をDecimalへ変換して合算し、最終結果を従来どおりInt32へ変換する。
- `Calculation.GroupCalculatedFee`も合算をDecimalとし、`DetailCalculatedFee`は税計算結果をDecimalのまま整数へ変換する。
- `GetGroupStatisticsList`は共通税計算へ渡す値と戻り値の型を合わせる。対象者選択・人数割り・按分額の合算は従来のDouble処理を残し、共通税計算へ渡す時点でDecimalに変換する。

値引額・数量・率による税前金額の計算とDiscountRateのDouble型、人数按分のルールは今回の対象外。金額計算全体からDoubleがなくなるわけではない。レシート合計は従来どおり同率をグループ横断で合算し、分類／明細／人別は従来の参考額の単位を維持する。

## 保存値と表示

- floorの−100円・10%は−111円から−110円へ、−50円は−56円から−55円へ修正する。通常の税額と負の端数を切り捨てる規則は維持する。
- 保存済み`t_receipts.total`やSavedTotal、端数方式を読込・比較・移行で書き換えない。旧保存値との差は既存の一覧比較表示で確認する。
- 明示的な登録・更新の保存SQLは変更しない。オーケーの手入力割引、DB構造、税率初期選択と画面操作も維持する。

## 検証

既存の値引・人数按分・整数範囲の回帰に加え、旧Double境界と修正値、正負・税率混在・両端数方式・非課税・税込／税抜、Decimalの大きな戻り値と会計／参考額を固定値で確認する。実SQLite・FK ON/OFFの画面テストでは、保存値−111円を維持して再計算−110円との差を表示し、全保存値・型・更新版・スキーマ・PRAGMAと書込0回を確認する。

現在の構成・件数・CIは[tests/README](../tests/README.md)を正本とする。以前は旧Doubleの境界値も互換性として固定していたが、今回のユーザー承認で誤差補正へ更新した。旧検証記録は過去のCI・PRに残る。

後続の[41 明細のDecimal計算](41-decimal-discount-calculation.md)で、ここでは対象外としていた値引計算とDiscountRateの型もDecimalへ統一した。現在は明細金額までDecimalで確定し、人数按分へ渡す段階だけ従来のDouble処理を残している。上記の対象範囲は税計算導入時点の記録である。
