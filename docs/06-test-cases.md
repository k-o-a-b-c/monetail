# 06 テスト計画・回帰テストケース

更新日: 2026-10-15 / **テスト定義案・未実行**。

目的: レガシー版の「実際の期待動作」をテストで固定し、将来のオンライン版・別言語版と同じ入力で比較する。差異は変更理由を記録してから解消する。

## テスト実施上の原則

- 実データDBを直接用いず、**バックアップから複製したテスト専用DB**を使う。
- テスト前にアプリのDB接続先を確認し、クラウド同期フォルダや本番DBに誤接続しない。
- 「現行コードから予測できる結果」と「望ましい業務上の結果」は別列で記録する。
- 日時／ユーザー／通貨／税率／割引率／入力順序と期待表示額を固定する。
- 実装済み／要確認／失敗を記録する。実行環境・DBスキーマ・テストデータ版も記録する。

## A. 入力・更新・参照（手動E2E）

| ID | 操作 | 確認内容 |
| --- | --- | --- |
| T-001 | 税込のレシートを新規保存 | 親・グループ・明細・対象者が再表示され、金額・税区分が一致する |
| T-002 | 1件のレシートに複数分類と複数明細 | 件数、表示順、税込／税抜、分類、対象者の対応が保持される |
| T-003 | 同じ明細に複数人を割り当てる | 保存後の対象者選択・分類集計のフィルタ結果 |
| T-004 | レシートの明細を追加・削除・並び替えて編集 | 子の再INSERT後も期待する内容が保持され、他レシートに影響しない |
| T-005 | レシートを流用登録 | 新IDで2件になり、元レシートが変化しない |
| T-006 | レシートを削除 | 親・子・対象者が残存しない。FK ON/OFF両方で確認 |

| T-011 | 同一日付の残高を登録 | 重複禁止のチェックが効くか |

| T-017 | 2つのアプリから同時に新規登録 | ID競合・DBロック・整合性・エラー通知を確認 |

| T-019 | 収入（負単価）と支出を同じレシートに登録 | 合計と各収支列を比較 |
| T-020 | データベースをバックアップ・復元 | 保存件数・金額・最終日時の差異がない |

## B. 計算のゴールデンケース（先にコードの予測値を固定する）

| ID | 入力 | 現行コードから予測した値／留意点 |
| --- | --- | --- |
| C-001 | 税込／単価100／数量2／値引額10／率0 | `(100-10)×2=180円` |
| C-002 | 税抜10%／単価100／数量1／割引0／課税対象 | `Floor(100×1.10)=110円` |
| C-003 | 税抜10%／単価100／数量1／割引0／非課税 | `100円` |
| C-004 | 税抜10%／単価19／数量1の課税明細を2件・同税率 | `Receipt.Total=41円`、明細表示合計`40円`。仕様確認が必要 |
| C-005 | 税込／単価100／数量1／値引率15% | `100-Ceiling(15)=85円` |
| C-006 | 税込／単価-100／数量1／割引0 | `Receipt.Total=-100円`、`Incomes=-100円`、`Expenses=0円` |
| C-007 | 税込／単価100・対象者2人／按分対象者1人 | `GetGroupStatisticsList` の按分額`50円` |
| C-008 | 対象者0人の100円明細／按分モード | `IsOnlyPerson=True` の場合、集計額`0円`。意図確認 |
| C-009 | 口座初期残高1000円、支払い200円、振替出金100円、入金50円 | `1000-200-100+50=750円` |
| C-010 | 口座の残高履歴も取引も存在しない | 推算残高`Nothing` |
| C-011 | JPY残高1500／USDJPYレート150.00 | USD換算`10.00` |
| C-012 | USDJPYの対象月レートがない | USD換算値は空欄 |
| C-013 | 小数値引率12.5%を保存して再読込 | 値保持・例外・精度を実DBで検証（期待値未確定） |
| C-014 | 値引100%超、負数量、税率0% | 許容可否を仕様決定後に期待値記載 |

**注意**: `Math.Floor`、`Math.Ceiling`、`Double`、VBの`Convert.ToInt32`を含むため、新実装側でSQL側の`ROUND`や一般的な四捨五入へ安易に置換しない。

## C. 自動テスト整備の順序

1. DBを使わない純粋計算の試験: C-001〜C-008 をユニットテストに移す。`Receipt.Total`、`Incomes`、`Expenses`、`GroupCalculatedFee`、`DetailCalculatedFee`。
2. 仮DBとスキーマの再現後、保存／読み直しの結合テスト: T-001〜T-012。
3. 年月境界・複数年・円未満・税率混在のテストを追加。
4. 同時アクセス・更新競合・障害時ロールバックを結合テストに追加。
5. 別言語へ移る前に、**入力→期待値**を共有できるJSON／CSVテストフィクスチャにする。
