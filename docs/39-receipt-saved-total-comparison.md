# 保存時合計と再計算値の比較表示

`t_receipts.total`は、仕様変更で再計算した金額に差が出ないかを確認する保存時合計である。再計算値を表示するだけでは不一致が見えないため、一覧の合計セルで差を示す。

## 読込と表示

- `Receipt.SavedTotal As Long?`はDB読込時の保存済みtotalを保持する。SQLite INTEGERの範囲を保持し、NULLを0へ置き換えない。新規のモデルはNothingとする。
- 一覧と支払方法別の共通階層SELECTへtotalを追加し、SQL数・順序・他の列番号は維持する。子だけの再読込では保存時合計を変更しない。
- 会計・集計と一覧の金額欄は従来どおり`Receipt.Total`の再計算値を使う。保存値は計算へ混ぜない。
- 値が異なる合計セルだけをLightYellow、選択時はGoldenrod・黒文字にする。ツールチップで保存値・再計算値・差額（再計算値－保存値）を整数・桁区切りで表示する。
- 差額はDecimalで引き、SQLite INTEGER両端とInt32の再計算値との比較でも桁あふれさせない。
- 一致時は不一致の色と説明を付けない。NULLは未記録で比較不可と説明し、差額0や不一致として扱わない。再計算が範囲超過する場合は既存の「範囲超過」と警告説明を維持する。
- 対象者未設定を示す行のMistyRose色は維持し、その上で不一致の合計セルだけを区別する。再描画・絞り込み・再読込で以前の警告を残さない。

## 保存値の保全

読込・表示・比較では、DBのtotalやNULL、税設定・明細・更新版を変更しない。DB移行と自動補正は行わない。独立した比較クラスや確認ダイアログも追加しない。

明示的な新規登録・更新で現在の合計をtotalへ保存する既存SQLは変更しない。SavedTotalは読込時の値であり、登録・更新後の一覧は従来どおりDBを再読込して新しい保存値を表示する。オーケーの手入力割引と税・端数の計算は維持する。

## 検証

実データを使わず、FK ON/OFFと切り捨て／四捨五入の一時DBで、読込値・NULL・0・整数両端、正負の差額・選択中の表示、既存の行色・範囲超過、文化による桁区切り、表示中モデルの変化・フィルター・空月と再表示を確認する。比較前後で全保存値・SQLite型・スキーマ・更新版・PRAGMAが同一で、書込0回を検証する。

構成・件数・最新結果は[tests/README](../tests/README.md)を正本とする。従来の金額書式テストで「正常な整数表示ならツールチップが空」としていた条件は変更し、一致／不一致／未記録ごとの説明をこの比較テストで検証する。
