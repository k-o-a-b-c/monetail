# 19 DB接続設定と起動時の確認

更新: 2026-10-19 / LEG-007。設定形式は既存の.NET Framework標準XMLを維持する。新しい設定画面・JSON・`.env`は追加しない。

## 設定する場所

利用者はexeと同じフォルダの`HouseholdAccountsBeta.exe.config`を編集し、アプリを再起動する。`applicationSettings`内の`HouseholdAccountsBeta.My.MySettings`にある次の値を変更する。

```xml
<setting name="ConnectionString" serializeAs="String">
  <value>Data Source=E:\家計簿フォルダ\家計簿.sqlite;FailIfMissing=True</value>
</setting>
```

`Data Source`には利用する既存SQLiteファイルを指定する。絶対パス・UNCパスと、exeの場所を基準とする相対パス（例:`Data Source=data\家計簿.sqlite`）を使用できる。起動元の作業フォルダは基準にしない。`C:家計簿.sqlite`や`\家計簿.sqlite`のようなドライブ／ルート相対指定、未指定、メモリDBは受け付けない。

開発時は`App.config`が実行用XMLへコピーされる。`Settings.settings`と生成済み`Settings.Designer.vb`は開発用の設定定義・既定値であり、利用者が編集するファイルではない。3か所の既定値は、従来の実行時設定であるEドライブへ統一した。実行用XMLの設定が優先され、項目を省略すると.NETの既定値が使われる。アプリから設定を書き換える機能は追加しない。

XMLの特殊文字は通常どおりエスケープする（例:`&`は`&amp;`）。ファイル名にセミコロンを含める場合はSQLite接続文字列としてパスを引用符で囲む。接続文字列そのものや内部例外はエラー画面へ出さない。

## 起動時の処理

メイン画面の一覧・マスタを読み込む前に、設定を一度読み、次を確認する。

1. `Data Source`をexe基準の絶対パスへ解決し、既存ファイルか確認する。
2. `FailIfMissing=True`を必ず適用して接続する。設定にFalseがあっても自動作成は許可しない。
3. 元DDLの16テーブル・90列と、税端数の2列・更新版の3列が存在するか確認する。
4. 成功後に通常の画面読込を開始する。設定・DBの問題では「DB設定エラー」を一度表示し、画面読込を中止して終了する。

不在・形式不正・テーブル／列不足を区別し、設定ファイルと解決後のDBパスを案内する。移行不足では対象列と該当SQLのファイル名を示す。失敗した接続は破棄し、プールにも残さない。設定修正・手動移行後は起動し直せる。

DB・フォルダの自動作成、スキーマの自動移行、業務データの保存は行わない。必要な移行はアプリを止め、[税端数](migrations/20261017_01_shop_tax_rounding.sql)、[更新版](migrations/20261019_01_revision_tokens.sql)の順にバックアップしたコピーで確認してから適用する。FK・タイムアウト・プーリング等の既存接続オプションは維持する。

## 確認範囲

必須のテーブル／列の存在を調べる検証で、列型・制約・マスタ内容・実データの整合性を保証する検査ではない。追加の列・索引は許可する。同じスキーマの別の家計DBは判別できないため、利用者は接続先を確認する。詳細なデータ検査・バックアップ復元は[11 DB検査](11-db-audit.md)を参照する。

アプリが設定を読む際のXMLエラーと、その初期化例外も設定エラーとして扱う。アプリの処理が始まる前に.NETランタイム自体が読み込めない設定ファイルは、ランタイム側のエラーとなる場合がある。

自動テストは実際の.NET設定プロバイダー・製品SQLite・DataAccessで、既定値の一致、相対パス・接続オプション、未作成の保持、空／不正／別DB、各移行列・必須列・テーブル不足、追加列許容、拒否時のファイル内容とハンドル解放、設定エラー通知と修正後の再接続を検証する。構成・件数・最新CI結果は[tests/README.md](../tests/README.md)を参照する。利用者環境の起動とエラー画面の手動確認は未実施。
