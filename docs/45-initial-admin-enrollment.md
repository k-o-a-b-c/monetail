# 45 初期管理者と登録コードの発行

**初期管理者の作成と、既存アカウントへのコード再発行まで実装。パスキー登録は[46](46-passkey-enrollment.md)まで実装。ログインは[47](47-passkey-login-sessions.md)まで実装。管理画面は後続。** [43 設計](43-passkey-authentication-design.md)に従い、[44 認証DB](44-auth-database-foundation.md)の共通DIを使う。本番DBへの適用は行っていない。

新規利用を基本とする導入設計は[56](56-new-user-onboarding-policy.md)を参照する。本書のコマンドは既存人物を必要とする現在の実装であり、人物のいない状態から最初の管理者を作る手順は未確定・未実装。既存DBの移行は一度きりの運用作業として扱う。

## 隔離したコピーでの操作

既存DBのコピーを`ConnectionStrings__Monetail`で指定し、最初に追加移行を適用する。実際の接続文字列・生コードはリポジトリへ記録しない。

```sh
dotnet run --project src/Monetail.Api -- migrate-auth-db
dotnet run --project src/Monetail.Api -- initialize-admin --person-code 3
```

人物コードの3は例であり、既存`m_user.code`を明示する。人物・名前・account_name・取引・totalは変更しない。

| 操作 | 処理 |
| --- | --- |
| `initialize-admin --person-code 整数` | 管理者がまだいなければ、既存人物への新しい認証ID・Adminロール・人物対応・登録コードを一つのトランザクションで作る。利用可否はfalseのまま |
| 同じ人物へ初期作成を再実行 | 作成済みとして終了し、認証情報・鍵・コードを変更せず、生コードも再表示しない |
| 別人物へ初期作成を実行 | 管理者が存在すれば拒否。初期作成コマンドで一般アカウントを管理者へ昇格させない |
| `issue-enrollment-code --person-code 整数` | 既存の人物対応と認証IDを再利用する。利用可否がfalseで、パスキーが残っていないアカウントだけを対象にする。古い未使用コードを失効し、新コードを発行する |

発行に成功した時だけ標準出力へ生コードとUTCの期限を表示する。応答を失った場合は、初期作成を繰り返す代わりに`issue-enrollment-code`を明示的に使う。人物やアカウントの二重作成は行わない。人物不在・対応不備・未適用移行・利用中アカウント等は終了コード1とし、Webサーバーを起動しない。

## コードの保存と保全

`auth_enrollment_codes`へ、暗号学的乱数32バイトから作ったコードのSHA-256ハッシュ、NOT NULLの認証ID、用途、UTCの作成／失効期限、消費日時、取消日時を保存する。生コードを保存せず、期限は発行から10分とする。未消費・未取消のコードはアカウントごとに一つとし、DBの一意索引でも制約する。

SQLiteの書込トランザクションで同時実行を直列化する。初期作成の途中失敗では認証ID・ロール・対応・コードを全て戻す。再発行の途中失敗でも古いコードの取消を戻す。管理操作のログには対象人物・認証ID・操作・結果を記録し、生コードを通常ログへ含めない。

消費・取消状態は単回登録のための保存基盤であり、コードの検証・期限切れ拒否・原子的な消費・パスキー登録成功時の有効化は、[46 登録処理](46-passkey-enrollment.md)で実装した。このコマンドだけでは家計APIを利用できない。

## 検証と後続

合成データと実SQLiteで、既存業務値の保持、初期作成の再実行、再発行、ハッシュのみ保存とログ非出力、途中失敗、利用中・鍵が残るアカウントの拒否、同時実行を検証する。構成・件数・結果は[tests/README.md](../tests/README.md)へ集約する。

全失効・緊急復旧・復元後の全体リセットは[49](49-authentication-revocation-recovery.md)まで実装した。既存人物への一般アカウント初回発行APIは[54](54-admin-account-creation.md)まで実装した。一般・管理者アカウントへの再発行APIは[55](55-admin-enrollment-code-reissue.md)で実装した。新規人物追加、停止のHTTP経路、追加管理者の権限変更は後続とする。ログイン画面は[47](47-passkey-login-sessions.md)まで実装した。登録画面は[46](46-passkey-enrollment.md)を参照する。今回の再発行は停止処理そのものではなく、コードを発行しても利用可否はtrueにしない。
