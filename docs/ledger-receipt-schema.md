# レシートDBの物理設計案（未実装・レビュー用）

更新: 2026-11-09。対象は**新APIのSQLite/EF Core**。旧VB/WinFormsの保存テーブルは変更しない。
確定済みの業務仕様と、実装前に確認する物理設計上の**提案**を区別する。本文の「提案」は利用者確認を経るまで確定仕様ではない。
関連: [科目・税・権限](ledger-core-schema.md#category-receipt-handoff)、[計算・集計](12-calculation-contract.md)、[旧DB](02-database.md)、[既存の再送契約](ledger-operation-retries.md)。

## 1. 全体構造とキー

| テーブル | 粒度 | 主キー（確定） | 親 |
| --- | --- | --- | --- |
| `ledger_receipts` | レシート1件 | (`ledger_id`, `receipt_id`) | 家計簿・支払方法 |
| `ledger_receipt_groups` | 科目ごとのグループ | (`ledger_id`, `group_id`) | レシート・科目 |
| `ledger_receipt_details` | 購入・収支明細1行 | (`ledger_id`, `detail_id`) | グループ |
| `ledger_receipt_detail_people` | 明細に対応する人物1人 | (`ledger_id`, `detail_id`, `person_id`) | 明細・人物 |

- **確定方針:** 家計簿をまたぐ参照は禁止。業務IDはサーバー発行の**UUID v7**（32文字N形式）、更新版・クライアントの作成`requestId`はUUID v4。IDの採番順を一覧表示順に流用しない。現在のマスタAPIはv7化前のため、業務ID全体の切り替えは既存データ・既存認証との整合性を別途確認する。
- **確定方針:** 既存マスタと同じく**`ledger_id`を含む複合PK**とし、レシート・グループ・明細の**ID単独にUNIQUE索引を追加しない**。UUID v7はサーバーが発行するが、DBで保証する一意性は各家計簿内の複合キー単位。これは既存の科目・人物・支払方法と同じ設計であり、家計簿をまたぐID単独の一意性をDB要件にしない。グループの「同じレシート内に同科目を重複させない」複合UNIQUE索引は別途設ける。
- 子テーブルには`ledger_id`を必ず持ち、すべてのFKは**同一家計簿内の複合FK**とする。親・マスタの削除はRESTRICT、レシート自身の削除だけ明細・対応人物・グループを**同一トランザクションで明示的に削除**する案（SQLite FKのCASCADEに依存しない）。
- 新規レシートのヘッダーから明細・対象人物まで一括確定する。部分保存や親だけのコミットは行わない。

## 2. `ledger_receipts`（レシート親）

列名は旧版の `date` → `transaction_at`、`tax_type` → `tax_inclusion_mode`、`total` → `total_amount` に整理した。**これは新テーブルの列名であり、旧版の列名・値・計算処理は変更しない。** 列順はキー → 取引内容 → 税・周期・金額 → メモ → 更新版・監査情報の順。

| 列 | SQLite型・NULL | 内容 |
| --- | --- | --- |
| `ledger_id` | TEXT NOT NULL | 家計簿ID、PKの一部 |
| `receipt_id` | TEXT NOT NULL | UUID v7、PKの一部 |
| `transaction_at` | TEXT NOT NULL | **取引日時を時刻まで保持**。旧版のローカル日時をUTCへ読み替えず、日付部分を税率履歴・有効期間の照合に使う。具体的なTEXT書式と秒未満の精度はAPI契約で定める |
| `shop_name` | TEXT NOT NULL | 店名。マスタFKは設けず、自由入力 |
| `shop_location` | TEXT NULL | 店舗所在地 |
| `payment_method_id` | TEXT NOT NULL | `(ledger_id, payment_method_id)`で支払方法FK |
| `tax_inclusion_mode` | INTEGER NOT NULL | 0=税込、1=税抜（旧版`tax_type`の値と計算契約は維持） |
| `tax_rounding_mode` | TEXT NOT NULL | `floor` / `half_up` |
| `recurrence_interval` | INTEGER NULL | 周期間隔。設定時は1以上の正整数 |
| `recurrence_unit` | TEXT NULL | `Week` / `Month` / `Year` |
| `total_amount` | INTEGER NOT NULL（確定） | 保存時に計算した合計を必ず保持。符号付きInt32範囲内。旧版のNULL値は移行時に個別対応 |
| `memo` | TEXT NULL | レシート自由記述。旧`tag`相当 |
| `revision` | TEXT NOT NULL | レシート単位の楽観的更新版（UUID v4） |
| `created_by_auth_user_id` | TEXT NOT NULL | 作成した認証アカウントID |
| `created_at_utc` | TEXT NOT NULL | 作成UTC日時 |
| `updated_by_auth_user_id` | TEXT NOT NULL | 最終更新した認証アカウントID（新規時は作成者） |
| `updated_at_utc` | TEXT NOT NULL | 最終更新UTC日時（新規時は作成日時） |

**制約／索引案**

- `FK(ledger_id)→ledgers(id)`、`FK(ledger_id,payment_method_id)→ledger_payment_methods(ledger_id,payment_method_id)`を設ける。**作成者・更新者の両IDはそれぞれ`AspNetUsers(Id)`へのRESTRICT FKを設定する（確定）**。レシート監査情報に参照されている認証アカウントは物理削除不可とし、無効化しても履歴と認証IDを残す。アカウント退会・削除機能は現時点で未実装であり、将来の退会仕様は別途検討する。
- `CHECK(tax_inclusion_mode IN (0,1))`、`CHECK(tax_rounding_mode IN ('floor','half_up'))`、`total_amount`はNOT NULLかつ符号付きInt32範囲内。
- 周期は**両列NULL（初期値：なし）または両列非NULL**。非NULL時は`recurrence_interval >= 1`かつ`recurrence_unit IN ('Week','Month','Year')`をDBとAPIの両方で検証する。隔週は2+Week、3か月ごとは3+Month。曜日・営業日などの規則列は持たない。
- 周期がある場合、レシート内に`occurrence_type='Regular'`の明細が**1件以上必須**。周期なしでも定期明細を認める。これは行をまたぐためAPIの一括保存トランザクションで検証する。
- 一覧・残高参照用の`(ledger_id,transaction_at,receipt_id)`、`(ledger_id,payment_method_id,transaction_at,receipt_id)`索引を提案する。日時TEXTは時系列で字句順が一致する正規化書式を使用し、API/DBで同一書式へ統一する（厳密な小数秒精度などは後続で確定）。
- `revision`はレシート親のみ。明細・グループ単位の更新版は持たない。

## 3. `ledger_receipt_groups`（科目グループ）

**税率は明細へ移動**し、グループは科目とメモのみを保持する。同じ科目内に異なる税率の明細を登録できる（DEC-155）。

| 列 | SQLite型・NULL | 内容 |
| --- | --- | --- |
| `ledger_id` | TEXT NOT NULL | 家計簿ID、PKの一部 |
| `group_id` | TEXT NOT NULL | UUID v7、PKの一部 |
| `receipt_id` | TEXT NOT NULL | 同一家計簿レシートへのFK |
| `category_id` | TEXT NOT NULL | 同一家計簿科目へのFK |
| `memo` | TEXT NULL | グループ自由記述 |

- **同一レシート・同一科目のグループは1件**。率が異なってもグループを分割しない。
- 重複禁止は通常の複合UNIQUE索引1本。`category_id`はNOT NULLであり、税率NULL用の部分UNIQUE索引2本は廃止する。

```sql
CREATE UNIQUE INDEX ux_ledger_receipt_groups_category
  ON ledger_receipt_groups(ledger_id, receipt_id, category_id);
```

- **グループの表示順列はなし**。科目の`display_order ASC, category_id ASC`に従う。グループ自体は税率で並べ替えない。
- 科目の`tax_category_code`は明細作成時の税率初期選択だけに用いる。グループに税区分・税率・課税対象フラグを持たせない。
- 使用済み科目の`income_expense`変更は拒否。名前・初期税区分など他の編集は可能。参照中の科目削除はRESTRICT。

## 4. `ledger_receipt_details`（明細）

旧版の `fee` → `unit_price`、`discount_fee` → `unit_discount_amount` に変更し、`display_order` を親キー直後に置く。実税率`tax_rate`は明細単位へ移す。旧Windows版の物理列・計算処理は変更しない。

| 列 | SQLite型・NULL | 内容 |
| --- | --- | --- |
| `ledger_id` | TEXT NOT NULL | 家計簿ID、PKの一部 |
| `detail_id` | TEXT NOT NULL | UUID v7、PKの一部 |
| `group_id` | TEXT NOT NULL | 同一家計簿グループへのFK |
| `display_order` | INTEGER NOT NULL | グループ内の並び順、0以上 |
| `name` | TEXT NOT NULL | 明細名 |
| `unit_price` | INTEGER NOT NULL | 単価、符号付きInt32（旧版`fee`） |
| `quantity` | INTEGER NOT NULL | 数量、1以上・Int32上限以下 |
| `unit_discount_amount` | INTEGER NOT NULL | 1単位の値引額、符号付きInt32（旧版`discount_fee`） |
| `discount_rate` | TEXT NOT NULL | 率値引（%）、Decimal、0～100、小数可 |
| `tax_rate` | TEXT NULL | **実税率（%）、Decimal。NULL=非課税、'0'=課税0%** |
| `expense_type` | TEXT NOT NULL | `Fixed` / `Variable` / `Excluded` |
| `occurrence_type` | TEXT NOT NULL | `Regular` / `Irregular` / `Temporary` |
| `memo` | TEXT NULL | 明細自由記述 |

- 明細金額：`x=(unit_price-unit_discount_amount)*quantity`、`discount_by_rate=Ceiling(x*discount_rate/100)`、`net=x-discount_by_rate`。**Decimalで計算し、従来の値引と税端数の規則を維持**。単価・値引額・数量・合計等はInt32範囲を検証し、超過ならAPIで保存拒否。入力値の0・100への自動補正は行わない。
- `discount_rate`と`tax_rate`はDecimal文字列のTEXT保存。APIはInvariantCultureで解析・正規化して数値を比較し、`8`・`8.0`・`08`を同じ値として扱う。非課税NULLと課税0%は別物。形式・数値範囲をAPIで検証する。TEXTの辞書順で税率を比較しない。
- **明細の税率候補は取引日に有効な全税区分履歴から数値重複を除いたもの＋非課税**。新規明細では科目の`tax_category_code`と取引日から得た税率を初期選択する。履歴がなければ別区分・別日付から代用せず明示選択を要求。明細ごとに変更可能。同じグループに非課税・課税0%・複数税率を混在させられる。
- **保存時は新規・更新・流用による新規登録のいずれでも、全明細の税率を取引日の有効な候補と照合**する。候補外の率がある場合は保存を拒否し、利用者による再選択を要求する。取引日・税率・明細が未変更の更新でも例外を設けないため、税率履歴が後から変更された場合はメモなど他項目のみの編集でも保存できないことがある。保存済みの税率を自動変更しない。
- **税込・税抜と端数方式はレシート単位のまま**。レシート合計は科目・グループをまたいで同じ数値税率の課税明細を合算・丸め、非課税分は別計上。課税0%と非課税は区別する。グループ・明細・人物の参考額の合計とレシート合計に差が生じ得る。**複数税率が同じグループに混在する場合のグループ参考額は後述の第4節の確定仕様**（DEC-156）に従う。
- **費用区分の初期値・選択肢は科目収支区分に依存**：収入科目は`Excluded`のみ、支出科目は`Fixed`/`Variable`/`Excluded`（初期値`Variable`）。`net`の正負に関係なくAPIでも検証する。
- 発生区分は`Regular`/`Irregular`/`Temporary`、初期値`Irregular`。レシート周期ありなら少なくとも1明細がRegular。
- 明細は`display_order ASC, detail_id ASC`で表示。順序は非負、同順序は許容しIDで安定ソートする。
- 明細名やメモの長さ制約はUIとの整合後に確定。

### 税率入力の支援方針（UI未実装）

- **確定（DEC-158）：通常の新規明細は、所属する科目マスタの初期税区分と取引日から税率を自動設定する**。直前の明細の税率を自動では引き継がない。各明細で手動変更できる。
- **明細複製は元明細の実税率を引き継ぐ**（通常の追加とは区別）。同じ科目の連続明細でも税率を無条件には引き継がない。複数明細の一括変更・キーボード操作等の詳細はUI設計時に検討する。手入力・保存済み値を勝手に上書きしない。
- レシートの流用時は各明細の保存済み税率を引き継ぐ。日付変更では各明細を検証し、候補外の率を黙って変更しない。

### WinUI 3の明細入力と一覧の分離（**DEC-159で基本方式確定・未実装**）

**明細の入力フォームと登録済み明細一覧を分ける**。旧Windows版の入力→明細追加→品名欄へ戻る流れを引き継ぎ、標準WinUI 3コントロールでキーボード主体の連続入力を可能にする。直前の「一覧行を直接編集し、詳細を行内で展開する」案は**不採用**とする。**レシート一覧の［新規］／［編集］から、上部の家計簿名・ナビゲーションを残し、その下のメイン領域全体をレシート専用入力画面へ切り替える**（DEC-162）。記録ホームの左「レシート」・右「資金移動／残高」の2領域はどちらも入力画面に置き換わり、一覧を背後に表示しない。別Window・レシート入力用の`ContentDialog`・明細ごとの`ContentDialog`は開かない。外部UIライブラリや自動保存を必須としない。

| 領域 | 項目・操作 | 方針 |
| --- | --- | --- |
| 画面の入口と出口（DEC-162） | レシート一覧の［新規］［編集］、入力画面の［保存］［キャンセル／戻る］ | 上部共通ナビゲーションは維持し、**メイン領域全体**でレシートを編集。保存成功後／キャンセル確定後は元のレシート一覧へ戻り、検索条件・スクロール位置・選択行を可能な限り維持。未保存変更がある場合の離脱確認は下記の**DEC-163確定仕様**に従い、自動破棄はしない |
| レシート親情報（DEC-171） | 取引日・時刻／店名・店舗所在地／支払方法・税込税抜・税端数／繰り返し周期・メモ | **上段4行**にまとめ、画面下部の保存操作付近に自動計算の合計を表示。詳細は後述のDEC-171 |
| 科目・グループ選択（DEC-172） | 左側に追加済み科目一覧、上部に科目ComboBox＋［追加］、右側に明細入力・一覧 | **1科目1グループ**。科目を選択しただけでは追加しない。追加後はその科目を選択し品名欄へ。科目別参考額はDEC-156 |
| **明細入力フォーム** | 品名・単価・数量・単価値引・率値引・税率・費用区分・発生区分・対象人物・メモ | **全項目を一覧と独立したフォームで編集**。主な入力（品名・単価・数量・値引）を連続操作できる。税率は明細の`ComboBox`で選択 |
| **登録済み明細一覧（DEC-164・176）** | **現在選択中の科目の明細のみ**。品名、単価、数量、値引有無・税率・明細参考額など | **一覧セルは読み取り専用**。行の選択と同時に上のフォームに値を読み込み、編集モードにする（DEC-176）。科目切替時は一覧の表示対象だけを切り替え、他科目の明細を消去・変更しない。セル直接編集や行内詳細展開は行わず、列幅・表示項目の細部は実装前に調整 |
| 明細追加・更新（DEC-176） | フォームの［追加］／［更新］ | **明細を1回選択した時点でフォームに読み込み［更新］へ切替**。選択解除で入力値を保ったまま［追加］へ戻す。［更新］は元明細へ反映、［追加］は新規明細。どちらもレシート全体のAPI保存はしない |
| 明細流用（DEC-176・177） | **一覧で選択 → ［流用］ → ［追加］** | ［流用］で現在のフォーム値（実税率・対象人物など）を保持しながら、元明細の選択／更新対象との関連付けだけ解除して［追加］モードにする。**［流用］を押した時点では追加しない**。元明細は変更しない |
| 明細削除（DEC-178）・並び替え | 一覧の選択明細を対象とする | **［削除］は確認なし**で選択明細を画面内モデルから削除する。対象明細の未反映編集も明示的な削除操作として破棄する。削除後は次の明細、なければ前の明細を選択し、［削除］ボタンにフォーカスを保持。残り0件では品名欄へ移動。並び替えの操作方法は後続で設計 |

**レシート親項目の4行配置（DEC-171・確定／未実装）**：共通ヘッダーの下にあるレシート専用画面の**明細・科目領域より上**に、レシート情報を次の4行で表示する。横幅が不足する場合は折り返し・縦積みにして、項目や入力欄を切り捨てない。正確な列幅とブレークポイントは実装時に調整する。

| 行 | 左から右への項目配置 |
| --- | --- |
| 1 | **取引日** → **時刻** |
| 2 | **店名** → **店舗所在地** |
| 3 | **支払方法** → **税込／税抜** → **税端数（切り捨て／四捨五入）** |
| 4 | **繰り返し周期** → **レシートメモ**（横幅を広めに確保） |

- **フォーカス順は上表の行・左から右**。`Enter`／`Shift+Enter`で次／前の入力欄へ移動する共通契約を適用し、IME変換中・候補展開中のEnterは確定を優先する。上段入力後の明細・科目欄との実際のフォーカス接続は画面全体の実装時に調整する。
- 店名・店舗所在地は**既存の入力履歴から候補を提示しつつ自由入力を許容**する。候補選択だけを必須にせず、店マスタの新規作成を前提にしない。候補の検索範囲・ソート・保存方式は後続設計とする。
- 繰り返し周期は**なしが初期値**。周期を設定するときだけ**間隔（1以上の整数）と単位（週／月／年）**を入力できるようにする。具体的なコントロール部品は後続検討。周期ありなら定期明細を1件以上必要とする既存契約（DEC-148）は維持する。
- **レシート合計は明細から計算して表示**し、親情報の4行へ入力欄として追加しない。保存操作の近くの**画面下部**に合計を表示する。税率別合算・端数処理・保存時の検証などの業務契約は変更しない。

**科目の追加と表示（DEC-172・確定／未実装）**：レシート情報の下で**左側にこのレシートに追加済みの科目一覧**を置き、右側に選択中の科目の明細入力フォームと登録済み明細一覧を置く。左側一覧は全科目マスタではなく、このレシート内の科目グループだけを表示する（1科目1グループ）。各行は科目名とグループ参考額を表示し、科目マスタの`display_order ASC, category_id ASC`に従って並べる。レシート全体の合計は選択中の科目だけでなく全科目のデータから算出する。

- 左側の一覧の**上部に［追加する科目］ComboBoxと［追加］ボタン**を並べる。旧Windows版の**「科目を選択 → ［追加］を押す」の2ステップ**を維持する。ComboBoxの選択変更だけではレシートの科目グループを追加しない。キーボードから候補を絞り込める入力支援を用意し、追加用の別ダイアログは開かない。
- **すでにレシートにある科目の重複追加は禁止**する（DBの同科目1グループ制約と一致）。未選択・追加済みの科目では［追加］を無効化するなど、重複登録できないようにする。対象外の科目を候補に残すか除外するかは実装時に調整する。
- ［追加］が成功したら**新科目を左側一覧に追加して選択中の科目とし、右側の明細入力フォームの品名欄にフォーカス**を移す。追加はレシート画面内の未保存状態への反映であり、レシート全体のAPI保存は行わない。明細の初期値・対象人物の選択保持はDEC-158・161に従う。
- **一覧の科目切替時の未反映下書き保護**はDEC-160に従う。具体的なクリック・↑／↓・Enter操作はDEC-173で確定し、科目一覧の単なるフォーカス移動だけで未反映下書きを破棄しない。

**追加済み科目一覧の切替操作（DEC-173・確定／未実装）**：左側一覧では、**マウスで科目行をクリックするとその科目への切替を要求**し、**キーボードの↑／↓はフォーカス中の行を移動するだけ**で、表示中の科目・右側のフォーム・明細一覧を切り替えない。**Enterでフォーカス中の科目への切替を要求**する。現在表示中の科目を再選択した場合は何もせず、編集中の下書きも変更しない。

- **切替が成功した時点**で左側の選択表示と右側の明細一覧を対象科目へ更新し、**品名欄にフォーカス**する。切替前の科目の明細は画面内モデルに保持する（DEC-164）。対象科目に明細がない場合は空一覧を表示する。
- 現在の明細フォームに**未反映の変更**があるときは、クリック／Enterによる切替要求の直前に、DEC-160の**「追加／更新して移動」「入力を破棄して移動」「編集に戻る」**を提示する。戻る／Escでは元の科目と入力値を保持し、移動しない。追加／更新の検証エラー時も切り替えない。**↑／↓で候補行を動かすだけでは確認を出さない**。単にフォーカスがある行と実際の表示対象科目を混同しない。
- WinUI 3の一覧部品が↑／↓で選択状態を変更する場合でも、**フォーカス移動と科目切替の確定を分離**して上記動作を満たす。標準コントロールを優先し、キー処理・フォーカス表示は実装時の受入試験で確認する。

**科目グループのメモ編集・削除（DEC-174・試行採用／UI未実装）**：旧Windows版の「科目・メモを指定して［更新］」方式から変更し、**左側の追加済み科目一覧の下部**に、現在表示中の科目グループの**［科目メモ］入力欄**と**［科目を削除］ボタン**を置く。右側の明細メモ・上部のレシートメモとは別の項目であり、科目マスタ自体は変更しない。

- **メモ編集**：現在の科目の`ledger_receipt_groups.memo`を直接編集する。科目メモ専用の［更新］ボタン／ダイアログは設けない。入力内容は画面内のレシート下書きに反映し、**レシート全体の［保存］で初めてAPIへ確定**する。別科目への切替後も編集済みメモを画面内で保持し、未保存変更としてDEC-163の離脱保護対象にする。
- **科目削除**：選択中の科目グループと**その科目に属する全明細・明細対象人物**をレシート画面内から削除する。実行前に**科目名と削除対象の明細件数**を明示し、確認を求める。キャンセル時は何も変更しない。確認後の削除も**レシート全体の［保存］までAPIへ反映しない**。レシートの他科目・明細は残す。
- **未反映の明細入力がある場合**：削除をそのまま実行せず、まず対象の明細入力を**追加／更新するか破棄するか**を利用者が明示するまで削除を止める。未反映の下書きは自動破棄しない。科目切替時の保護（DEC-160）とレシート離脱時の保護（DEC-163）は引き続き適用する。
- **試行採用**：旧版と操作が異なるため、実装後にメモの即時反映による誤操作、削除確認、キーボードでの到達性を検証し、必要なら再検討する。削除後の科目選択・フォーカスはDEC-175で確定する。部品の正確な寸法は後続で調整する。

**科目削除後の選択・フォーカス（DEC-175・確定／未実装）**：削除の確認後、左側の科目一覧を科目マスタの表示順（`display_order ASC, category_id ASC`）で並べ直し、**削除位置に次の科目があればその科目、なければ1つ前の科目**を自動選択する。削除によって科目が0件になった場合は選択なしとし、右側の明細一覧を空表示にする。

- **別の科目が自動選択された場合でもフォーカスは［科目を削除］ボタンのまま**とし、品名欄へ自動移動しない。ボタンに続けてEnterを押した場合にも、DEC-174の科目名・明細件数付き確認を**毎回**提示する。
- **科目が0件になった場合**は削除対象がないため［科目を削除］を無効にし、フォーカスを**［追加する科目］ComboBox**へ移す。削除確認をキャンセルした場合は、科目の選択・内容・フォーカスを変更しない。
- このフォーカス保持は**科目削除後だけの特例**。通常の科目クリック・Enterによる切替成功時、および科目追加後の品名欄へのフォーカス移動（DEC-172・173）は変更しない。

**配置の基本方針（DEC-166・確定／未実装）**：明細入力フォームを上、その直下に［追加／更新］等の操作と、選択中の科目の登録済み明細一覧を下に置く。旧Windows版のように、フォームと一覧は**同じ連続した入力領域として視覚的に一体化**させ、独立したカード・大きな囲み・過度な余白などで明確に区切らない。**機能上は別**で、フォームで入力・更新し、一覧は読み取り専用の確認・選択用とする。対象人物の左右配置はDEC-169に従い、具体的な入力欄の配置・フォーカス順はDEC-170で確定する。正確な寸法は後続で調整する。

**明細フォームの配置・フォーカス順（DEC-170・確定／未実装）**：標準幅では**左側を主な入力欄、右側を対象人物の常時表示チェックボックス一覧**とする（DEC-169）。左側は上から、まず**品名を横長1欄**、次に**単価／数量、単価値引／率値引、税率／費用区分**をそれぞれ左右2列で並べ、次に**発生区分**を置く。対象人物一覧の下端位置と左側の各欄の下端は必ずしもそろえず、**メモを左右の下に横長で置き、その下の右寄せに［追加／更新］**、さらに下に登録済み明細一覧を続ける（DEC-166）。人物一覧を下段へ移す狭幅レイアウトでも論理的なフォーカス順は変えない。

- **明細入力のフォーカス順**：**品名 → 単価 → 数量 → 単価値引 → 率値引 → 税率 → 費用区分 → 発生区分 → 対象人物一覧 → メモ → ［追加／更新］**。右側の人物一覧へは左側の全項目を終えてから移る。選択できない項目は飛ばし、表示位置が切り替わっても順序は維持する。
- `Enter`／`Shift+Enter`で前後の入力可能な欄へ移り、最後のメモ欄の`Enter`は［追加／更新］へ**フォーカス移動するだけ**で実行しない。ボタンにフォーカスした後の`Enter`はそのボタンを実行する。`Tab`／`Shift+Tab`は共通の標準操作に従う。
- 人物一覧内は**↑／↓で移動、Spaceで選択切替**、`Tab`／`Shift+Tab`で一覧の外へ（DEC-168）。IME変換中・`ComboBox`展開中のキー処理を優先する。`Alt+Enter`による明細追加・更新と`Ctrl+Enter`によるレシート保存（DEC-159）は従来どおりで、変更しない。
- **数量1、値引0、費用区分・発生区分の初期値、科目と取引日から補完する税率**はDEC-158等に従う。入力欄を逐一通らず、品名・単価など必要な値を入力して`Alt+Enter`で連続登録できる。対象人物の選択維持はDEC-161を維持する。具体的な列幅・余白・ブレークポイント・メモ欄の高さは実装前に調整する。

**一覧の表示範囲（DEC-164・確定／未実装）**：明細一覧は**選択中の科目グループに属する明細だけ**を表示する。科目を変更したときは現在の科目の明細一覧に切り替え、以前の科目の明細もレシートの画面内モデルに保持する。0件の科目は空一覧とする。各科目の参考額とレシート全体の合計は、一覧フィルターに影響されず**全科目のデータ**から算出する。未反映の明細入力がある状態で科目を切り替える場合は、DEC-160の確認を適用してから表示対象を変更する。明細の並び順は既存どおり科目グループ内で管理する。**科目欄は左側配置で確定（DEC-172）**。画面全体の具体的な寸法は引き続き調整対象。科目切替キー操作はDEC-173で確定。フォームと明細一覧の上下関係・視覚的一体化はDEC-166に従う。

**通常の新規入力の初期値**：数量は`1`、単価値引・率値引は`0`、支出科目の費用区分は`Variable`（収入科目なら`Excluded`のみ）、発生区分は`Irregular`。税率は**科目マスタの初期税区分＋取引日**から補完し、直前明細の実税率は自動継承しない（DEC-158）。対応税率履歴がなければ未選択とし、**非課税（保存値NULL）とはUI内部で区別**する。対象人物の初期選択と連続入力時の継承は、**DEC-161で確定**。

#### 対象人物の初期選択と連続入力（**DEC-161で確定・UI未実装**）

旧Windows版の`RegisterForm.vb`は、明細追加後の`ClearDetailControl(False)`でも科目変更時の`ClearDetailControl(True)`でも**人物リストの選択をクリアしない**。既存明細を編集開始した場合はその明細に保存された対象人物へ切り替わる。なおフォーム初期表示は`UserListBox.DataSource`を設定するのみで明示的な未選択処理がないため、**初期選択の実際の見え方を旧版と同一とは断定しない**。

| 場面 | 新版の確定ルール |
| --- | --- |
| **新規レシートの最初の通常明細** | **対象人物は0人（未選択）を明示的な初期状態**とする。ログイン本人・支払方法所有者・家計簿全員を推測して自動選択しない。0人も保存可能な業務値 |
| **通常明細の追加成功後** | **現在選択していた人物集合を入力フォームに保持**し、次の明細へ流用できるようにする。明細単位の選択内容が自動入力の基準となり、科目マスタには新たな人物初期値を持たせない |
| **別の科目グループに移動** | 対象人物の選択をそのまま維持し、連続入力を妨げない。ただし日付・人物の有効期間が不適合なら、保存前に修正を求める |
| **一覧の既存明細を編集** | 一覧で選択した時点で対象明細の保存済み人物集合をフォームに再現（DEC-176）。更新して新規入力へ戻るときも、そのときフォームで選択している集合を次の入力に残す |
| **明細複製** | 元明細の対象人物集合を引き継いで新規下書きを作る。税率引継ぎ（DEC-158）と同様、複製後は変更可能 |
| **既存レシート編集・レシート流用** | 保存済みの各明細の対象人物集合は維持。流用先の取引日に人物が有効かチェックし、無断で別の人物へ差し替えない |
| **0人の明細** | 入力可能・保存可能。0人を自動的にログイン本人や家計簿全員と解釈しない。集計時の人物按分・対象者照合は既存規則に従う |

**対象人物の表示方式（DEC-167・169・確定／未実装）：** 明細フォーム内に**常時表示される複数選択領域**を設ける。**標準幅では主な入力欄の右側**に配置し、幅が不足する場合に限って**入力欄の下側**へ移す。どちらも対象人物を常時見える領域とし、選択のためにドロップダウンやポップアップを開く操作を必須としない。人物欄を下側へ移しても、明細入力フォーム全体は登録済み明細一覧の上に置く（DEC-166）。0人（未選択）も明確に扱う。切替幅・領域内スクロール・高さ・チェック項目の列数は実装前に調整する。

**対象人物の選択操作（DEC-168・確定／未実装）：** 人物ごとにチェックボックスを常時表示し、クリックで個別に選択・解除する。**キーボードでは↑／↓で人物間を移動、Spaceで現在の人物のチェックを切り替え、Tab／Shift+Tabで人物選択領域から次／前の入力欄へ移動**する。Ctrlキーを押しながら複数人を選択する方式は採用しない。標準WinUI 3コントロールを優先し、選択中の人物集合と単なるフォーカス・行選択を区別する。0人選択を許容し、対象人数が多い場合は領域内をスクロールできるようにする。

**未決定のUI細部：** チェック項目の表示列数・高さ、人数0人であることの明細一覧表示。**人物の選択保持は入力支援だけ**で、他の明細の保存済み人物を一括更新しない。選択を自動で戻すことによる入力消失を避け、別明細を編集開始する場合はDEC-160の下書き切替確認を先に適用する。

**キーボード操作の基本契約（DEC-159）：**

| 入力・操作 | 動作 |
| --- | --- |
| `Enter`／`Shift+Enter` | 共通[入力契約](59-input-controls-design.md#enterキーによるフォーカス移動確定単一行のwinui入力へ適用済み)に従い、次／前の入力可能な欄へ。初期値のままでよい欄は**Alt+Enterで追加できるため逐一通過不要** |
| `Tab`／`Shift+Tab` | WinUI標準フォーカス移動。マウスを使わず科目選択・フォーム・一覧へ到達できるようにする |
| **`Alt+Enter`** | **編集中の明細だけを追加／更新**する画面固有ショートカット。フォームの［追加］／［更新］と同じ入力検証・金額範囲検査を実行。**レシート全体の保存はしない** |
| **`Ctrl+Enter`** | 共通仕様どおり**レシート全体を保存**。明細フォームに**未反映の変更がある場合は保存を停止**し、先に［追加／更新］か［変更を破棄］を行うよう案内する（DEC-160の暫定ルール）。未確定明細の自動追加や自動破棄はしない |
| 明細一覧で`↑`／`↓` | **選択行を変え、その明細を即座にフォームへ読み込む**（DEC-176）。未反映の入力変更があれば切替前にDEC-160の3択確認を適用する |
| 明細一覧で`Enter` | **編集開始のための追加操作は不要**。選択済み明細があれば品名欄へフォーカスを移す補助操作として扱う。実装時に標準ListViewとの競合を確認する |
| IME変換中・ComboBox展開中 | 変換・候補の確定を優先。**そのキー入力で追加・更新・レシート保存を実行しない** |

**連続入力**：品名を入力→単価を入力→必要な数量・値引・税率等だけ変更→`Alt+Enter`。明細追加が成功したら一覧に反映して新規入力状態へ戻し、**品名欄にフォーカス**する。品名・単価は空欄に戻し、数量・値引・区分・税率は前記の新規初期値を適用。対象人物は**DEC-161に従い**新規レシートの最初の明細は未選択、明細追加・更新後や科目切替後は選択を引き継ぐ。エラー時は明細を追加・更新せず、**入力値とフォーカス位置を保持して当該欄の近くにエラー**を表示する。

**明細一覧のワンステップ編集と複製（DEC-176・確定／未実装）**：旧Windows版に近づけ、**選択中の科目の明細一覧で行を1回クリックした時点**で、当該明細のすべての値（対象人物・実税率を含む）を上のフォームへ読み込み、**［追加］を［更新］へ切り替える**。一覧の↑／↓キーによる選択変更でも同じ。追加の［編集］ボタンや、編集開始のためのEnter／ダブルクリックは要求しない。これは読み取り専用の一覧セルを編集する意味ではなく、編集先は従来どおりフォーム（DEC-159）。

- **［流用］による追加モードへの切替（DEC-177）**：既存明細が選択されているときだけ［流用］ボタンを有効にする。押すと**現在のフォームの全入力値を保持**し、元明細との関連付けと一覧選択を解除してボタン表示を［更新］から［追加］に切り替える。**この時点では明細を追加せず、元明細も変更しない**。その後の［追加］で別明細を新規登録する。複製された下書きは実税率・区分・対象人物・メモなどの値を維持し、利用者が追加前に編集できる。標準ListViewで保証されない空白クリック／Escによる解除を必須操作とせず、［流用］をマウス・キーボード共通の明示操作とする。標準の選択解除操作を利用する場合もフォームの値は保持し、同じ追加モードへ移る。
- **変更中の別明細選択**：現在のフォームに未反映の変更がある場合に限り、別行のクリック／↑／↓による選択変更の確定前にDEC-160の3択を提示する。選択変更の取り消しでは元の選択とフォームを保持する。未変更であれば確認なしで1操作で切り替える。**［流用］や標準操作による選択解除はフォーム値を消さないため、この切替確認の対象にせず**、未保存値を保持して新規明細モードへ移す。
- **追加／更新成功後**は対象行の選択を解除し、新規入力用の初期値へ戻して品名欄にフォーカス（DEC-159・161）。一覧で同じ行を再クリックしても入力し直さない。［編集］［複製］ボタンは置かず、**流用モード切替には［流用］を置く（DEC-177）**。連続編集時のダイアログ頻度は実装後に確認する。

**編集・取消（DEC-176・177）**：一覧で既存明細を**選択した時点でフォームに読み込み、［更新］モード**にする。**［流用］を押すと入力値を残して選択を解除し、［追加］モード**へ切り替える。［流用］では登録せず、続けて［追加］で新しい明細を作る。標準の選択解除操作でも同じ状態へ移る。追加／更新でレシート画面内モデルへ反映し、レシート自体は［保存］までAPIへ送らない。未反映の編集下書きがあるときの**別明細選択・科目切替**は以下の**暫定採用方式（DEC-160）**で保護する。

**明細一覧の削除操作（DEC-178・確定／未実装）**：**［削除］ボタンで選択中の明細1件**とその対象人物関連付けを、レシート画面内の編集モデルから削除する。**確認ダイアログは表示しない**。削除対象の明細にフォームの**未反映編集があっても、削除操作そのものを優先し、その下書きも確認なしに破棄**する。［削除］は対象明細が選択されているときだけ有効。別明細の選択・科目切替で下書きが上書きされる場合に使うDEC-160の3択確認とは区別する。

- 削除後は、一覧の表示順で**削除位置の次の明細があればその明細を、なければ直前の明細を自動選択**する。新たに選択した明細はDEC-176に従いフォームへ読み込んで［更新］モードにする。この自動選択に伴うDEC-160の確認は出さない。
- **別明細が残っている場合、フォーカスは［削除］ボタンに保持**する。連続削除のクリック・Enterでは、その時点の選択明細1件を毎回削除する。**0件になった場合**は選択を解除し、フォームを通常の新規入力初期値へ戻して［追加］モードとし、無効になった［削除］から品名欄へフォーカスを移す。
- 削除は**レシート全体を保存するまでAPIには反映しない**。画面離脱時はDEC-163で未保存変更を保護し、レシート保存前に破棄した場合はサーバー保存済みの明細を維持する。削除前のフォーム下書きそのものは復元しない。

#### 明細の未反映入力と選択切替（**DEC-160 暫定採用・UI未実装**）

明細の［追加／更新］は**画面内のレシート編集モデルへの反映**であって、APIへの保存ではない。次の区別を保つ。

- **明細フォームの下書き**：新規明細で入力中、または既存明細をフォームで変更したが［更新］していない状態。
- **レシート全体の未保存変更**：明細を追加／更新／削除して画面内モデルに反映済みだが、［レシート保存］していない状態。この状態は、明細・科目の切替時には保持する。**今回の明細下書き破棄の対象には含めない**。

一覧の**単一クリック・上下キーで別明細を選ぶと、選択と同時にフォームへ対象明細を読み込む（DEC-176）**。下書きが初期状態・編集元と同内容なら確認なく切り替える。既存値からの変更や新規入力の品名・単価等の実入力がある場合は、切替確定前に3択で保護する。**［流用］／選択解除なら入力値を保持して追加モードへ移行**するため、下書きを破棄せず確認不要。科目によって自動セットされた税率・数量1等、**自動初期値だけで下書きが変更済みとは判定しない**。

| 操作・状態 | 切替動作（暫定採用） |
| --- | --- |
| 一覧で別明細を選択（クリック／上下キー） | **対象の明細を即フォームへ読み込み［更新］に切替**。未反映の変更があれば下記3択の確認を先に行う（DEC-176） |
| 下書き未変更で、別明細を選択／別科目へ切替 | **即時切替**。確認は出さず、別明細選択ならその時点でフォームへ対象を読み込む |
| 下書き変更済みで、別明細を選択／別科目へ切替 | 切替を一旦保留し、**標準`ContentDialog`で「追加／更新して移動」「入力を破棄して移動」「編集に戻る」**の3択を出す。**既定・Escは「編集に戻る」**。クリック／↑／↓の選択変更も対象。単なる同じ行の再選択は対象外 |
| 「追加／更新して移動」 | 今編集中の**元科目の明細**に［追加／更新］と同じ検証・金額上限確認をして画面内モデルへ反映。成功したときだけ選択先へ移動。失敗なら**選択は変えず**ダイアログを閉じ、下書きと入力エラーを保持 |
| 「入力を破棄して移動」 | **現在のフォーム下書きだけ**破棄して選択先へ移動。以前に［追加／更新］した別の明細や、レシート全体の未保存変更は残す |
| 「編集に戻る」／Esc | 選択元・入力値・編集モードを保持し、移動しない。入力フォーカスをフォームへ戻す |
| ［流用］（または標準操作による一覧選択解除） | **現在のフォーム値を保持**し、更新対象との関連付けだけ解除して［追加］へ切替。**確認不要**（未反映値を破棄しない）。元明細は未変更で、続けて［追加］すれば別明細を作れる。［流用］押下だけでは追加しない（DEC-177） |
| ［削除］（選択明細を削除） | **確認不要**。選択明細の未反映編集も含めて削除・破棄する明示的な操作であり、DEC-160の切替確認は適用しない（DEC-178） |
| 選択中の同じ明細を再選択 | 下書きを読み直して上書きしない。確認も不要 |
| `Alt+Enter` | 既存の明細追加／更新を実行し、成功時に新規入力状態へ戻る。ダイアログは出さない |
| `Ctrl+Enter`（レシート保存） | 下書きに未反映変更があれば**明細の追加／更新を要求して保存を止める**。レシート保存で下書きを自動反映しない |

- **編集対象・科目の切替は保留中に確定しない**。選択変更イベントの発火だけで値を上書きせず、確認後に実際の選択行とフォームの編集対象を確定する。Esc／「編集に戻る」では元の選択行・下書きを保持する。選択イベントの再入や意図しないフォーム初期化に注意する。
- 下書きが不正でも「編集に戻る」「入力を破棄して移動」は選べる。「追加／更新して移動」だけは検証に通る必要がある。メッセージを連続表示するより、失敗した欄の近くにエラーを示す。
- **画面・家計簿を離れる場合は別問題**：レシート全体の未保存変更も含む離脱確認は**DEC-163**で確定。ここでの3択はあくまで明細内の切替用で、レシート離脱の「保存／破棄／戻る」と区別する。認証失効からの復元詳細は後続で確認する。
- **旧Windows版との対比（現行コード確認済み）**：旧`RegisterForm.vb`の`DetailListView_SelectedIndexChanged`では選択に応じて入力欄を直ちに書き換え、選択解除時はフォームの値を残して［追加］へ戻るため複製可能。**下書き破棄の確認は行わない**。新版はこのワンステップ編集と複製操作を継承しつつ、別明細への上書きと科目切替時のみ未反映変更をDEC-160で保護する。
- **暫定採用**のため、入力速度・ダイアログ頻度をWinUIの受入試験で確認し、煩雑であれば再検討する。正常移動・更新失敗・破棄・Esc・IME変換中・キーボードのみ・選択変更の再入を試験ケースに含める。

#### レシート画面の離脱と未保存データ保護（**DEC-163で3択確定・UI未実装**）

**対象:** レシート画面で新規入力・既存編集・流用登録をしているときの「他機能への画面移動」「家計簿切替」「ログアウト」「別レシート表示」「通常のウィンドウ終了」。**レシート編集モデルの未保存変更**（親項目・グループ・追加済み明細・削除/並び替え等）と、**明細フォームの未反映下書き**の両方を保護する。明細/科目内の編集切替（DEC-160）とは別の境界。

| 操作・状態 | 新版の確定動作（DEC-163） |
| --- | --- |
| 初期状態・保存済み内容からの変更なし | 確認なしで画面移動・家計簿切替・ログアウト・通常終了を進める。フォームの自動初期値だけでは変更済みとみなさない |
| **未保存変更あり**で他機能/別家計簿/別レシートへ移動・ログアウト・通常終了 | **処理を保留**して標準`ContentDialog`で「**保存して移動**」「**破棄して移動**」「**編集に戻る**」を提示。既定/Esc/閉じる操作は**編集に戻る**。移動先・ログアウト・終了を先に実行しない |
| 「保存して移動」 | 明細下書きに未反映の実入力がなければ通常の**レシート全体保存**と同じ検証・権限・楽観的更新版照合・API応答確認を行い、**保存成功後にだけ離脱**。エラー・競合・通信障害なら離脱せず入力を維持。**下書きの自動追加/更新はしない** |
| 明細下書きに未反映変更がある状態で「保存して移動」 | 保存と離脱を止め、「明細を［追加／更新］するか、入力を明示的に破棄してください」と案内。明細の入力欄に戻す。**未反映明細を勝手に捨てたり、レシート全体へ取り込んだりしない**（DEC-160と一致） |
| 「破棄して移動」 | **現在開いているレシートの未反映下書き・未保存変更をともに破棄**して初めて離脱。既存レシートの**サーバー保存済みデータには影響しない**。明細内切替の「下書きだけ破棄」と混同しない |
| 「編集に戻る」／Esc | 移動・ログアウト・終了を中止。フォーム、親項目、科目/明細、未保存入力、元の更新版と編集対象を保持 |
| 既に保存要求を送信中 | 完了結果が判明するまで二重保存・重複終了操作を止める。失敗した場合も入力を保持し、失敗を理由に勝手に「破棄して移動」を選ばない |

- **通常の画面移動のみを守る仕組み**で、**アプリの強制終了・OS終了・電源断・クラッシュ時の入力復元は保証しない**。本決定ではローカルディスクへの自動下書き保存・サーバーへの自動保存・復旧用DBの追加は採用しない。通常のウィンドウ終了でキャンセル可能か、閉じる際の非同期API保存を安全に待てるかは**WinUI 3実装時に検証**する。
- **通信障害**は認証失効と区別。通信エラーでは勝手にログイン画面へ戻したり、入力を破棄したりしない。再試行は既存Client/APIの作成`requestId`・更新版・競合契約に従い、無条件の自動再送はしない。
- **認証失効（利用者が意図したログアウトとは別・復元詳細は別途確認）**：既存の人物等と同じく、編集中レシート全体・明細フォーム下書き・元の家計簿・元の認証アカウント・API接続先・元の更新版/作成`requestId`を**アプリのメモリ内だけで一時保持**する案。**同じ接続先・同じ認証アカウントで再ログイン**できた場合のみ、家計簿参加/権限/参照先の現在状態を再検証して編集画面を復元する案。**自動保存しない**。権限喪失・対象削除・変更競合なら下書きを保持して書込を停止し、説明と明示操作を用意する。異なるアカウント/接続先へは入力を持ち越さない。実装時はアプリ終了でメモリが失われることを明示する。
- **ログアウト・接続先変更は利用者が意図して開始する操作**なので、DEC-163の離脱確認の対象。**認証失効に伴う自動ログイン遷移**では保存確認ダイアログを挟まず、メモリ下書きの復帰要件は既存画面との整合を含めて後続で確定する。
- **未保存判定**：サーバー取得時点／最後の保存成功時点のレシート値と、現在のレシート編集モデル＋明細フォーム下書きを比較する。入力欄を触っただけで最終値が元に戻った場合、不要な確認を出さない。税込税抜・周期・店名・支払方法・対象者などを含み、表示だけの状態変更は対象外。新規レシートの自動初期値だけで変更済みとはしない。
- **受入観点（未実施）**：新規/既存/流用、明細未反映あり/なし、画面移動/家計簿切替/ログアウト/通常終了、保存成功/検証失敗/409/ネットワーク失敗、破棄/Esc、認証失効→同一/別アカウント復帰、IME変換中、ショートカット、強制終了の非保証を分けて確認する。

**日付・税率の変更**：取引日が変わったら、一覧の全明細の率を新日付の候補に照合して維持/要再選択を判定する。無効な税率には一覧の明細とフォーム双方にエラーを表示し、利用者の再選択までレシート保存不可。既存レシート編集・流用でも保存済みの実税率は無断変更しない。非課税と課税0%は区別する。

**金額表示**：一覧の明細参考額は明細単位で算出し、科目グループの参考額はグループ内税率別合算（DEC-156）。**会計上のレシート合計は別に表示**し、参考額の単純合算で置き換えない。表示列・幅・スクロール・IME・100～200% DPIの具体的な受入確認はWinUI実装時に行う。

### 複数税率の計算粒度（グループ参考額：DEC-156、グループ別人物按分：DEC-157）

既存の[計算契約](12-calculation-contract.md#2-合計と内訳の丸め粒度の違い)にある**会計合計と参考額の違いは維持する**。税率を明細へ移すことで、同じ科目のグループ内に複数税率が混在する。**グループ参考額はグループ内で税率別に合算・端数処理する方式に確定**した（DEC-156）。**人物ごとのグループ参考額に限り**明細別按分を先に行ってからグループ内の税率別に集計する方式を確定（DEC-157）。人物別のレシート全体・月次等の総額に同じ集約単位を適用するとは決めていない。画面表示の詳細は提案段階。

| 表示・用途 | 合算・丸めの境界 |
| --- | --- |
| **レシート合計**・符号別収支 | 科目・グループをまたいで、レシートの**課税税率ごとに**明細の値引後金額を合算して税端数処理。非課税は別に加算。従来の境界を維持 |
| **グループ参考額（確定）** | 当該グループ内の課税明細を**税率ごとに合算し、それぞれ親レシートの税込/税抜・端数方式で税計算して合計**。非課税明細の値引後金額は税を加えず合算する。**グループごとに独立**し、異なるグループ間で丸め前の値を統合しない |
| **明細参考額** | 当該明細だけで値引・税端数処理。別明細とは合算しない |
| **人物ごとのグループ参考額（按分・集計単位は確定）** | 対象者条件で採用した**明細ごとに**値引後金額を対象人数で割り、按分値を**当該グループ内の税率別**に合算してから税計算・端数処理する。対象者0人は按分対象外（従来どおり）。**負額・小数按分の正確な最終丸め手順は実装前に固定例で確認** |
| **人物別のレシート全体・期間合計等（未確定）** | 上記のグループ参考額を単純に足した値を正本とはしない。グループ境界を越える集約方法と表示上の定義は別途決める |

**確定仕様の計算例**。税抜・`floor` の例：同じ「食費」グループに課税10%・19円の明細2件と課税8%・19円の明細1件がある場合（値引なし）。

- グループ参考額：10%分 `Floor((19+19)×1.10)=41円` ＋ 8%分 `Floor(19×1.08)=20円` → **61円**
- 明細参考額の合計：10%分 `20+20` ＋ 8%分 `20` → **60円**
- このレシートに別の科目で課税10%・19円を1件追加すると、**レシート合計は82円**（10%分3件を合算した62円＋8%分20円）。科目別参考額の合計は81円。参考額を足して会計合計を上書きしない。

人物ごとの**グループ参考額**は、従来の「対象人物の照合→明細金額÷対象人数→グループ単位で税・丸め」を引き継ぎ、混合税率時はそのグループの中でさらに税率別に按分額を合算する（DEC-157）。対象者0人は人数割りしない（按分時は算入しない）。対象者集合の一致/部分一致条件は従来どおり。按分前に明細ごとに整数円へ切り捨てたり、全レシートでまとめてからグループへ割り当てたりしない。税込/税抜と端数方式は親レシートから参照する。**既存の`floor`/`half_up`の最終丸めと、複数税率混在時の小数値・負額の厳密な結果は回帰例で決める**。人物別のレシート全体・期間総額については本決定の対象外とする。

**UI表示は未確定**。グループ見出しに参考額を1つ置き、必要なら明細の税率列・税率別小計を確認できるようにする案。税率別にグループを分け直したり、DBにグループ合計・税率別合計の保存列を追加したりはしない。集計時に算出する。

## 5. `ledger_receipt_detail_people`（対象人物）

| 列 | SQLite型・NULL | 内容 |
| --- | --- | --- |
| `ledger_id` | TEXT NOT NULL | 家計簿ID、PKの一部 |
| `detail_id` | TEXT NOT NULL | 同一家計簿明細へのFK、PKの一部 |
| `person_id` | TEXT NOT NULL | 同一家計簿人物へのFK、PKの一部 |

- 明細に紐づく人物は**0人以上**。同じ人物の重複をPKで防ぐ。人物は家計簿の人物IDであり、認証ユーザーIDではない。
- 人別の金額按分は別の金額列で保持せず、既存の参考額計算を利用する。人数で割った端数の扱いは[計算仕様](12-calculation-contract.md)を維持する。
- 人物の削除は参照が残る間RESTRICT。作成/編集/削除は親レシートのトランザクションで実施する。

## 6. FK・保存・読取の原則

- 必須の複合FK：グループ→レシート、グループ→科目、明細→グループ、明細対象者→明細/人物、親→支払方法。いずれも`ledger_id`を含む。必要な親の`(ledger_id,id)`キーと子FK列索引を用意する。
- 基本的な`CHECK`：各列の列挙値、Int32範囲、数量正値、周期2列のNULL一致、表示順非負。Decimalの解析、**明細ごとの税率と取引日の適合性**、科目別費用区分、周期に対応する定期明細の有無、取引日に有効な科目・支払方法・人物などの条件はAPIの保存トランザクションで検証する。
- 作成は既存`operation_requests`で`receipt.create`を識別して再送保護する案（再送記録の保持方式は取引件数増加も考慮して再確認）。修正/削除は親`revision`を必須とし、子階層まで**まとめて**保存・置換する案。成功時に新`revision`、`updated_by_auth_user_id`、`updated_at_utc`を更新する。
- 操作権限：Adminは全レシート、Viewerは閲覧のみ、Editorは対応人物が所有する支払方法のレシートを操作。**支払方法を変更する編集では旧・新の両方の所有者を照合**。監査の作成者は権限制御に使わない。書込トランザクション中にも最新の参加・権限を照合する。
- レシート削除は子の対応人物→明細→グループ→親の順に実施し、失敗時は全取消。読込だけでは保存済み合計・税率・明細・履歴を補正しない。
- 同じ数値税率の課税**明細**は科目やグループが異なってもレシート全体で合算し税端数処理。非課税は別集計し課税0%と区別する。グループ/明細/人別の参考額が親合計と1円以上ずれる場合があることを保持する。

## 7. 実装前に残る確認事項

| 論点 | 設計案・現状 | 確認が必要な理由 |
| --- | --- | --- |
| 取引日時の詳細書式 | **時刻まで保存すると確定**。`transaction_at TEXT NOT NULL` | ローカル日時を維持し、具体的なISO系文字列形式、小数秒の精度、API日時表現を後続で確定 |
| 旧版の`total`がNULLのデータ | 新DBの`total_amount`はINTEGER NOT NULLと確定 | 実データを調査して移行前に個別対応。NULLを自動的に0へ置き換えない |
| 主キーとID一意性 | **全4表とも`ledger_id`を含む複合PKで確定。レシート・グループ・明細のID単独UNIQUEは設けない** | 既存マスタと同じキー設計。家計簿間の参照禁止は複合FKで保護する |
| 監査ユーザーと削除 | **作成者・更新者とも認証アカウントへのRESTRICT FKで確定** | アカウントの物理削除は未実装。将来の退会・削除機能は履歴保持方針と合わせて別途設計 |
| 混合税率グループの参考額・人物按分 | **グループ参考額の計算はDEC-156、人物ごとのグループ参考額の按分→グループ内税率別集計はDEC-157で確定**。最終丸め細部・UIは未確定 | 0～3人、正負、税率混在、税込/税抜、`floor`/`half_up`の固定例で按分後の厳密な丸めを検証 |
| 人物別のレシート全体・期間総額 | **未確定**。グループ参考額の単純合算を正本にしない | 目的ごとの集約境界と端数・会計合計との関係を後続設計で判断 |
| 有効期間と再編集 | **レシート保存時は変更箇所を問わず全明細の税率を取引日の現行履歴に照合**し、不一致なら保存拒否。保存済みの税率は自動補正しない | 科目・支払方法・人物の有効期間が後変更された場合の再編集条件は後続設計 |
| レシートのAPI形 | POST/PATCH/DELETEで子階層を含む一括保存を提案 | 部分更新や子ID保持、競合応答、再送ハッシュの具体形は別途API仕様で確定 |
| 旧版データ引継ぎ | **実データ検査まで保留** | 旧グループの税率と旧明細の課税対象フラグから新明細の税率を対応付け、同科目の旧グループを統合する必要がある。移行方法は別途確定 |
