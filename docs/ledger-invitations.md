## 家計簿への招待の発行・一覧・取消

### WinUI 3の招待管理画面

家計簿管理者が「管理・設定 → 参加者管理」の参加者一覧の［招待］から、同じWindowの「管理・設定」右ペインにある**専用画面**へ移る。参加者の編集用`ContentDialog`とは別とし、［戻る］で参加者一覧に戻る。招待管理の入口は参加者一覧に集約する。

- ［新しい招待リンクを発行］は確認ダイアログなしで即時実行する。発行中はボタンを無効化して二重送信を防ぎ、成功応答の有効リンク一覧を表示する。
- 発行が通信失敗した場合は、同じ作成`requestId`を維持して利用者が再試行できるようにする。再送の結果は[招待API](specs/api/features/invitations.md#7-整合性再送)に従う。別の新規発行操作では新しい`requestId`を使う。
- 有効リンク一覧には**有効期限・［コピー］・［取消］**を表示し、**新しく発行したものを上**にする（発行日時降順、同日時は招待ID昇順）。表示対象は[APIの有効招待一覧](specs/api/features/invitations.md#管理3操作の共通応答)に従い、表示時・コピー時にも期限を確認する。有効な既存リンクは再コピーできる。
- ［コピー］はその行の既存招待URLをクリップボードへコピーする。［取消］は対象リンクの確認用`ContentDialog`を出し、［取消する］の明示操作で実行する。成功時は取消応答の更新後一覧を表示する。失敗時は理由を表示し、勝手に取消を繰り返さない。
- 発行・取消の成功応答に含まれる更新後一覧を使用し、成功直後の一覧取得を重ねない。招待URL・トークンは通常ログに出さない。
- 管理APIの403・404では[共通画面処理](ledger-person-conflicts.md#権限喪失削除済み結果への再送)に従い家計簿APIから現在の参加・権限を再取得する。発行・取消の404でAdmin権限が残る場合は有効招待一覧を再取得し、取消対象が不在なら選択を解除して通知し、同じ対象への取消を停止する。発行再送の結果が不在ならその旨を通知し、同じ要求IDによる再発行を繰り返さない。取得失敗・権限喪失時は操作を停止する。自動再発行・自動取消は行わない。

発行画面ではアカウントを指定せず、新しいリンクを発行する。

### ブラウザーへの招待情報の受け渡し

ブラウザーのトークン受け渡しは以下のとおり。通常のログインでは最後に開いた家計簿等へ進み、招待経由ではログイン後の参加確認を優先する。

1. [招待API](specs/api/features/invitations.md)の招待URLから、`#token=`以降のトークンをブラウザーのJavaScriptが読み取る。保存・通信に先立ち、`history.replaceState`で表示中のURLからフラグメントを除く。
2. トークンをJavaScriptの状態として保持し、同一タブの`sessionStorage`へ一時保存する。ページ再読み込みやログインへの移動を挟んでも同じタブで復元する。恒久的な`localStorage`には保存しない。結果不明の参加要求が残っている場合は、別の招待リンクで一時保存の記録を上書きしない。
3. 未ログインならログインへ進み、成功後は招待の参加確認を表示する。`/auth/login?returnUrl=/ledger-invitation`で、ログイン画面へ「成功後は招待ページを表示する」と伝える（DEC-099）。ログイン画面の戻り先許可へこの固定パスだけを追加し、既存の`/connect/authorize`への戻り方を維持する。戻り先URLへトークンを埋め込まない。
4. 招待ページで一時保存した同じトークンをpreview・acceptそれぞれのJSON本文の`token`として送信する。［参加する］の明示操作でacceptを実行する。APIの認可・有効性検証は[API正本](specs/api/features/invitations.md)に従う。
5. 通常の招待では参加成功・既に参加済み・使用済み等で利用不可・本人の［戻る］で一時保存を消す。通信障害やログイン待ちの間は再試行できるよう残す。参加結果が不明な場合は後述の確認・復旧の保持・削除条件を優先する。一時保存を利用できない場合は入力や秘密値をログへ出さず案内し、参加処理を進めない。

フラグメントは通常のページ取得のHTTP要求へ送られないため、招待トークンをリクエストURLの通常ログへ載せずに受け渡せる。APIへのPOST本文もログへ出さない既定方針は維持する。保存方式は[招待DB](ledger-core-schema.md#ledger-invitations-storage)を参照する。

## 家計簿の参加確認・結果

APIの状態・応答は[招待API](specs/api/features/invitations.md)に従う。

リンクを受け取って開く・参加する操作と使用済み等の表示はブラウザー側で扱い、Windows専用の参加画面やリンク受信は追加しない。Windowsの参加者一覧から開く招待発行・管理の画面とは区別する。

未参加者が家計簿招待リンクを開くと、参加先の家計簿名を使った「『家計簿名』に参加しますか？」と「参加する」「戻る」を表示する。アカウントの表示名とは区別する。招待を開いただけでは参加せず、「参加する」で確定する。

参加確認画面の通常の戻り先は、Web家計簿画面が未実装の間は暫定的に既存の`/auth/login`とする。ログイン済みは［ログイン情報に戻る］、未ログインは［ログイン画面に戻る］を表示し、通常の戻る操作では一時情報を削除する。Web家計簿画面の実装時に遷移先を再検討する。結果不明の記録がない通常の招待で無効・期限切れ・使用済み・取消済みと判明した場合は、戻るを含む操作ボタンを表示しない。

参加成功後は、Webのレシート一覧が未実装の間、**招待ページ内に**「家計簿に参加しました。Windows版で家計簿を開いてください。」と表示する。別の完了画面や未実装のレシート一覧には遷移せず、メッセージを自動で消さない（DEC-117）。Webのレシート一覧が利用可能になった段階で、遷移先は改めて検討する。有効なリンクを開いたアカウントが既に参加済みなら、その時点で「この家計簿には参加済みです。」と表示する（DEC-084）。［参加する］は表示しない。

**参加確定の結果不明時の確認・復旧**

- ［参加する］を押した時点で、previewで確認した`ledgerId`と現在の`/auth/me`の`authUserId`を、招待トークンと同じタブの`sessionStorage`に紐付けて保持する。トークン・アカウントIDをURL、ログ、`localStorage`へ出さない。初回の参加要求は同一アカウントのpreviewが取得できている場合だけ送る。
- `POST /ledger-invitations/accept`の応答喪失・タイムアウト等で確定結果が分からなければ、「参加できたか確認できませんでした。」と表示し、［参加状況を確認］を提供する。**自動でacceptを再送しない**。結果不明の記録は同じタブの再読み込み後も維持する。未完了記録があるときは、招待の再previewや再参加より先に結果確認の導線を示す。
- ［参加状況を確認］では、`/auth/me`でログイン済みの同じ`authUserId`を確認したうえで、保存した`ledgerId`へ`GET /ledgers/{ledgerId}`を送る。現在も参加している応答（200）なら参加成功と判断し、通常の参加完了メッセージを表示してトークン・結果不明の記録を消す。別アカウントへは記録を引き継がず、元の操作の成功と判定しない。
- 家計簿個別GETが404の場合、トークンを保持していれば、その時点では参加していないと案内し、［参加状況を再確認］と利用者の明示操作による［参加する］を提供する。元の処理が後から確定する可能性があるため、この段階では参加失敗として終了しない。受領可能かは毎回APIが判定する。
- acceptの業務エラー `invitation_used`・`invitation_expired`・`invitation_revoked`（409）または `invitation_invalid`（404）によって招待が利用不能と確定した場合は、トークンだけをJavaScriptの状態・`sessionStorage`の両方から削除する。結果確認用の `ledgerId`・`authUserId` は保持し、以後は［参加状況を確認］または［参加状況を再確認］だけで同一アカウントの現在の参加を確認する。**利用不能の確定後に実行した家計簿個別GETが200なら参加成功、404なら参加失敗として終了する。** 404では「家計簿に参加できませんでした。」と表示し、操作ボタンを表示せず、残りの一時保存も削除する。過去のacceptの処理結果を特定するのではなく、現在の参加状態で判定する。通信障害等で確認できない間はトークンのない結果不明記録を保持し、同じタブの再読み込み・ログインを挟んで復元する。確認が終わるまでacceptの再送・別リンクによる上書きを行わない。認証失効・通信障害等、招待の利用不能が確定しない場合はトークンも保持する。
- 結果不明時は通常の戻るを表示せず、別アカウントや認証失効では［元のアカウントでログインし直す］から固定の`/auth/login?returnUrl=/ledger-invitation`へ進める。既存画面で利用者が明示的にログアウト・再ログインし、元の本人に一致するときだけ明示確認を再開する。画面移動・ログイン状態の切替では結果不明の記録を消去せず、自動ログアウトしない。
- 状態確認の通信障害・503等は結果不明として維持し、勝手に再確認・再参加を繰り返さない。401ではログインが必要と案内し、再ログイン後も元の本人と一致する場合に限って利用者の明示操作で確認を再開する。保存領域が使えない／識別情報が欠ける場合は成功と推定せず、秘密情報を表示せずに案内する。
- 参加成功または前述の利用不能確定後の参加失敗で結果確認を終了し、一時保存をすべて削除する。確認終了専用のボタンは設けない。元の結果不明記録がない通常の招待での使用済み・期限切れ・取消済みの扱いは既存仕様を維持する。参加状況の照会には既存の家計簿個別GETを使用する。

## 招待リンクの共通エラー画面

アカウント登録・家計簿参加の両方で、リンクに問題がある場合は同じ形式のエラー画面を表示する。

| 状態 | 表示するメッセージ |
| --- | --- |
| 無効・取消済み | 無効な招待です。 |
| 期限切れ | 招待の期限が切れています。 |
| 使用済み（家計簿参加） | この招待リンクは使用済みです。 |

通常の招待エラー画面には「戻る」などの操作ボタンを置かない。家計簿参加の結果不明時は前述の確認・復旧を優先する。アカウント登録の招待と家計簿参加の招待は別々のまま扱い、有効期間等の条件まで共通化しない。
