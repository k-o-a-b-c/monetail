## 家計簿への招待の発行・一覧・取消（API実装／画面未実装）

家計簿管理者が「管理・設定 → 参加者管理 → 参加者一覧の［招待］ → 招待画面」から操作する。家計簿招待の入口は参加者一覧だけとし、「管理・設定」の直下には設けない（DEC-071）。招待画面にはリンクを追加するボタンと有効な招待リンクの一覧を表示し、同じ画面で各リンクを取り消せるようにする。

- 有効期限は発行から7日間。アカウント登録用の10分とは別の条件とする。
- 1リンクで新たに参加できるのは1名。未参加者は［参加する］を押して参加に成功した時だけ使用済みにし、参加失敗や画面を開く・閉じるだけでは消費しない。既存参加者には開いた時点で参加済みと表示し、［参加する］を表示せず、リンクを消費・失効させない（DEC-084。DEC-083の既存参加者が押した時の失効を変更）。
- 有効なリンクの一覧には、未使用・期限内・未取消のものを表示する。
- 招待を受けて参加したアカウントの初期役割は、既定の方針どおり閲覧者とする。

**招待先・再コピー・再発行（利用者確認済み・未実装）**

- 招待先のアカウントは発行時に固定せず、リンクを受け取った登録済みアカウントがログインして参加する（DEC-094）。発行画面に全体のアカウント検索・指定を追加しない。アカウント登録と家計簿参加を別の招待にする既定方針は維持する。
- 有効リンク一覧から、既存の同じ招待リンクを再表示・コピーできる（DEC-094）。家計簿招待のトークンは暗号化せず保存し、同じリンクの復元に使う（DEC-095）。
- 再発行専用の操作は追加せず、古いリンクの取消と新しいリンクの発行で対応する（DEC-094）。新しいリンクを発行しただけで他の有効リンクを一律に無効にしない。

同じリンクによる同時参加でも1人しか新たに参加できない既定方針は維持する。参加者追加と招待の使用済み化を同じトランザクションで確定し、他のアカウントは使用済みの案内となる構成を検討する。これは既存参加者がリンクを消費しないDEC-084とは区別する。

**家計簿招待API・保存方式（API／DB実装済み）**

再コピー可能というDEC-094を満たすため、家計簿招待用の`ledger_invitations`を設ける（DEC-097）。トークンを暗号化せず保存することは確認済み（DEC-095）。保存項目は、招待ID（API生成UUID）・家計簿ID・トークン・発行者アカウントID・発行UTC日時・期限UTC日時・使用者アカウントID（未使用はNULL）・使用UTC日時（未使用はNULL）・取消UTC日時（未取消はNULL）の9列を基本とする（DEC-097）。期限切れは現在時刻との比較で求め、状態名の重複列を持たない。保存したトークンを照合・再コピーの両方に使い、ハッシュの重複列を追加せず、トークンに一意制約を置く。

トークンは暗号学的乱数で生成し、家計簿招待では平文保存する（DEC-095）。Data Protectionでのトークン暗号化案は採用しない。平文のトークン・リンク全体は通常ログへ記録しない。認証側の登録招待は既定のハッシュのみ・再表示なしのままとし、家計簿招待の平文保存・再コピーに合わせて変更しない。

APIは参加確定時にも現在の期限・使用済み・取消状態をDBで検証し、失効済みのトークンでは新たに参加させない。確認画面を開いた時点だけの検証で参加を通さない。すべてのリンクが失効していれば、DBに残ったトークンから新たに参加することはできない。招待の失効と、既に成立した参加を除外する操作は別とする。

| API（利用者確認済み・DEC-096） | 役割 |
| --- | --- |
| `GET /ledgers/{ledgerId}/invitations` | 現在の家計簿管理者が有効な招待とコピー用リンクを取得 |
| `POST /ledgers/{ledgerId}/invitations` | 現在の家計簿管理者が招待を発行。作成要求IDを受け取り、発行したリンクと更新後の有効招待一覧を返す |
| `DELETE /ledgers/{ledgerId}/invitations/{invitationId}` | 現在の家計簿管理者が招待を取消し、更新後の有効招待一覧を返す |
| `POST /ledger-invitations/preview` | 登録済みログインアカウントが本文のトークンで状態・参加先・参加済みかを確認。読み取り専用 |
| `POST /ledger-invitations/accept` | 登録済みログインアカウントが本文のトークンで参加を確定 |

管理者用APIは毎回現在の家計簿内の役割を確認し、受領側は家計簿未参加でもログイン済みアカウントが利用できる構成にする。参照とpreviewは既定のアカウント共有120回／分、発行・取消・acceptは共有20回／分を使う。HTTPメソッドだけで回数枠を分けない既定方針に従う。ブラウザーの招待ページ・トークンの受け渡し・ログイン後の固定の戻り先は、後述の確認済み方針に従う。

次のAPI・再送・一括保存の基本処理は利用者確認済み（DEC-096）。

- 招待発行の再送も既定の共通`operation_requests`へ`ledger-invitation.create`として記録する。成功した招待と同一トランザクションで記録し、同じ作成要求の再送では新しいリンクを増やさない。新しい専用の再送表は作らない。DEC-096により、DEC-066の家計簿・人物作成の対象へ招待発行も追加する。
- 未参加者の参加者行追加・招待の使用済み化・対象家計簿を開く処理と最終選択の更新を同一トランザクションにまとめる。成功応答へ家計簿データを含め、参加後に別の開く要求を送らない。どこかで保存に失敗すれば参加・招待消費・最終選択をすべて戻す。
- 同じリンクを別のアカウントが同時に承諾しても、先に確定した1人だけを参加させる。後の要求は使用済みとして扱う。取消と参加も同じ書込トランザクションで状態を照合し、取消が先なら参加不可、参加が先ならその参加を取消操作で元へ戻さない。
- 既存参加者には参加済みと表示し、リンクを消費しないDEC-084を維持する。使用済み・期限切れ・取消済み等の案内は既定の招待エラー画面に従う。招待行や共通の要求記録を根拠に、除外済みのアカウントを自動で再参加させない。

**招待テーブルの列（DB実装済み）とブラウザー受け渡し（未実装）**

上記の9列と以下の列名を確認済み（DEC-097）。トークンの平文保存自体はDEC-095で確認済み。招待の状態を案内できるよう、期限切れ・使用済み・取消済みでも行を残し、自動削除は設けない。

| 列名 | 内容 |
| --- | --- |
| `id` | API生成の招待UUID・主キー |
| `ledger_id` | 参加先の家計簿ID |
| `token` | 推測困難な乱数トークン。平文で保持し、照合とリンクの再コピーに使う。一意制約を置く |
| `created_by_auth_user_id` | 発行したアカウントID |
| `created_at_utc` | 発行日時 |
| `expires_at_utc` | 有効期限 |
| `used_by_auth_user_id` | 使用したアカウントID。未使用はNULL |
| `used_at_utc` | 使用日時。未使用はNULL |
| `revoked_at_utc` | 取消日時。未取消はNULL |

ブラウザーのトークン受け渡しは以下の方針を確認済み（DEC-098・099）。通常のログインでは最後に開いた家計簿等へ進み、招待経由ではログイン後の参加確認を優先する。

1. リンクは設定済みの固定HTTPSオリジンを使い、`https://<公開オリジン>/ledger-invitation#token=<トークン>`の形にする。`#`以降のフラグメントをブラウザーのJavaScriptが読み取り、トークンをAPIへのPOST本文で送る。URLのパス・クエリにトークンを入れない。
2. 読み取ったトークンを同一タブの`sessionStorage`へ一時保存し、`history.replaceState`で表示中のURLからフラグメントを除く。ページ再読み込みやログインへの移動を挟んでも同じタブで復元する。恒久的な`localStorage`には保存しない。
3. 未ログインならログインへ進み、成功後は招待の参加確認を表示する。`/auth/login?returnUrl=/ledger-invitation`で、ログイン画面へ「成功後は招待ページを表示する」と伝える（DEC-099）。ログイン画面の戻り先許可へこの固定パスだけを追加し、既存の`/connect/authorize`への戻り方を維持する。戻り先URLへトークンを埋め込まない。
4. 招待ページで一時保存したトークンを使ってpreviewし、［参加する］でacceptする。トークンの保持だけで権限を与えず、APIの最新の本人・期限・取消・使用状態の確認を維持する。
5. 参加成功・既に参加済み・使用済み等で利用不可・本人の［戻る］では一時保存を消す。通信障害やログイン待ちの間は再試行できるよう残す。一時保存を利用できない場合は入力や秘密値をログへ出さず案内し、参加処理を進めない。

フラグメントは通常のページ取得のHTTP要求へ送られないため、招待トークンをリクエストURLの通常ログへ載せずに受け渡せる。APIへのPOST本文もログへ出さない既定方針は維持する。DBで暗号化しないDEC-095とは別の、ブラウザーとAPI間の受け渡し方法である。

## 家計簿の参加確認・結果（未実装）

参加前確認と参加確定のAPIは実装済み。previewはstatus・ledgerId・ledgerName・expiresAtUtc、参加成功はstatus=joinedと開いたledgerを返す。以下のブラウザー画面とログインからの復帰は未実装。招待取消は現在の状態を同じトランザクション内で検証する単方向の処理であり、使用済みの招待を取り消して参加を解除することはない。

リンクを受け取って開く・参加する操作と使用済み等の表示はブラウザー側で扱い、Windows専用の参加画面やリンク受信は追加しない。Windowsの参加者一覧から開く招待発行・管理の画面とは区別する。

未参加者が家計簿招待リンクを開くと、参加先の家計簿名を使った「『家計簿名』に参加しますか？」と「参加する」「戻る」を表示する。アカウントの表示名とは区別する。招待を開いただけでは参加せず、「参加する」で確定する。

未ログインなら先にログイン画面を表示し、ログイン成功後は通常の家計簿への遷移よりも参加確認画面への復帰を優先する。参加確認画面の「戻る」は、ログイン済みなら上記の通常の行き先（最後に開いた家計簿等）、未ログインならログイン画面へ進む。

参加成功後は、その家計簿のレシート一覧へ進み、「家計簿に参加しました」を一定時間表示する。参加完了専用の画面は挟まない。有効なリンクを開いたアカウントが既に参加済みなら、その時点で「この家計簿には参加済みです。」と表示する（DEC-084）。［参加する］は表示せず、参加・役割・人物対応を変更せず、招待リンクも消費・失効させない。メッセージの具体的な表示時間は実装前に具体化する。

## 招待リンクの共通エラー画面（未実装）

アカウント登録・家計簿参加の両方で、リンクに問題がある場合は同じ形式のエラー画面を表示する。

| 状態 | 表示するメッセージ |
| --- | --- |
| 無効・取消済み | 無効な招待です。 |
| 期限切れ | 招待の期限が切れています。 |
| 使用済み（家計簿参加） | この招待リンクは使用済みです。 |

「戻る」などの操作ボタンは置かない。アカウント登録の招待と家計簿参加の招待は別々のまま扱い、有効期間等の条件まで共通化しない。
