# 01 機能一覧・画面仕様（レガシー版）

更新日: 2026-10-18 / 対象: 現行ソース、実SQLite DDL、移行SQL、自動テストとの照合。Windows CIで対象の画面操作・保存処理と既存ソリューションのビルドを確認済み。実運用DB・手動での画面確認は未実施。

## ステータスの定義

- **実装確認**: 画面と処理のソースを確認できた（動作保証ではない）。
- **自動検証済み**: 記載した範囲を一時DB・自動テストで確認した。実運用環境全体の確認とは区別する。
- **一部実装**: 雛形、途中までのUI、またはコメントアウトが残る。
- **未確認**: ソースから存在・正否を断定できない。

## 操作上の補足

- レシートの登録・流用は、店名／内税か外税か／支払方法／明細の必須チェックを共用する。不備があれば両ボタンを無効にし、処理を直接呼んでも確認・Seqやヘッダーの変更前に止める。修正後は追加操作なしで再登録できる。[30 詳細](30-receipt-input-validation.md)。
- 税端数のラジオボタンは内税／外税とは別グループ。新規入力で店名を確定すると、設定したUserCode（未指定ならWindowsログイン名）に対応する所有者の同店の履歴から、日付降順・同日時は `seq` 降順で方式を選ぶ。履歴なしは切り捨て。店舗マスタ未登録・店名自由入力でも利用でき、店舗マスタの端数値は初期選択に使わない。
- 手動で税端数方式を選んだ後や保存済みレシートの編集では、店舗変更で方式を上書きしない。内税／外税と端数方式は画面側で保持し、合計だけをプレビュー計算する。必要な登録確認がすべて済んでから `Receipt` に転記するため、編集中・確認取消・画面取消で元の両設定は変わらない。レシート全体をコピーする実装ではない。
- 流用は従来どおり、確認後すぐに新規保存して画面を閉じる。登録ボタンの押し直しは不要で、画面上の税設定を引き継ぐ。元レシートのDB上の内容は変更しない。
- レシート更新・削除時は、対象者割当→明細→グループの順に子を削除し、削除時は最後に親を削除する。既存トランザクションでDB変更を一括して確定・巻き戻す。外部キーON/OFF両方で自動検証済みで、製品の接続設定は変更していない。
- 所在地、レシート・グループ・明細のタグがSQLのNULLでも、読込時は空欄として扱う。読込・取消ではDBのNULLを更新せず、明示的に保存した場合は画面上の空文字を保存する。必須の店名・品名等の読込条件は変更していない。残高・支払方法別残高・振替のタグもNULLだけを空文字へ変換する（LEG-028）。
- 明細の値引率は小数を含む`Double`として保存・再読込する。小数率で読込例外となる不具合を修正し、入力操作・単価値引・率値引の計算方式は維持する。
- 既存レシートの端数方式は移行時に `floor` とし、既存金額は更新しない。オーケーの割引は従来の明細割引額への手入力を継続する。
- 同じ分類のグループを選ぶと「統合」できる。分類の重複登録を防ぐUI処理がある。
- 振替では移動元と移動先が同一のとき登録を拒否する。
- 残高登録では、評価額のみの入力は拒否。少なくとも1件の口座残高が必要。
- 残高削除は支払方法別の子→残高親の順に行い、既存トランザクション内で確定・巻き戻す。FK ON/OFFで成功・親削除失敗時の復元と再削除を自動検証済み。画面操作・製品のFK設定・DDLは維持する（LEG-027）。
- 支払メモは渡された全行の追加・更新が成功した場合だけ確定し、失敗時はその一括保存のDB変更をすべて戻して例外を呼出元へ伝える。空リストは保存しない。終了時のYes／No／Cancelなど画面の操作・確認は変更しない。
- 支払方法の所有者として使う `m_user` と、購入明細の「対象者」は同じ人マスタでも用途が異なる。
- 明細対象者の集計は「部分一致」「完全一致」と「対象者１名のみの按分表示」がある。具体的計算は [03-calculations.md](03-calculations.md)。
- アプリのログイン認証、スマホ入力、Web API、クラウド同期は**現行機能としては確認されていない**。

分類集計・収支集計で金額の範囲を超えた場合、表全体を「集計不可／範囲超過」へ置き換え、年や絞り込み条件の変更で再計算する。保存値は変更しない。[26 詳細](26-statistics-amount-overflow.md)。

残高推算欄は範囲外を「範囲超過」と表示し、残高の反映ボタンで入力値を壊さない。残高集計は表とグラフを消して範囲超過を知らせ、条件変更で復帰する。[27 詳細](27-balance-amount-overflow.md)。

振替の登録・流用は入力条件を共用し、名称空欄・支払方法未選択・不正な金額では両ボタンを無効にする。処理を直接呼んでも確認・モデル変更より前に止め、修正後は再操作できる。[28 詳細](28-transfer-input-validation.md)。

残高登録は一時的な明細リストで全入力を検証し、確認後に元モデルへ反映する。入力エラーや確認取消では日付・タグ・明細と参照を保持し、同じオブジェクトを開き直しても元の値を表示する。[29 詳細](29-balance-input-state.md)。
