# 集計詳細画面の金額範囲超過

更新: 2026-10-21。対象は`DetailViewForm`の分類別／支払方法別の詳細。利用者承認に基づき、明細別・グループ別の金額計算で範囲を超えても画面の操作を続けられるようにする。

## 表示と復帰

- 既存の`DetailCalculatedFee`／`GroupCalculatedFee`によるInt32変換で`OverflowException`が起きた場合、前回の結果と途中までの行を消し、「集計不可／範囲超過」の1行へ置き換える。Seq・店名・数量などは空欄にし、ツールチップで明細表示や対象条件の見直しを案内する。
- 繰り返し切り替えられるよう、表内の表示だけで知らせ、メッセージボックスは追加しない。0円や上限値への補正、正常な行だけの部分表示は行わない。
- 明細表示のチェックを切り替え、選んだ表示の計算が範囲内なら通常の表へ戻る。グループの合算だけが超える場合と、逆に明細が超えてもグループ内で相殺される場合がある。どちらも既存の計算式を維持する。
- 読込前に前回の行を消し、成功・範囲超過・それ以外の例外のいずれでも`Finally`で行高・列幅・見出しの自動調整を復元する。品名列の幅を最大500にする既存処理も維持する。金額以外の例外は呼出元へ返す。
- 分類／支払方法、月／年、コードの絞り込み、列の表示条件、日時・店名・数量・タグなど正常時の表示を維持する。詳細画面に新しい期間／条件コントロールは追加しない。

これは表示側の対策であり、計算式・税率別合算・端数処理・割引・DataAccess・保存SQL・スキーマを変更しない。移行も不要。[25 登録時の範囲確認](25-receipt-amount-overflow.md)、[26 月年集計](26-statistics-amount-overflow.md)、[27 残高表示](27-balance-amount-overflow.md)とは別の表示経路を扱う。

## 自動検証

Windowsで製品のDetailViewForm・Designerと実SQLiteを使い、FK ON/OFF・両端数方式を確認する。現在の登録防御で拒否される値も、既存データの読込経路を検証するため一時DBへ直接設定する。利用者の実DBは変更しない。

- 分類別／支払方法別で正負のグループ合算超過と明細の数量倍超過を確認し、前回の正常な表と途中行を残さない。実際のCheckedChangedで明細／グループを往復し、計算できる側へ復帰する。
- コードの指定／全件・空の分類／支払方法、月／年・空月・空年を確認する。コードや期間の変更は既存の呼出引数をテストから設定するもので、画面上の新しい操作や親集計画面からの一連のE2Eではない。
- Shownから始まる税による正負の超過と再表示、通常の税額、型の最小／最大値、日時・店舗・所在地・支払方法・タグ・数量・長い品名の幅上限を固定値で比較する。
- 自動調整・列の可視性・ソート記号の復元、範囲超過以外の例外の伝播と再表示を確認する。
- 表示・切替前後で全保存値・格納型・更新版・スキーマ・FK／user_versionを比較し、書込イベント0回を確認する。

件数・CI結果は[tests/README](../tests/README.md)に集約する。利用者環境の手動操作と実データの監査は未実施。
