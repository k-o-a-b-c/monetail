# 明細の率値引と金額をDecimalで計算する

従来のDouble式では、3,000円×1.1%が33.00000000000001円となり、Ceilingで34円の値引きになる。入力・モデル・読込・明細計算をDecimalに揃え、正しい値引額33円・明細金額2,967円を得る。

## 計算と入力

1. 単価から単価値引額を引き、数量を掛けて基礎金額を得る。Decimalで計算する。
2. `Math.Ceiling(基礎金額 * 割引率 / 100D)`を基礎金額から引く。明細ごとの整数化は維持する。
3. 整数化した明細金額を従来どおり税率別に合算し、レシートの方式で税を計算する。

`ReceiptDetail.DiscountRate`はDecimal。RegisterFormはDecimal.TryParseの標準書式と現在のカルチャーで読み取る。不正値は0、負値は0、100%超は100へ補正し、通知ダイアログは増やさない。小数2桁への制限・丸めや独自パーサーは追加しない。

Receiptの合計・分類／明細参考額・対象者別参考額で使う明細計算をすべてDecimalにする。対象者の選択・人数割りは今回の対象外で、整数化した明細金額を従来のDoubleによる按分へ渡す。独立クラスや計算ルールの分岐は追加しない。

## DBと保存値

一覧／支払方法別の共通読込と子再読込はGetDecimalを使う。既存のINTEGER率とREAL小数率を扱い、DBのINTEGER宣言・保存SQL・既存データを移行しない。保存時はDecimalのモデル値を既存のパラメーターへ渡し、小数率の格納クラスが従来どおりREALであることを検証する。

読込・比較・再計算で保存済みtotal・率・数量・端数方式を補正しない。旧保存値2,966円との差は一覧で示す。明示的な登録・更新の既存SQLは維持する。オーケーの手入力値引と操作、割引率の過去データ125%／150%の読込・計算も維持する。

## 検証

固定値で整数境界・正負・0／100%・既存の100%超、単価値引後の数量倍、税との組合せ、明細単位の整数化を確認する。実SQLite・FK ON/OFF・両端数方式で、現在のカルチャーによる率入力、整数／小数率の保存と3読込経路、保存済みtotalを維持した差の表示、全保存値・型・更新版・スキーマ・PRAGMAと書込0回を確認する。

既存の小数率読込・保存テストへ1.1%／2.2%／2.51%を追加し、Decimal型で比較する。実データは使わない。件数と最新結果は[tests/README](../tests/README.md)を正本とする。過去のGetInt32→GetDouble修正と税計算Decimal化は、その時点のCI記録として残す。
