# レシート一覧の金額範囲超過

更新: 2026-10-21。対象は`ViewForm_List.vb`のレシート一覧。通常の登録・更新には既に[25 金額範囲の防御](25-receipt-amount-overflow.md)があり、今回の対象は既存の範囲外データ等を表示する経路である。利用者は一度保留を検討した後、実施を承認した。

## 表示とデータバインド

従来は`List(Of Receipt)`の`Total As Integer`を金額列へ直接バインドしていた。範囲外のReceipt.Totalは読取りでOverflowExceptionを投げる。Windowsの再現テストでは旧経路にDataErrorの記録用ハンドラーを付け、直接バインドのエラーを捕捉する。製品へ包括的なDataError抑止は追加しない。

一覧内の非公開`ReceiptListRow`は元のReceiptを参照し、Seq・日時・店名・所在地・支払方法・タグをそのまま返す。TotalだけをObjectとして公開し、正常時は従来の整数、OverflowException時は「範囲超過」を返す。整数は従来のN0書式で表示し、範囲外のセルには明細確認のツールチップを付ける。金額以外の例外は握りつぶさない。

- 他の行は通常どおり表示し、利用者・支払方法による絞り込み、年月更新、行選択、編集ボタン／ダブルクリックによる編集を継続できる。
- 金額を含めてReceiptの現在値を参照し、表示結果を固定コピーしない。元Receiptをディープコピーせず、AccountListと編集先の参照は維持する。
- 対象者が未設定の明細を持つレシートの色付け、正常な金額の書式、振替一覧を維持する。列のバインド名・Designerは変更しない。
- 範囲超過は一覧の該当セルで知らせ、通知ダイアログ、0や上限値への補正を追加しない。修正は既存のレシート編集画面で行う。

Receiptの計算APIは引き続き範囲外で例外を返す。税率別合算・端数処理・オーケーの割引・DataAccess・保存SQL・スキーマ・保存済み合計を変更せず、移行も不要。明細操作時の元モデル反映や編集取消の既存契約を変えるものではない。

## 検証

製品の一覧partial・Designer・登録画面と実SQLiteをWindowsで使用し、FK ON/OFF・両端数方式で確認する。

- 旧Total直接バインドの読取りエラーを再現し、表示用Totalが金額以外の例外を隠さないことを確認する。旧経路の記録用ハンドラーはテスト専用とする。
- 正負の数量倍・税による範囲超過と、通常額・0円・整数両端の行を混在させる。通常の金額とen-US／de-DEのN0書式、日時・店舗・任意文字列・支払方法の参照、色付け、振替一覧とクリップボード用データを比較する。
- 同じReceiptの明細値を一時的に変更し、金額とツールチップが正常／範囲超過へ再表示されることを確認する。DBは更新せず、変更値も元に戻す。
- 選択行の復元、実際の支払方法選択イベント、利用者の条件、空月への移動と復帰、製品の編集／ダブルクリック処理から元Receiptを開いて取り消す動作を確認する。
- 同じ編集経路で範囲外のレシートを修正・保存し、一覧の更新、選択と整数表示、保存値・更新版の反映、他の行の保持を確認する。
- 読込・表示・切替・取消では、全保存値・格納型・更新版・スキーマ・FK／user_versionを保持し、書込0回と製品一覧でのDataError 0回を確認する。

一時DB・年月・利用者候補はテスト用partialから設定する。支払方法の選択と一覧の編集処理は製品のイベントを実行するが、利用者選択の親画面イベントと年月移動ボタンはE2Eに含めない。残高通知はテスト用カウンターへ置き換えるため、メイン画面全体の起動・通知の内容・全タブのE2Eや実DB監査の完了を意味しない。件数・CI結果は[tests/README](../tests/README.md)に集約する。
