# 新Windows版 画面台帳（画面一覧・遷移・実装状況）

更新: 2026-11-15。対象は **Windows 11 / WinUI 3版**。画面設計を横断的に見直すための索引であり、**新しい画面仕様を確定する文書ではない**。表示項目・保存・権限・未保存データ保護の正本は各行のリンク先。共通の配置・操作は [UI_DESIGN.md](../UI_DESIGN.md)、入力操作は [59](59-input-controls-design.md)、新旧機能の採否は [機能横断比較台帳](legacy-new-final-parity-matrix.md) を参照する。Webの登録・パスキー・全体アカウント管理画面は対象外（[新規利用](ledger-onboarding.md)、[招待](ledger-invitations.md)）。

## 判定基準

- **画面あり**：現行 `MainWindow.xaml` に表示領域・導線がある。全機能のAPI接続や実機確認済みを意味しない。
- **一部**：画面の一部はあるが、正本で定めた構成・操作や保存との接続が未完成。
- **枠のみ**：無効な入口・仮表示のみで、対象業務画面はない。
- **未実装**：確定済みの画面方針はあるが、該当WinUI画面はない。
- **要設計**：旧版機能または将来の入口があるが、新版の画面構成・採否を確定していない。

実装状態は上記XAMLと各機能正本の照合時点のもの。APIやDBの実装状態とは独立し、Windows実機での見た目・操作検証結果を含まない。

## 全体の画面遷移（既存仕様・現状と承認済みの変更後設計）

```text
起動 →（必要時）接続先設定 → ログイン → ブラウザー認証待ち
     → 家計簿選択 / 家計簿作成 → 家計簿ホーム
     └─ 接続失敗 → 再試行 / 接続先変更 / 終了

家計簿を開いた画面（共通上部：家計簿名・切替 ｜ 記録 ｜ 集計・分析〔未実装〕 ｜ 管理・設定）
  ※ 共通上部の管理・設定への適用はDEC-279で設計確定、実装は後続
  記録：レシート・振替・残高の3一覧〔確定構成、現行はレシート一覧中心〕
    レシート一覧 → レシート専用入力（新規・編集） → 一覧
    振替一覧 → 振替専用入力（新規・編集） → 一覧〔未実装〕
    残高一覧 → 残高の登録・編集〔後続、詳細導線要設計〕
  管理・設定：共通上部の下に左側メニュー + 右側コンテンツ（現行の独立した戻るボタンは統一時に廃止）
    人物 / 科目 / 支払方法 → 一覧、追加・編集ダイアログ、並び順専用画面
    参加者 → 編集ダイアログ / 招待管理の専用画面
    接続先の設定 / ログイン情報 / その他の未実装メニュー
```

家計簿の切替はホームのポップアップを使用し、機能画面は原則 **同一Window内** で切り替える。人物・科目・支払方法の追加・編集には `ContentDialog` を使う。レシート・振替の入力と各種並び順変更・招待管理は専用表示領域を使う。詳しい戻り・保存・離脱条件は各正本を参照。

## 旧版機能からの未確定の入口

旧版には **分類／収支／残高集計、集計内訳** 等がある。新版は **科目別集計／収支集計／残高集計を上部［集計・分析］の下で `SelectorBar` により切り替える構成（DEC-285）**を確定した。年の直接入力・前年／翌年ボタンと3画面での共通選択は確定（DEC-289）。**記録一覧とも人物・年を共有し、集計では月の入力を無効にする（DEC-290）**。全期間の一覧から集計へ移ると保持済みの年で集計し、戻っても一覧は全期間のまま。集計で年変更があれば月指定復帰時に変更後の年と元の月を表示（DEC-291）。**科目別・収支集計の表は1月〜12月＋年計の13データ列（DEC-296）**。旧残高集計は12か月のみだったが、新版は［前年比］を13列目に追加（DEC-297・302）。基準額は前年12月の最後の登録（12/31必須ではない）、比較対象は終了済みの算出可能な最新月末（DEC-298・302）。支払方法間で比較月を統一し、算出不能行と不完全合計は「—」（DEC-299）。評価額モードの参照元は評価額あり支払方法では評価額のみ、評価額なしでは残高。評価額ありで評価額を欠いても残高を代用しない（DEC-306）。前年12月に登録がない支払方法は前年比「—」、評価額あり支払方法は12月内に評価額がない場合も前年比「—」（DEC-303・307）。対象年の初期値・入力検証、その他の集計条件・計算契約と内訳対象セルの範囲は未決定。**内訳は集計セルのダブルクリックで同じ主領域に表示し、左上［← 戻る］で元表へ戻る（DEC-286）**。**対象セルの年月・科目等と、元表の人物・収支など適用中の絞り込みを落とさず引き継ぐ（DEC-287）**。**初期はレシート内の科目グループ単位、［明細表示］チェックで購入明細単位へ切り替える（DEC-288）**。グループ・明細の参考額と会計合計の端数差は維持する。**支払メモは右側パネルの配置と基本的な保存タイミングをDEC-282で確定済み**。[旧版機能一覧](01-features.md)、[機能横断比較台帳](legacy-new-final-parity-matrix.md)、[新旧比較](legacy-new-comparison.md)を参照して採否・遷移を別途確認する。旧版の画面数を新版の画面数に機械的に置き換えない。

## 全体ナビゲーション見直しの論点

**確定（DEC-279・2026-11-15、WinUI実装は後続）**：上部を全機能共通の1行に統一する。管理・設定でも同じ上部を残し、下に左メニュー・右コンテンツを表示する。現行の管理専用［記録・集計に戻る］は廃止し、上部の［記録］で戻る。詳細な確定設計は[共通UI](../UI_DESIGN.md#共通上部ナビゲーションdec-2792026-11-15確定実装は後続)を正本とする。

**確定（DEC-280・2026-11-15、レシートのWinUI変更は後続）**：レシート・振替の専用入力画面はともに左上［← 戻る］。下部のキャンセル／一覧に戻るボタンは設けない。未保存保護は既存仕様を維持。正本は[共通UI](../UI_DESIGN.md)および[レシートUI](ledger-receipt-ui.md)、[振替UI](ledger-transfer-ui.md)。

**確定（DEC-281・2026-11-15、WinUI変更は後続）**：「集計・分析」は上部に残す（未実装時は無効表示）。「店舗管理」は設けない。「表示設定」と「入力時の初期値」は当面メニューから除外する。

**引き続き検討する論点（未決定）**：以下は変更提案の論点であり、確定済みの既存仕様を変更しない。
1. **記録ホームの確定構成への整合**：3一覧・1組の共通フィルター・一覧別文字列検索へ現行XAMLを移す際、個々の画面と戻り導線を分かりやすくする。**3一覧の配置比率・狭幅2段維持・フィルター共通化は既に確定しており、ここで再決定しない**。
2. **旧版にある未移行機能の所属**：支払メモは右側パネル内の直接編集・即保存（DEC-282）、残高登録は記録ホームから専用入力画面（DEC-284）、集計・分析は固定3ビュー切替（DEC-285）。**年次集計の具体的な入力条件・内訳の対象セル範囲やAPI・残高入力の業務詳細は要設計**。内訳の同一画面内への切替・左上戻る操作はDEC-286、集計条件の完全な引継ぎはDEC-287で確定。未承認の新画面は増やさない。

レビューでは上部ナビゲーション・専用入力の戻り位置・未実装メニューの扱いを確定済みとし、次に **2. 旧版機能の所属**へ進む。WinUI 3標準 `NavigationView`・`ListView`・`ContentDialog` とキーボード／アクセシビリティ対応を前提とする。実装時に実プロジェクトの参照パッケージでAPI可用性を確認する。
