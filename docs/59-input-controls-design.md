# 59 新Windows版の入力コントロール設計

新Windows版の共通入力コントロールについて、キー操作・入力形式・補完・正規化・形式不正への対処を管理する正本。共通の配置・フォント・エラー表示の原則は[UI_DESIGN.md](../UI_DESIGN.md)、人物等の業務仕様・権限・保存は[58 家計簿設計](58-ledger-foundation-design.md)を参照する。

日付・時刻入力とEnterキー操作の共通部品をWinFormsで実装し、人物管理へ日付入力とキー操作を適用した。WinUI 3へUIを切り替える決定後も以下の確定仕様を維持するが、WinUI 3の入力欄・フォーカス・IME連携は未実装。Client内の補完・正規化ロジックは再利用し、UI依存部分を作り直して検証する。時刻入力部品は、時刻を扱う業務画面の追加時に適用する。検証結果と未検証項目は[tests/README](../tests/README.md)を参照する。今後の追加案や旧版の実装を、そのまま新版の確定仕様と扱わない。

## 日付のキーボード入力（実装済み）

以下は利用者確認済みの仕様。入力欄ごとの空欄可否は各機能の正本に従う。

### 入力形式と正規化

| 区切りなしの入力 | 読み取り方 |
| --- | --- |
| 1〜2桁 | 日（`d`／`dd`） |
| 3〜4桁 | 月日（`mdd`／`mmdd`） |
| 6桁 | 2桁年と月日（`yymmdd`） |
| 8桁 | 4桁年と月日（`yyyymmdd`） |

- 区切りなしの年月日は6桁・8桁に限定し、5桁・7桁は不正入力として扱う。
- 区切り文字は`-`・`.`・`/`とし、混在も許可する。`年`・`月`・`日`を使う日本語表記は受け付けない。
- 区切り付き入力は2組なら月日、3組なら年月日。年は2桁・4桁、月日は各1〜2桁とする。2桁年は6桁入力と同じ方法で補完する。
- 全角の数字とこれらの区切り文字を半角へそろえ、前後の空白を除去して読み取る。内部の空白や余分な区切りは不正入力として扱う。

### 日付の補完

- 日だけを入力した場合は、本日を含む過去1か月以内で、その日が存在する最も新しい日付へ年月を補完する。範囲内に存在しなければ不正入力として扱う。指定日を月末へ丸めない。
  例えば2026/03/01に`31`を入力した場合は不正入力。2026/04/01なら2026/03/31に補完する。
- 月日を入力した場合は、本日を含む過去1年以内で、その月日が存在する最も新しい日付へ年を補完する。範囲内に存在しなければ不正入力として扱う。月日を別の値へ丸めたり、数年前までさかのぼったりしない。
  例えば`2/29`は2026/11/01時点や2028/02/01時点では不正入力。2028/03/01時点なら2028/02/29、2029/02/28時点でも2028/02/29に補完し、2029/03/01時点では不正入力になる。1月29日や2月28日へ変更しない。
- 2桁年は、入力した下2桁が一致する年のうち、現在の年に最も近い世紀で補完する。前後で同じ距離（50年差）なら過去側を選ぶ。先に年を決めてからその年月日の実在を確認し、存在しなければ不正入力として扱う。有効な日付を求めて別の世紀を探し直さない。
  現在が2026年なら`960401`は1996/04/01、`261201`は2026/12/01、`270401`は2027/04/01、`000401`は2000/04/01、`760401`は1976/04/01。現在が2100年なら`260401`は2126/04/01になる。
- 4桁年は入力した年・月・日をそのまま使い、その年月日が存在しなければ不正入力として扱う。年を指定した有効な日付は、未来日も維持する。
- 1か月・1年は暦で数え、1か月前・1年前から本日までの両端を含む。30日・365日等の固定日数にはしない。起算日の同日が存在しない場合はその月末を境界とし、補完対象の指定日・月日を丸める処理とは区別する。

### 不正入力と空欄

| 欄の仕様 | 不正入力時 | 空欄で確定した場合 |
| --- | --- | --- |
| 空欄可 | 空欄へ置き換える | 空欄を維持する |
| 日付必須 | 本日の日付へ置き換える | 本日の日付へ補完する |

- 不正入力には、非対応の形式・桁数、4月31日等の存在しない月日、年指定でその年に存在しない日付、補完範囲内に候補がない場合を含む。
- 日付形式のエラー説明やメッセージボックスは表示しない。これは共通UIの入力エラー表示とは別の、日付コントロール固有の補正仕様とする。
- 人物の有効期間の空欄は制限なしであり、不正入力も本日ではなく空欄へ置き換える。
- 開始日と終了日の前後関係等の業務条件違反は、この補正の対象にせず、各機能の確定済みエラー処理に従う。

### 基準日・確定・表示

- 「今日」と年の補完の基準は、入力確定時点のWindowsのローカル日付を使う。
- 入力途中では補完せず、欄を離れるときと保存直前に同じ処理を行う。キャンセル時は補完を行わない。
- 有効な日付の表示は`yyyy/MM/dd`へ統一する。空欄へ補正した場合は何も表示しない。
- 日付欄からの移動方法そのものは、次項のEnterキー操作の確定仕様に従って実装する。

## Enterキーによるフォーカス移動（実装済み）

通常の入力欄では、以下の利用者確認済みの操作とする。

| 操作・場面 | 動作 |
| --- | --- |
| Enter | 次の欄・ボタンへ移動する |
| Shift＋Enter | 前の欄・ボタンへ移動する |
| 最後の入力欄でEnter | 保存ボタンへ移動する。そのEnterでは保存しない |
| ボタン上でEnter | そのボタンを実行する |
| Ctrl＋Enter | 登録・編集画面で登録／保存を実行する |
| IME変換中 | 変換確定を優先し、移動・保存しない |
| コンボボックスの候補を開いている間 | 候補を確定し、そのEnterでは移動しない |
| 複数行入力・表のセル編集 | Enterは改行や表の標準操作を優先する |

- フォーカス移動は画面のTab順に従い、無効・非表示の欄を移動先から除外する。保存ボタンも移動可能な場合に対象とする。
- Tab／Shift＋Tab、矢印、Space等の標準操作を維持する。
- 登録・保存の実行は、既存の権限・入力条件・操作の有効／無効に従う。ショートカットで実行条件を迂回しない。

## 時刻のキーボード入力（実装済み）

### 入力形式と省略補完（確定）

| 区切りなしの入力 | 読み取り方 | 入力例と結果 |
| --- | --- | --- |
| 1〜2桁 | 時（`h`／`hh`） | `9`・`09` → `09:00:00` |
| 3〜4桁 | 時分（`hmm`／`hhmm`） | `915`・`0915` → `09:15:00` |
| 5〜6桁 | 時分秒（`hmmss`／`hhmmss`） | `91530`・`091530` → `09:15:30` |

省略した分・秒は0で補完する。`9:15`・`9:15:30`のようなコロン区切りの入力も受け付ける。

### 入力範囲と正規化（確定）

- 時は0〜23、分・秒は0〜59の24時間表記とする。`24:00`等、範囲外の値は不正入力として扱う。
- コロン区切りでは時分・時分秒の各部分を1〜2桁とする。例えば`9:5`は`09:05:00`に補完する。
- 全角の数字とコロンを半角へそろえ、前後の空白を除去して読み取る。内部の空白は不正入力として扱う。

### 不正入力と空欄（確定）

空欄の可否は日付と同様に欄ごとの仕様で設定する。

| 欄の仕様 | 不正入力時 | 空欄で確定した場合 |
| --- | --- | --- |
| 空欄可 | 空欄へ置き換える | 空欄を維持する |
| 時刻必須 | 午前0時（`00:00:00`）へ置き換える | 午前0時へ補完する |

時刻形式のエラー説明やメッセージボックスは表示しない。各画面の業務条件に対するエラー処理とは区別する。

### 確定・表示（確定）

- 日付と同様に、入力途中では補完せず、欄を離れるときと保存直前に同じ処理を行う。キャンセル時は補完を行わない。
- 有効な時刻の表示は24時間表記の`HH:mm:ss`へ統一する。空欄へ補正した場合は何も表示しない。
- 時刻欄からの移動方法そのものは、Enterキー操作の確定仕様に従って実装する。
