## 日付のキーボード入力（仕様整理中・省略入力は未実装）

以下は利用者と確認した事項。日付コントロール全体の仕様が確定したとは扱わず、残る判断点を確認してから実装する。

| 区切りなしの入力 | 読み取り方 |
| --- | --- |
| 1〜2桁 | 日（`d`／`dd`） |
| 3〜4桁 | 月日（`mdd`／`mmdd`） |
| 6桁 | 2桁年と月日（`yymmdd`） |
| 8桁 | 4桁年と月日（`yyyymmdd`） |

- 区切りなしの年月日は6桁・8桁に限定し、5桁・7桁は受け付けない。
- 区切り文字は`-`・`.`・`/`とし、`年`・`月`・`日`を使う日本語表記は受け付けない。全角の数字とこれらの区切り文字は、半角へそろえてから読み取る。
- 日だけを入力した場合は、本日を含む過去1か月以内で、その日が存在する最も新しい日付へ年月を補完する。1か月以内に存在しなければ不正入力として本日へ置き換える。指定日を月末へ丸めない。
  例えば2026/03/01に`31`を入力した場合は本日へ置き換える。2026/04/01なら2026/03/31に補完する。
- 月日を入力した場合は、本日を含む過去1年以内で、その月日が存在する最も新しい日付へ年を補完する。1年以内に存在しなければ不正入力として本日へ置き換える。月日を別の値へ丸めたり、数年前までさかのぼったりしない。
  例えば`2/29`は2026/11/01時点や2028/02/01時点では本日へ置き換える。2028/03/01時点なら2028/02/29、2029/02/28時点でも2028/02/29に補完し、2029/03/01時点では本日へ置き換える。1月29日や2月28日へ変更しない。
- 6桁の年は、入力した下2桁が一致する年のうち、現在の年に最も近い世紀で補完する。前後で同じ距離（50年差）なら過去側を選ぶ。先に年を決めてからその年月日の実在を確認し、存在しなければ本日へ置き換える。月日を過去へ戻したり、有効な日付を求めて別の世紀を探したりしない。
  現在が2026年なら`960401`は1996/04/01、`261201`は2026/12/01、`270401`は2027/04/01、`000401`は2000/04/01、`760401`は1976/04/01。現在が2100年なら`260401`は2126/04/01になる。
- 8桁は入力した4桁年・月・日をそのまま使い、その年月日が存在しなければ本日へ置き換える。
- 日付として解釈できない入力は本日の日付へ置き換え、日付形式のエラー説明やメッセージボックスは表示しない。非対応の桁数、4月31日等どの年にも存在しない月日、年を指定した場合にその年に存在しない日付も対象とする。これは日付入力の形式不正に対する補正であり、開始日と終了日の前後関係等の業務条件違反は各機能の確定済みエラー処理に従う。
- 補完期間の境界の詳細、区切り付き入力の年部の桁数や区切りの混在、補完の基準日と実行タイミング、確定後の表示形式は引き続き確認する。Enter移動・時刻補完の詳細も未確定で、旧版の調査結果や会話中の提案をそのまま採用済みと扱わない。
- 空欄の意味は各欄の確定済み仕様を維持する。人物の有効期間の空欄は制限なしであり、今日の日付へ自動置換しない。
