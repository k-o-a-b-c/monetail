# 42 明細税率と正確な計算へのWindows版切替

2026-10-22。[40の設計](40-detail-tax-unified-design.md)に従い、[41のコピー移行](41-detail-tax-copy-migration.md)後のDBを使うWindows版へ切り替えた。Windows自動テスト・CLI実行・既存ビルドは確認済み。実DBへの適用と手動の画面確認は未完了。利用者の指示により、未完了テストは[tests/READMEの一覧](../tests/README.md#未完了テストまとめて実施するもの)へ集約する。

## モデル・保存・読込

- `ReceiptDetail.TaxRate`が税設定を持ち、`DiscountRate`はDecimal。`ReceiptGroup.TaxRate`と`ReceiptDetail.TaxTarget`は廃止。
- 税率マスタは`tax_treatment`で課税と対象外を区別し、0%課税を対象外に読み替えない。旧コードの表示制限を廃止し、全マスタコードを読める。
- 分類は初期値用の`default_tax_category_code`を参照。区分別の開始日と税率コードで初期選択し、区分数・8%／10%・2019年の条件をコードへ固定しない。
- 一覧・支払方法別は階層1 SELECTを維持し、子再読込も一時領域へ読み切ってから反映。登録・更新は明細の税率コードと割引率のInvariantCulture文字列を保存する。
- 接続時に新構造と完了移行IDを要求する。旧DBへのフォールバックや起動時の自動移行はない。元DBをバックアップしてコピー移行し、設定XMLの接続先を検証済みコピーへ変更する。

## 計算と画面

会計・収支・分類／個人別参考額・詳細表示・残高推算は新しい明細税率を使う。[12 現行計算契約](12-calculation-contract.md)。割引率はDecimalのまま保持し、中間の乗除算と税額・按分は整数の係数／分数で扱う。税額と最終参考円額の業務上の丸め以外に近似を挟まない。税率別に合算する会計の890円を維持し、旧Doubleの誤差は修正する。手入力値引と率値引のCeilingは維持する。

税率選択をグループ欄から明細欄へ移し、対象外も同じ選択欄にまとめる。グループ一覧は分類名のみ、明細名は初期値と税率値／課税種別が異なるときだけ`（8%）`・`（対象外）`等を付ける。同率の別コードは同じ表示。

同分類の追加を抑止し、既存分類へ変更するとグループを統合する。各明細の税率・対象者を保持し、両方のメモを元のグループ順に番号付きで残す。日時・分類の選択だけでは保存済み明細の税率を変えず、手動選択と編集中の明細も維持する。表示更新では行を作り直さず選択・未反映入力を保つ。

店名・日付・内外税・端数方式は確認後に元Receiptへ反映する既存方式。明細の追加／更新はボタン時点で反映する。流用は従来どおり確認後の即時登録と画面終了で、追加の登録操作はない。マスタメンテナンス画面は追加していない。

## 初期値データと導入前の確認

コピー移行は適用履歴を空で作成する。履歴がない分類・開始日前は税率未選択となり、手動選択後に明細を追加できる。グループだけの作成は可能。実際の分類と区分の対応・期間は利用者のデータ確認後に設定し、仮の1%期間や国の税制変更日を推測で本番登録しない。ルールとマスタは接続内でキャッシュするため、外部で設定変更した後はアプリを開き直す。

Windowsでの実SQLite・画面自動テスト・CLI実行、標準SDK／既存ソリューションのビルド、性能計測を確認した。結果と対象コミットは[tests/README](../tests/README.md)を正本とする。Windows CIで見つかった残高メモの読込列を修正し、日付変更の確認回数・例外型・空グループ・分類別表示のテストを現行仕様へ合わせた。手動の画面確認と実レシート照合は別の受入確認として残る。
