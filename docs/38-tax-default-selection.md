# 税率の初期選択を並び順から独立させる

## 仕様

`TaxRateSelection.GetDefaultRate`は日付、分類の軽減税率対象フラグ、税率マスタ候補を受け取る。WinFormsやReceiptGroupには依存せず、明細入力へ移す際にも共用できる。

- 2019-10-01以降の通常分類（分類未選択を含む）は10%。軽減対象分類は8%。
- それ以前は分類にかかわらず8%。2014年以前も従来どおり8%とし、過去制度の追加対応は行わない。
- `TaxRate.Rate`が一致するマスタのオブジェクトを返す。コードを税率値として扱わず、候補の順番や値を変更しない。同率が複数ある場合は候補の先頭を使う。
- 該当なしはNothing。画面では未選択とし、税率を手動選択するまでグループの追加・更新・統合を止める。ボタン処理の直接呼出でも元モデルを変更しない。
- 日付・分類変更時の初期選択、手動変更、既存グループ選択時の保存済み税率復元という従来の操作を維持する。入力欄だけの変更では既存グループの税率を書き換えない。

`RegisterForm.SetGroupTaxRate`は共通処理が返すマスタを選択する。税率SQLや並び順、`start_date`の読込、DB構造、金額計算と端数処理、割引・登録・流用は変更しない。保存済み`t_receipts.total`の再計算や更新は行わない。期間別の税率改定と明細への税率移設は今回の範囲外。

## 検証

税率の候補順を逆転させ、日付境界の直前／当日、通常／軽減分類、率とは異なるコード、0%／5%の追加候補、空候補／必要税率の欠落を固定期待値で確認する。

Windowsの実画面・テスト用SQLiteではFK ON/OFFで、日付・分類による選択、税率欠落時のボタン状態と直接呼出の抑止、手動選択後の追加、既存8%グループの選択と取消・再表示を検証する。読込・画面操作で全保存値・型・スキーマ・版・PRAGMAと保存済みtotalが変わらず、書込がないことを確認する。件数と実行結果は[tests/README](../tests/README.md)を正本とする。
