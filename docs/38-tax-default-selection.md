# 税率の初期選択

RegisterFormのグループ税率は、マスタの表示順ではなく税率値で初期選択する。税率マスタの追加・並び替えで8%と10%の選択が変わる問題（LEG-013）を解消する。

## 選択条件

| レシート日付・分類 | 初期税率 |
| --- | ---: |
| 2019年10月1日より前 | 8% |
| 同日以降・軽減対象 | 8% |
| 同日以降・通常分類または分類未選択 | 10% |

この日付・軽減対象の条件は従来どおり。ComboBox内のTaxRateをRateで検索し、同じ率が複数ある場合はコードが最小のものを選ぶ。マスタの取得SQLと表示順は変更しない。

必要な率がない場合は未選択とし、グループの追加／更新を無効にする。ボタン処理の直接呼出でも、モデル変更前に検証する。利用者が登録済みの別税率を明示的に選ぶと、従来どおり追加／更新できる。分類が未選択の場合は追加／更新できない。

既存分類への「統合」は統合先の税率を保持するため、初期税率が見つからなくても実行できる。追加の選択操作は要求しない。

## 既存データと対象範囲

既存グループを選択すると、そのグループの保存済みTaxRateを表示する。同率で別コードがあっても、初期値のコードに置き換えない。日付・分類による初期値の選択だけではReceiptの税率を変更せず、ヘッダーのみ保存しても既存グループの税率コードと計算結果を維持する。グループを明示的に追加／更新する従来の経路は維持する。

DB移行、税計算、内税／外税、端数方式、即時保存する流用、オーケーの手入力値引は変更しない。グループ・明細自体の編集を含むフォーム全体の取消方式を変更するものではない。

日付に応じた税率の自動選択は[追加要望として記録](08-requested-enhancements.md#6-やりたいこと追加要望未着手)したが、未実装。期間境界・軽減税率との組合せは未設計で、将来税率を追加しても現在の初期値には採用せず、上記の8%／10%条件を維持する。

## 検証

製品フォーム・実SQLiteを使い、FK ON/OFFで次を確認する。

- 将来税率・同率の重複と表示順の昇順／降順、日付境界・通常／軽減／分類未選択での初期値とモデル保持。
- 税率マスタが空、10%のみ、12%のみの場合の未選択・追加抑止と手動選択、既存分類への統合と統合先税率の保持。
- 既存の12%／8%、重複コードの10%／8%を表示・取消・ヘッダーのみ保存しても保持し、再読込後の税率コードと会計合計が一致すること。

表示・取消・メモリ上のグループ操作ではDB全値・型・版・スキーマ・PRAGMAを比較し、書込0回も確認する。テストの現在件数・CIは[tests/README](../tests/README.md)、実装は[RegisterForm](../HouseholdAccountsBeta/HouseholdAccountsBeta/Control/RegisterForm.vb)、回帰は[TaxDefaultTests](../tests/PersistenceTests/TaxDefaultTests.vb)を参照する。
