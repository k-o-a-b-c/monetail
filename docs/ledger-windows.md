# Windows版のAPI接続

[← 58 家計簿設計・文書案内](58-ledger-foundation-design.md)

## Windows版のAPI対応を先行する（実装中）

Webでの業務入力を作る前に、Windows版を同じAPIへ接続する。認証アカウント・パスキー・家計簿とその参加権限を共用し、Windowsログイン名をAPIの本人識別や認可の根拠にしない。家計簿内の人物は引き続きアカウントと別管理で、任意対応を使う。

現行のWindows版は起動時に人物・支払方法等のマスタをSQLiteから読み、一覧・入力・集計もDataAccessを直接利用する。新APIは認証・全体アカウント管理・家計簿の作成／参照／開く操作に加え、人物・参加者・招待のAPIを実装した。支払方法・分類・レシート等の業務APIはまだない。

新版は旧版とは別プロジェクトとし、技術構成・配置は[04](architecture-winui.md#新版windows版の構成)を正本とする。旧版全体を一括変換せず、起動・認証・家計簿選択、レシートの一覧／入力・編集、振替・残高・集計の順に機能を移す。各機能に必要なAPIを先に用意し、移した機能ごとに旧版との操作・計算結果を確認する。旧版は切替完了まで利用できる状態で残す。

APIは後からWebの業務画面でも利用する。

Windows版のログインは外部ブラウザーのパスキー認証とOAuthの認可コード＋PKCEを使う（DEC-051）。ブラウザー側のCookie認証を維持し、Windows版のAPI通信はBearerトークンで行う。既にブラウザーでログイン済みなら再認証を省略し、元の固定期限を引き継ぐ。OAuthの現行API・固定期限・失効の契約は[43](auth-windows-oauth.md#windows版のoauth認証dec-051)を正本とする。Clientに接続・認証・復元・ログアウトと、家計簿の参加確認・選択・作成・切替を実装した。対応するWinUI 3画面を製品起動へ接続済み。家計簿の通信も必要なトークン更新を行い、明確な認証拒否だけでログインへ戻す。

Windows版の起動時も、保存されたログイン状態が有効ならログイン画面を省略して家計簿へ進む。必要なトークン更新とAPIでの有効性・現在の参加確認を行い、上記の[通常の行き先](ledger-onboarding.md#所属1件以上で開く家計簿)に従う。保存情報が存在するだけで認証済みとは判断しない。

認証情報の保存・更新・削除は[43](auth-windows-oauth.md#windows版の認証情報保存)、APIの業務モデル・キー設計は実装時に具体化する。旧版の取引Seq・マスタCodeを新版モデルの前提にせず、旧キーとの対応は一度きりのSQL移行で整理する。

既存データの引継ぎは前節の一度きりのSQL適用を維持する。保存済みreceipt.totalを再計算・補正しない。既存Windows版の直接DB接続をAPIが扱えるようになったとみなしたり、現在の実DBへ新構成を自動適用したりしない。

### Windows版の接続先設定

接続先が未設定の初回起動では、サーバーURLの入力欄と「接続」を表示する。保存済み設定を確認して初回表示対象を決めてからWindowをActivateする。未設定では初めからConnectionSetupPageを表示し、StartupPage・起動の進捗表示・ネットワーク要求・遅延通知処理を開始しない。HTTPSの接続先を確認してから設定を保存し、ログインへ進む。次回以降は保存済みの接続先を使ってこの入力を省略する。「管理・設定 → 接続先の設定」から変更できるようにする。変更時の再ログインとトークンの扱いは[43](auth-windows-oauth.md#windows版の認証情報保存)、保存先と形式は[04](architecture-winui.md#新版windows版の構成)を正本とする。

### Windows版の起動表示・接続失敗時の操作

Window.Activateより前に、接続先と現在の接続先に対応する保存済み認証情報の有無をローカルで判定する。保存情報の存在は認証の有効性を意味しない。

| 起動時の状態 | 初回表示・処理 |
| --- | --- |
| 接続先未設定 | 接続先設定Pageを直接表示。通信・起動Page生成なし |
| 接続先設定済み・認証情報なし | ログインを直接表示。通信・起動Page生成なし |
| 認証情報あり | 起動Pageで既存の認証検証・必要なトークン更新を実行。有効なら家計簿情報を取得してから進み、失効ならログインへ |
| 通信失敗 | 認証情報を保持し、接続エラー画面へ |

起動Pageは接続先設定と同じFrameホストへ必要時に生成し、中央に「Monetail」、最初から動作するProgressRing、「接続中…」を表示する。従来の1秒遅延は廃止する。通信・認証・遷移はWindowとClientが担当し、完了・失敗・離脱時はPage/Frameの参照を解放する。離脱後の遅い応答で画面を更新しない。同一Windowを維持し、別の起動用小窓は作らない。

保存済み接続先の起動ではメタデータの再取得を省き、既存の本人確認APIと必要なトークン更新で検証する。接続先の初回設定・変更時のメタデータ検証は維持する。初回接続成功後に認証情報がなければ、起動Pageを挟まずログインへ進む。ブラウザー認証の前後にも起動Pageを挟まない。

接続失敗時はエラーメッセージと「再試行」「接続先の変更」「終了」を表示する。通信障害と認証の失効を区別し、通信障害だけを理由に認証情報を削除しない。起動の認証・家計簿復元と接続確認は既存の10秒でタイムアウトとし、ブラウザーで利用者の認証操作を待つ時間には適用しない。再試行時には設定と保存情報を再読込する。破損・復号不能・接続先不一致・別プロセスの変更の扱いは既存の[認証情報保存契約](auth-windows-oauth.md#windows版の認証情報保存)を維持する。

起動時に必要なトークン更新を行ってもログイン状態を継続できない場合、またはDPAPIで復号できない場合は、接続先設定を残してログイン画面へ進む。認証をキャンセルした場合もログイン画面に留まり、再試行できるようにする。通信障害を理由に再ログインへ切り替えたり、接続先設定を消したりしない。

### Windows版のログイン・認証待ち・ブラウザー完了表示

Windows側のログイン画面は、接続先設定・起動表示と共通Frameに必要時だけ配置する独立したLoginPageとする。アプリ名と「ログイン」「接続先の変更」を表示し、操作をWindowへ通知する。通常離脱でPageとイベント購読を解放し、再訪は新規生成する。認証情報なしではWindow.Activate前に直接配置し、通信も起動Page生成もしない。PageはOAuth・通信・認証状態を管理せず、Windowと既存Clientの責務を維持する。共有InfoBarによるエラー表示、処理中の二重操作防止、キャンセル後の再試行、401退避中の編集/実コントロール保持は変更しない。「ログイン」を押すと外部ブラウザーで認証を開始する。ブラウザー側が未ログインならログイン画面からパスキー認証し、既に有効なログイン状態なら再認証を省略する。Windows側で認証成功を確認してトークンを取得したら、認証待ちを終了して通常の家計簿側の行き先へ自動で進み、Windows側に認証成功専用の画面は挟まない。

認証待ちも同じLoginPage内の表示とし、標準Visibilityで認証前領域を隠し、「Monetail」「ブラウザーでログインしてください。」と「ブラウザーを開く」「キャンセル」を表示する。認証開始・取消・OAuth拒否ではPageの遷移/再生成を行わず、取消後は同じPageの認証前表示へ戻って再試行できる。通常の画面離脱後に戻る場合は新しいPageを生成する。

認証待ち中はWindowのbusyにかかわらず、再オープンとキャンセルを操作可能にする。再オープンは同じ認証要求URLを使い、ログインを二重開始しない。コード交換後の認証結果確定中は待機操作を無効にする。OAuth・取消・保存と操作可否の判断はWindow/既存Clientが所有し、Pageは表示切替と4操作の通知だけを担当する。ブラウザー起動失敗等は既存の共有InfoBarに表示する。家計簿/接続先設定への通常離脱とWindow終了ではPage参照・購読を解放し、終了時には既存のWindow寿命に従って認証処理を中断する。

認証完了後は、認証に使ったブラウザーのタブを自動で閉じることを試みる。閉じられない場合は「認証が完了しました。このタブを閉じて、Monetailに戻ってください。」を表示する。[ブラウザーの自動終了制約](https://developer.mozilla.org/en-US/docs/Web/API/Window/close)により、常に閉じられることは前提にしない。

Windows版を前面へ戻すことも試み、OSによって制限された場合はタスクバーの点滅で知らせる。[Windowsの前面表示制約](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)に従い、自動復帰ができない場合でも認証の完了と家計簿側への遷移を妨げない。
