## 人物の管理（DEC-055・APIとWindows画面実装）

人物・参加者・招待のAPIと初回DB定義、Windowsの人物一覧を実装済み。人物の追加・編集・日付/Enter入力・保存失敗と更新版競合の画面、同一アカウントでの再ログイン後の編集復帰を実装した。参加者・招待の管理画面は未実装で、そちらの画面動作は設計として保持する。レシートの取引日に基づく有効期間検証は、明細対象人物と支払方法所有者の双方へ接続済み。参照する既存レシートが期間外となる人物の期間変更は拒否する。振替・残高等の検証は各業務モデルの追加時に接続する。今回の参照削除制限は、参加者との対応とDBのRESTRICT制約で検証した。

利用者確認済みの方針は次のとおり。

- 人物IDはAPI側で生成するUUIDとし、名前・表示順から独立した識別子にする。通常の人物管理画面には表示しない（DEC-062）。
- 人物名は前後の空白を除いて1〜100文字。同じ家計簿で同名の人物は認めない。前後空白除去後の完全一致で比較し、大文字小文字・全角半角・Unicodeの正規化を同一視しない。文字数は家計簿名と同じ`.NET string.Length`（UTF-16コード単位数）で数える。通常の日本語は1、一部の絵文字等は複数として数える。上限超過を自動で切り詰めず、API側でも検証して入力エラーにする。名前が変わっても人物の識別は維持する（DEC-063）。
- 人物一覧は当該家計簿の全参加者が閲覧可能。未参加者や未ログインの利用者への公開を意味しない。
- 人物一覧の初期表示はWindowsの本日日付で有効な人物のみとし、開始日・終了日は両端を含む。［有効期間外も表示］で取得済みの全人物へ切り替える。絞り込みは表示だけに適用し、追加GET・人物の削除/更新は行わない。人物の並び順は任意に設定できるようにし、通常の人物一覧・選択欄では、表示対象のうち設定順にかかわらずログイン中の本人を先頭とする。それ以外の人物は設定順に従う。本人に対応する人物がなければ先頭への移動は行わない。下記の並び順設定画面のみ例外とする。
- 設定する並び順は家計簿内で共通とし、変更できるのは家計簿管理者のみ。本人を先頭に移すのは各利用者への表示時に行い、保存している共通順そのものは変えない。
- 人物一覧に管理者用の［並び順を変更］を置き、専用の並び順設定画面を開く。この画面だけは本人を先頭へ移さず、保存する共通順をそのまま表示する。人物を選択して［上へ］［下へ］で移動し、［保存］で確定する。［キャンセル］は変更を保存せず一覧へ戻る。
- 人物を追加できるのは家計簿管理者のみ。
- 人物名を変更できるのは本人と家計簿管理者。本人とは、当該家計簿でその人物に対応付けられたアカウントでログインしている利用者。人物名の一致で本人と判定しない。
- 人物との対応は家計簿内の参加者編集画面で設定する。家計簿管理者が、その参加者に対応する人物を同じ家計簿から選び、「未設定」も認める。人物編集にはアカウント選択を置かない。全体のアカウント設定と家計簿内の参加者編集を区別する。人物登録や家計簿への参加と対応付けは独立した操作とする（DEC-061）。
- 対応は参加者テーブルにNULL許容の人物IDを持たせて保存する。未設定はNULLとし、同一家計簿内で同じ人物への対応の重複を禁止する。同じ家計簿の人物への複合FKを設け、対応専用テーブルは作らない（DEC-059。人物側にアカウントIDを持つDEC-058から変更）。
- 人物編集の保存は、名前・有効期間を1要求・1トランザクションでまとめる。どこかが失敗したら全体を戻し、成功時は更新後の人物一覧も同じ応答で返す。人物との対応は参加者編集で別の操作として保存する（DEC-061。DEC-056から対応の操作場所を移すが、人物情報の一括保存・一覧返却は維持する）。
- 人物の削除・有効期間の変更は家計簿管理者のみ。
- 名前変更後は過去の記録も現在の人物名で表示する。各取引に変更前の人物名を複製しない。
- 使用済みの人物は残し、過去の表示・集計を維持したまま、今後の選択候補から外せるようにする。本当に未使用の人物は削除可能にする。
- 人物に有効期間を設定できるようにする。適用対象は明細対象者に限定せず、支払方法の所有者を通じたレシート・振替・残高等、人物を使用する業務全体。人物の期間は認証アカウントの利用期限とは別で、登録・ログインは引き続き人物対応に依存しない。
- 有効期間は操作日ではなく記録対象の日付で判定する。レシートではレシートの日付を使い、現在は期間終了後でも期間内の日付のレシートを入力するときは選択できる。
- 有効開始日・終了日はそれぞれ空欄なら、その側の制限なし。両方空欄なら全期間で有効。指定した開始日・終了日はともに有効期間に含む。開始日が4/1なら4/1は入力可能、3/31は不可。終了日が9/30なら9/30は入力可能、10/1は不可。判定はレシートの日付に対して行う。
- 人物を使用している既存の記録を範囲外にする有効期間の設定・変更は認めない。レシート・振替・残高等を対象とする。例えば4/1の既存レシートで使われていれば、開始日を4/2に変更できない。
- 未使用の判定では、レシートに加えて振替・残高も対象にする。
- 人物への参照が1件でも残っている間は削除不可。取引がなくても、所有者として登録された支払方法や参加者との対応が残っていれば削除しない。削除処理では参照や対応を自動解除せず、先に管理者が参加者編集で人物を「未設定」にして保存し、その後で人物を削除する。対応解除後も他の参照があれば削除不可。アカウント本体・家計簿への参加・役割は維持する（DEC-060・061）。

人物管理画面は家計簿ホームの「管理・設定」から開く。管理・設定の左側にメニューを残し、右側に人物一覧を表示する。人物一覧には上記の期間表示チェックのみを置き、検索や追加の絞り込みは設けない。

一覧は1人を選択する方式とし、未選択時や権限がない操作のボタンは無効にする。削除時は人物名を含む確認を表示し、参照があれば削除せず理由を表示する。このボタン制御・削除操作は利用者確認済み。

人物名の文字数の数え方・同名判定は上記の方針で確定済み。画面の具体案は下記に分ける。各業務機能で有効期間の判定に使う日付や、支払方法自体の有効期間との関係は、その機能の設計時に具体化する。参加者編集での人物の選択・解除・付け替えと参加者表への人物IDの保存は確定済みだが、APIのパスと要求・応答項目は下記に実装済み。管理画面の配置等の未決定事項とは区別する。

削除制限の技術方針は利用者確認済み。人物を参照する支払方法・明細対象者等に家計簿ID＋人物IDの索引を設け、DBの外部キー制約（RESTRICT）で参照のある人物の削除を拒否する。APIは参照による削除拒否を画面へ伝える。一覧表示時に全履歴を走査せず、削除時の現在の参照をDB側で検証する。書込トランザクションと外部キー制約で、他の端末との同時操作でも参照切れを防ぐ。具体的な参照先は業務モデル設計時に網羅する。一覧で削除可否を事前表示するかは未確定。

旧版で人物を直接参照する箇所は、購入明細の対象者、支払方法の所有者、店舗マスタの人物別設定。レシートの支払者・振替の移動元と先・残高・支払メモは支払方法を通じて人物を参照する。集計はこれらから算出し、集計専用の人物参照を保存しない。新版の参加者から人物への任意の対応も参照元に含め、残っている間は人物を削除できない。旧店舗の人物別設定等を新版へ採用するかは、旧列の存在を根拠に決定せず後続設計で確認する。

### 人物管理画面（同じウィンドウ内で切替）

本日有効/全期間の表示切替・任意の設定順と通常表示での本人先頭・専用画面での並べ替え・ボタン制御・削除確認は上記の確定事項に従う。子ウィンドウを開かず、同じメインウィンドウ内で扱う（DEC-100）。人物の追加・編集は一覧を背後に残す標準のContentDialogとする（DEC-108）。並び順設定は同じWindow内で切り替える。最新の利用者確認では、管理・設定の左側メニューと右側の人物一覧を同時に表示する。画面の技術構成は[04](architecture-winui.md#新版windows版の構成)のWinUI 3に従い、未保存の入力保持と保存・取消の契約は維持する。

| 画面 | 表示・操作 |
| --- | --- |
| ホーム | 上部の「管理・設定」から管理画面を開き、左側の「人物管理」で右側に開いている家計簿の人物一覧を表示する |
| 人物一覧 | 家計簿名・人物名・有効開始日・有効終了日を表示。本人の人物名に「本人」を添える。初期は本日有効な人物のみ。［有効期間外も表示］で全員へ切替。本人先頭は表示対象にのみ適用し、期間外の本人を特例表示しない |
| 人物の追加 | ContentDialogで人物名・有効開始日・有効終了日を入力。初期値はすべて空欄。［登録］と［キャンセル］を置く |
| 人物の編集 | ContentDialogで選択した人物の現在の名前・有効開始日・有効終了日を表示。アカウントの選択は置かない。［保存］と［キャンセル］を置く |
| 並び順設定 | 管理者のみ操作可能。共通順で全員を表示し、［上へ］［下へ］で並べ替える。［保存］で確定、［キャンセル］で破棄して一覧へ戻る。本人先頭の表示処理は適用しない |

人物一覧には、期間の空欄が制限なしである説明を添える。一覧・追加と編集・並び順設定の共通レイアウトは[UI_DESIGN.md](../UI_DESIGN.md)を参照する。共通UI基準への見た目の適用は後続の画面改修で行い、本書では表示項目・操作条件・保存と遷移の契約を保持する。

操作権限は上記の確定事項に従い、画面では次の形にする。

| 操作 | 家計簿管理者 | 管理者以外の本人（閲覧者を含む） | それ以外の参加者 |
| --- | --- | --- | --- |
| 一覧を見る | 可 | 可 | 可 |
| 追加 | 可 | 不可 | 不可 |
| 選択した人物を編集 | 名前・有効期間 | 自分の名前のみ。有効期間は表示するが変更不可 | 不可 |
| 削除 | 確認後に実行。参照があれば拒否 | 不可 | 不可 |
| 並び順を変更 | 可 | 不可 | 不可 |

- 一覧は1人を選択する方式とし、未選択時や権限がない操作のボタンは無効にする。表示対象0件なら「表示対象の人物はありません。」を表示し、管理者は［追加］から登録する。
- 追加・編集は保存成功時にダイアログを閉じ、応答の一覧を表示する。［キャンセル］または標準のEsc操作は入力を保存せず閉じる。保存中は重複操作・取消を受け付けない。［ホームへ戻る］は開いていた家計簿のホームへ戻る。
- 人物の追加・編集ダイアログが開いている間は、背後の左メニューやホームへの移動を操作できない（DEC-108。画面切替時の破棄を定めたDEC-105から変更）。キャンセル後の人物管理は一覧から始め、編集を自動再開しない。保存の確認や自動保存は追加しない。
- 保存中のログイン失効によるログイン画面への遷移は例外とし、ダイアログを閉じて入力・元の更新版・作成要求IDをメモリー内に一時保持する（DEC-107）。同じAPI接続先の同じアカウントでログインし直した場合だけ、元の家計簿を直接開き、人物一覧から現在の参加・役割・本人対応を確認してダイアログで編集を再開する。復元した旨を画面内に示し、自動保存せず本人が確認して保存する。別アカウント・接続先変更へは引き継がず、通常の行き先へ進む。
- 共通順の保存中に認証が失効した場合も、同じアカウント・接続先で再ログイン後、未保存の人物ID順と元の全体更新版を復元する（DEC-109）。既存の元家計簿・権限確認を共用し、自動保存しない。表示名には取得済みの最新情報を使うが、人物の増減を理由に未保存のID順を黙って補正せず、保存時の競合処理で最新一覧へ置き換える。権限を失っていれば順序を残して保存不可とし、別の本人・接続先には渡さない。
- 再ログイン後に参加・編集権限を失っている、または人物が削除されている場合も、本人へ既に返した入力を残したまま保存不可と説明する。未参加なら人物一覧の追加取得を行わない。権限不足で名前だけ等を黙って部分保存しない。閉じた後の操作可否は現在の権限に従う。
- 人物の追加・編集は名前と有効期間をまとめて保存する。人物名の空欄・文字数超過・同名・開始日が終了日より後の入力や、既存の記録を期間外にする変更は理由を画面内へ表示し、入力を残して修正できるようにする。
- 削除時は人物名を含む確認を表示する。削除成功後は一覧から取り除き、参照があれば削除せず理由を表示する。削除可否を調べるために一覧表示時の全履歴走査は行わない。 確認は同じWindow内のContentDialogを使い、既定ボタンはキャンセルとする。削除中は操作を無効にし、成功応答の一覧を反映して閉じる。参照・通信・権限エラーは確認内で説明し、追加GETや勝手な対象削除をしない。競合では全最新項目を表示し、明示的な切り替えで確認対象と版を更新した後、改めて削除する。Ctrl+Enterの登録・保存操作では削除を実行しない。認証失効は共通のログイン画面へ戻り、自動で削除を再送しない。追加・編集の入力復元とは区別する。
- 通信失敗では入力を保持して再試行可能にする。更新版の不一致による競合では、下記の確認済みの画面内表示で最新情報を確認し、明示的に切り替えてから保存する。権限喪失時は下記の確認済みの画面内エラー方針に従う。通信障害時の再送の具体的な応答項目はAPI設計で具体化する。

**競合時の最新情報表示（Windows人物編集に実装）**

競合時だけ編集画面内に最新の保存内容を表示する方式へ変更した（DEC-065。DEC-064の読み直しダイアログを置き換える）。最新内容を表示するTextBlock群をXAMLのコンテナーにまとめ、通常はCollapsedにする。表示領域をあらかじめ予約せず、競合時にその内容分だけ広げ、必要ならスクロールできるようにする。

- 更新版の競合応答に、現在の権限で返せる最新の情報と更新版を含める。人物編集では名前・有効開始日・有効終了日の3項目すべてを読み取り専用で表示する。相違のある項目だけに絞る表示や差分の強調は行わない。確認のためだけの追加取得通信を行わない。同名等の入力・制約エラーと更新版の競合を区別する。
- 編集中の入力はそのまま残し、最新情報とは別に保持する。最新情報を受け取っただけで入力や保存用の更新版を切り替えない。
- ［最新内容に切り替える］を押したときだけ、入力欄と保存用の更新版を表示中の最新情報へ置き換え、通常の編集へ戻る。今回の未保存入力が置き換わることを表示する。切り替えるまでは古い版による保存を通さない。
- 切り替えた後の保存でも更新版を照合する。さらに変更されていれば再び最新情報を表示し、競合を理由に自動で上書きしたり、入力を黙って破棄したりしない。

**参加者編集・並べ替えの競合（並べ替えはWindows接続済み／参加者画面は未実装）**

- 参加者編集は人物編集と同じ仕組みを使う（DEC-090）。同じ参加者行の役割・人物対応の先行変更を検出したら、最新の役割と対応する人物を読み取り専用で表示する。編集内容は残し、［最新内容に切り替える］で入力と参加者の更新版を置き換える。役割と対応の別項目を編集していても同じ参加者行の古い版は保存しない。
- 人物の並べ替えの競合では、「ほかの操作で変更されています。最新の並び順を読み込みます。」と知らせ、そのまま未保存の並べ替えを破棄して最新の並び順へ置き換える（DEC-092）。最新一覧を参考欄に並べる表示や、切り替えるかを選ぶ確認は設けない。
- 最新の人物一覧と並び順全体の更新版を競合応答に含め、追加GETなしで編集側の全一覧と保存用の更新版を置き換える（DEC-092）。人物の追加・削除も反映し、並べ替え画面では共通順をそのまま表示する既定方針を維持する。
- 権限喪失はDEC-081のエラー表示を優先し、閲覧権限のない最新情報を返さず、再取得や自動遷移をしない。
- 別々の参加者に同じ人物を同時設定した場合は、先に確定した対応だけを成立させ、後の保存は制約エラーとして拒否する（DEC-091）。更新版の競合用の切り替え表示ではなく、画面内に別の参加者へ設定済みと表示して入力を残す。失敗した保存では役割・人物対応の両方を変更せず、他の参加者の対応を奪わない。

**入力エラーの表示（Windows人物編集に実装）**

人物名の文字数超過等の入力不備は、［登録］または［保存］を押したときに画面内の該当欄付近へ短いエラー文を表示する（DEC-081）。普段は表示領域を予約せず、エラー時だけ説明を追加する。入力は保持し、保存せずに該当欄へフォーカスを戻して修正できるようにする。クライアントで確認できる入力不備は送信前に止め、API側でも同じ条件を検証する。

| 条件 | 表示する説明の案 |
| --- | --- |
| 人物名が100文字超 | 人物名は100文字以内で入力してください。 |
| 人物名が空欄・空白のみ | 人物名を入力してください。 |
| 同じ家計簿に完全一致の同名がある | 同じ名前の人物が登録されています。 |
| 開始日が終了日より後 | 有効開始日は有効終了日以前の日付にしてください。 |
| 既存の記録が新しい有効期間から外れる | 既存の記録が期間外になるため、この有効期間には変更できません。 |
