# 07 開発ロードマップ（レガシー完成 → 将来の再実装）

更新日: 2026-10-19。完了項目は現行コードとCI結果に基づく。残るマイルストーンは**提案**で、機能追加範囲や技術スタックの最終決定ではない。

## 方針

レガシー版の日常利用に必要な機能と計算の互換性を先に確定し、次世代版の設計・テストへ引き継ぐ。現段階ではSQLiteをD1へ変更しない。マスタメンテナンス画面はユーザー方針で作成を見送り、店舗登録なしでもレシートを入力できる構成を維持する。

## 仕様の判断と次の候補

[13 用語・意思決定](13-glossary-decisions.md)の各項目について、確定・実装済み・未決定を区別する。DDL受領、税端数、テスト／CI整備、レシート更新・削除と残高削除の外部キー対応、レシート・残高・振替のNULL読込、小数割引率の読込修正、支払メモ一括保存のトランザクション化は完了しており、再び未実装の前提で計画しない。

古い編集の上書き防止（LEG-016）と接続先の既定値統一・起動時検証（LEG-007）を実装した。利用者は実行用XMLで自身のDBを指定する。残高推算の日付境界の現行挙動は実SQLite回帰へ追加した。次の候補は境界仕様の確定・修正（LEG-029）と、その後の重複ロジック整理（LEG-025）。ローカル2接続の採番は直列化を確認したため、採番方式の変更は保留する。マスタ画面は引き続き作成を見送り、ポイントは採否の判断を先に行う。

D1への変更、未決定の認証・権限の先行実装、実DBへの未検証SQL適用、ソースの全面書換えは行わない。
