# 07 開発ロードマップ（Windows版の継続開発 → Web化）

更新日: 2026-10-21。完了項目は現行コードとCI結果に基づく。Windows版先行・Web化必須・Web入力の優先順位は利用者決定。残るマイルストーンは**提案**で、機能追加範囲や技術スタックの最終決定ではない。

## 方針

まずWindows版を進め、日常の入力・保存・表示と計算の互換性を整える。後続のWeb化は必須とし、Web版ではレシート入力、次に振替入力を優先する。現段階ではSQLiteをD1へ変更しない。マスタメンテナンス画面はユーザー方針で作成を見送り、店舗登録なしでもレシートを入力できる構成を維持する。[33 方針と未決定事項](33-windows-first-web-input-priorities.md)。

## 仕様の判断と次の候補

[13 用語・意思決定](13-glossary-decisions.md)の各項目について、確定・実装済み・未決定を区別する。DDL受領、税端数、テスト／CI整備、レシート更新・削除と残高削除の外部キー対応、レシート・残高・振替のNULL読込、小数割引率の読込修正、支払メモ一括保存のトランザクション化は完了しており、再び未実装の前提で計画しない。

古い編集の上書き防止（LEG-016）と接続先の既定値統一・起動時検証（LEG-007）を実装した。利用者は実行用XMLで自身のDBを指定する。残高推算の日付境界の現行挙動は実SQLite回帰へ追加した。日末残高の仕様を確定し、境界を修正した（LEG-029）。重複ロジックも共通化した（LEG-025）。分類・人別集計の未網羅だった主要条件も回帰化した（CAL-004）。対象者なし・複数選択時の運用判断はLEG-011に残る。利用者承認に基づき、数量・率の欄を離れたときと明細追加／更新時に、不正な数量を1・率を0（100%超は100）へダイアログなしで補正する処理を追加した。既存の範囲外値は読込・計算を維持する（[23 仕様](23-detail-input-validation.md)、LEG-030）。単価・値引額の整数式入力も共用化し、乗算優先と不正式・途中の桁あふれの0補正を実装した（[24 仕様](24-integer-money-expressions.md)、LEG-031）。金額の範囲超過も明細反映・登録・流用前に確認し、警告と入力保持、プレビュー表示を実装した（[25 仕様](25-receipt-amount-overflow.md)、LEG-032）。分類・収支の月年集計も範囲超過表示と条件変更後の復帰を追加した（[26 仕様](26-statistics-amount-overflow.md)、LEG-033）。残高推算・集計にも範囲超過表示、転記抑止、表・グラフの復帰を追加した（[27 仕様](27-balance-amount-overflow.md)、LEG-034）。振替の登録・流用も入力条件を共用し、確認・モデル変更前の中止と修正後の再保存を追加した（[28 仕様](28-transfer-input-validation.md)、LEG-035）。残高登録も一時明細で検証してからモデルへ反映する順序にし、エラー後の同一オブジェクト再表示と再保存を追加した（[29 仕様](29-balance-input-state.md)、LEG-036）。レシートの登録・流用も必須入力の検証を共用し、不備があれば確認・モデル変更前に中止する（[30 仕様](30-receipt-input-validation.md)、LEG-037）。集計詳細画面も金額範囲超過の表内表示、途中行の消去と明細切替後の復帰を追加した（[31 仕様](31-detail-view-amount-overflow.md)、LEG-038）。レシート一覧も参照を維持する表示用Totalで範囲外セルを表示し、絞り込みと既存の編集経路を継続する（[32 仕様](32-receipt-list-amount-overflow.md)、LEG-039）。レシート読込のSQL回数・時間を比較するWindows計測を追加した（[34 方法と結果](34-receipt-read-performance.md)、LEG-026）。GetReceiptsを1 SELECTへ一括化し、取得内容の互換性と性能を比較する（[35](35-batch-receipt-reads.md)）。残高推算のGetPaymentReceiptsも一括化し、期間条件・Seq順・推算途中の超過を維持して同一CI内で改修前と比較する（[36](36-batch-payment-receipt-reads.md)）。子再読込の途中失敗でも元レシートが部分状態にならないよう、成功後だけ子を反映する（[37](37-receipt-child-reload-state.md)、LEG-040）。後続のWeb化を必須として仕様とテストを引き継ぎ、Web版の入力はレシート→振替の順とする（[33 方針](33-windows-first-web-input-priorities.md)、DEC-024）。ローカル2接続の採番は直列化を確認したため、採番方式の変更は保留する。マスタ画面は引き続き作成を見送り、ポイントは採否の判断を先に行う。

D1への変更、未決定の認証・権限の先行実装、実DBへの未検証SQL適用、ソースの全面書換えは行わない。
