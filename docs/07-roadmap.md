# 07 次に進めること

進め方・優先順位の正本。各機能の仕様・実装状況は[文書案内](INDEX.md)の正本を参照し、この文書に複製しない。

## 進め方

Windows版の操作とデータ保全を尊重し、Webでの業務入力より先にWindows版をAPIへ接続する。Web化は必須とし、Web入力はレシート、次に振替を優先する。未確定の仕様は確認してから実装する。

## 次の順序

1. 招待制を当面維持しつつ一般公開の自己登録へ設定で移行できる設計を先に整理し、認証API・登録画面・濫用対策・復旧の未決定条件を確認後に段階的に実装する（[DEC-110](auth-passkeys.md#登録方式の段階的拡張dec-110方針確認済み未実装)）。
2. Windows版の接続・認証・家計簿選択・作成・切替の画面を実機で確認し、必要な調整を行う。
3. 家計簿内の人物・任意対応・マスタと業務データのAPIを実装し、Windows版の参照・レシート入力から順に接続する。振替・残高・集計等も段階的に移す。
4. 同じAPIへWebの業務画面を接続する。登録・ログイン・招待・家計簿切替の実装済み範囲と未実装範囲を区別する。

設計と未決定事項の正本は[58](58-ledger-foundation-design.md)。通常の起動・運用は[42](42-api-foundation.md)、認証は[43](43-passkey-authentication-design.md)。

## 残る確認・保留

- Windowsの手動操作、実レシートとの照合、実DBの型・FK・索引・日付境界・参考配分とバックアップ復旧の確認。自動テスト成功と区別する。
- 共有フォルダー・複数プロセス・WAL等の残る競合条件、未網羅の入力・表示・移行の例外、切替・ロールバックとバージョンタグの整備。
- 支払方法の有効期限、ポイントの採用範囲、PC／スマートフォンでの業務画面。Windows追加要望は[08](08-requested-enhancements.md)。
- 新構成確定後の一度きりの既存DB引継ぎと、必要最小限のスクリプト・合成データでのリハーサル。常設の移行画面・APIは作らない。

完了済みの作業や過去の候補は[履歴](history.md#note-07)へ保存した。履歴に残る未実施確認を完了済みとみなさない。検証結果は[tests/README.md](../tests/README.md)だけを更新する。
