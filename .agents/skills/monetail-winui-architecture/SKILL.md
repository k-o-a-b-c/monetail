# monetail WinUI 3：小さな責務と依存関係

## 位置づけ

- 本Skillは**monetail固有の構造判断**を担当する。`AGENTS.md`の仕様承認ルール、`UI_DESIGN.md`のUI基準、`docs/architecture-winui.md`の構成、および対象機能の正本を優先する。
- WinUI 3の実装方法・API可否は同梱の`winui-design`で確認し、一覧・入力・検証は`windows-lob-xaml`、変更後は`winui-code-review`を使う。実装時は`winui-dev-workflow`、UI検証時は`winui-ui-testing`も参照する。
- リポジトリの現在の開発・CIは`WindowsPackageType=None`の非パッケージ構成。構造整理に便乗してパッケージ方式、外部依存、ターゲットを変更しない。将来の配布方式は別途判断する。

## 実装前に最小限の責務表を作る

対象画面のXAML領域、対応する`MainWindow*.cs`、`Monetail.Windows.Client`内の既存モデル/Workspace、該当スモークテストを必要箇所だけ確認する。

| 責務 | 原則的な所有者 |
| --- | --- |
| Window全体の画面遷移、家計簿とアカウントの切替、未保存離脱ガード、アプリ終了 | `MainWindow` |
| 一画面内のコントロール、表示、選択、入力イベント、フォーカス、キーボード/IME | 画面の`Page`/`UserControl`とそのcode-behind |
| API呼出、認証・権限契約、保存/競合、業務検証、業務状態モデル | 既存`Monetail.Windows.Client`の適切なクラス |
| 表示にだけ必要な変換・行モデル | そのViewに近い小さなクラス。業務状態を二重管理しない |

これらは目標の境界であり、既存`MainWindow`の実装がすでに満たすという意味ではない。分離時も既存の再認証/退避などの振る舞いを変更しない。

## 判断規則

1. **まず削減する結合を特定**する。`partial class MainWindow`のファイル移動だけでは所有者も依存関係も変わらない。分離後にMainWindowがViewの内部`x:Name`を直接触らない状態を目指す。
2. **Viewの公開面は最小限**にする。必要な表示データをプロパティ/メソッドで渡し、操作意図や選択IDをイベント等で通知する。Viewへ`MainWindow`・`Window`・APIクライアントを丸ごと渡さない。既存`Views/LedgerChoiceView`は参考例であり、全画面を同じ型に強制しない。
3. **既存Clientを先に探す**。フォーム内の生文字列やフォーカス状態はUIに必要だが、保存下書き・更新版・結果不明・401復帰などの業務状態をUI用モデルへ丸ごとコピーしない。UI固有の状態が必要な場合だけ小さなViewModelを検討し、導入理由を明示する。MVVMやDIを一律強制しない。
4. **WinUI標準を先に選ぶ**。`ListView`、`Grid`、`ContentDialog`、`AutoSuggestBox`等で足りるなら独自コントロール・レイアウトエンジン・スクロール/フォーカス処理を追加しない。APIはプロジェクトの実参照で検証し、WPF/UWPの機能を前提にしない。
5. **変更を狭く保つ**。1 PRは1つの画面境界または1つの責務の抽出を基本とする。全画面への一括MVVM化、共通基盤の先行追加、画面分離とUI仕様変更の同時実施をしない。
6. **実装後は複雑さを比較**する。新規フィールド/フラグ/ハンドラー/抽象化、画面間・`MainWindow`への直接参照、重複バインディング/状態、コード総量の増減と理由を確認する。行数減少だけで成功としない。

## 変更ごとの成果物

- **着手前（簡潔に）**：現在の責務→分離先、残す責務、Viewの公開面、Clientの再利用箇所、関連XAML/イベント/テスト、振る舞い変更の有無。未決定の利用者向け仕様は`AGENTS.md`に従い確認する。
- **実装中**：単独で成立する最小境界から移し、不要になったフィールド・イベント・内部`x:Name`参照を除去する。ソース上の参照移動だけで分離済みと報告しない。
- **検証・レビュー**：対象のWindowsスモークと必要なClientテストを選択する。選択/未選択、Tab・矢印・Enter・IME、表示/再表示、フォーカス、狭幅/高DPI、認証/未保存/競合など該当経路を確認し、未実施を明記する。実行方法・成功記録は`tests/README.md`を正本とする。
- **PR報告**：削減した依存と増えた要素、保護した既存動作、テスト結果、未確認事項だけを短く書く。
